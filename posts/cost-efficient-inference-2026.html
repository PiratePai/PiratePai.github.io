0导读与大事记：高性价比是什么、和低时延高吞吐有何不同

这份报告回答四个问题：高性价比推理与低时延、高吞吐到底是不是一回事、什么时候冲突；一百万 tokens 的价格由哪些项构成、自己怎么算；四年降了三个数量级的功劳簿怎么分；推理引擎与服务化团队该盯哪些指标、按什么顺序动手。全文沿一条主线展开——高性价比 = 单位成本产出最大化：把 $/M tokens 拆成"GPU 时租 × 卡数 × 时间 ÷ 实际产出"，再乘一个质量折扣项，然后对每一项分别做小。低时延优化的是"时间"里的等待部分，高吞吐优化的是"产出"里的批量部分；高性价比是它们的上层目标函数，还要多管两项它们不管的事：买什么硬件（时租）与质量是否守得住（折扣项）。

1预备知识：一个 token 的成本账本

写给第一次接触推理经济学的读者：本节只需要"除法"和"租东西按时计费"两个常识。先建立四个概念：成本公式、三个目标的三角形、质量调整成本、账本的隐藏项。

1.1 从 GPU 时租到 $/M tokens：一条除法公式

自部署推理的成本起点不是"模型多大"，而是你租（或买）的算力每小时多少钱。云上 H100 的市场合约价 2025-10 约为 $1.70/小时，2026-03 回升到 $2.35；B200 在 2026-09 达 $8.01（三个月 +79%，HBM 短缺驱动）[GPUIDX]。假设租了 N 张卡、系统总输出吞吐为 T（tok/s），那么：

$/百万输出 tokens = (时租 R × 卡数 N × 10⁶) ÷ (T × 3600)

代两个数：单卡 H100（$2.35/h）跑出 2,000 tok/s，则每百万 tokens ≈ $0.33；同样吞吐用 $8 的 B200 反而要 $1.11——贵卡必须跑出与价差相称的吞吐才划算。MLPerf Inference v6.1 里 CoreWeave 的 GB300 NVL72 在 gpt-oss-120b 离线场景做到 16,635 tok/s/卡[MLPERF61]：按 $8/小时算，每百万 tokens 仅 $0.13——吞吐摊薄了时租，这就是"高性能硬件反而更便宜"的全部秘密。反过来，若利用率只有 10%，分母缩小 10 倍，什么卡都贵。

把 GPU 集群想成一支按小时计费的专业施工队：低时延是"一个电话就到"（养着随时待命），高吞吐是"一车尽量装满"（拼车摊薄成本），高性价比是"每运一吨货花的总钱最少"——既要车装满（吞吐），又要少养闲车（利用率），还要货不返工（质量）。施工队的时薪（GPU 时租）你谈不下来多少，能做的是让每一分钟都有货可运、运的每趟货都算数。

1.2 三个目标的三角形：一致与冲突

低时延（TTFT/TPOT）、高吞吐（tok/s）、高性价比（tokens/$ 或 $/M tokens）经常被混为一谈，但它们只在特定区间一致：

手段低时延高吞吐高性价比说明
加大 batch✗ 变差✓ 显著提升✓ 提升（质量不损）decode 是访存受限的，更多人摊薄权重搬运；但 TPOT 随 batch 增大而升高，超过 SLO 的 batch 是"白赚的吞吐、丢掉的承诺"
更小/量化模型✓ 改善✓ 提升✓ 提升，但引入质量折扣FP8/NVFP4 在现代硬件上几乎免费提速；质量损失要过回归（R1-0528 从 FP8 到 NVFP4 主流基准损失 ≤1%[NVFP4]）
P/D 分离✓ TTFT 改善✓ goodput 提升✓ 但有额外成本消干涉收益常大于 KV 传输与双池固定成本，但池配比错了反而更贵（详见 6.2）
投机解码✓ 改善△ batch 大时可能持平或略降△ 视能耗与接受率接受长度高时每成功 token 便宜；batch 大时验证算力挤占主算力，能耗口径可能变差（2.33 vs 2 J/token 的教学账本[SPECENERGY]）
独占低负载机器✓ 最优✗ 空转✗ 最差"为 10 个用户保 p99"是合法业务选择，但要清楚它对单位成本意味着什么

判断标准一句话：低时延与高吞吐是"承诺"，高性价比是"账本"；前两者定义了 goodput 的边界，后者要求在边界内最大化产出÷投入。这也是 DistServe 提出 goodput（SLO 达标吞吐）的初衷——把承诺与吞吐绑成一个可优化的单一指标[DISTSERVE24]（站内推理服务篇 1.4 与评测篇 2.1 给了定义与手算例子，本文不重复）。

1.3 质量调整成本：便宜但答错要重来

$/M tokens 的分子是钱，分母是 token 数；但用户买的从来不是 token，是答对的任务。一次答错触发重试，实际成本翻倍还搭上时延。于是有了质量调整口径：

每成功任务成本 = 每次调用成本 × 平均调用次数 ÷ 任务成功率

三种策略的账可能反转：直接回答 2 积分/次、best-of-4 花 6 积分未必更贵——如果它把成功率从 30% 抬到 80%，每成功成本反而从 6.67 降到 7.5 之外更低的档位（该教学账本在评测篇 4.2 有完整表格）。同理，混合价（如 Artificial Analysis 的 7:2:1 缓存:输入:输出加权）对 reasoning 类 1:5 负载会失真最多 5 倍[TOKENARENA26]——先想清楚自己的负载长什么样，再选口径。

1.4 账本的隐藏项：TCO 不止租金

Epoch AI 的测算：电费只占 GPU TCO 的 10–15%，资本开支（购置/折旧/资金成本）主导长期成本下限[EPOCHTCO]。完整的账本还包括：网络（400G RoCE 集群非小事）、存储（KV 池的 SSD）、机房 PUE、运维人力、以及碎片化时间的浪费——白天为峰值预留的容量在凌晨就是纯折旧。很多"降价 90%"的新闻只算了 GPU 时间，没算这些；自己建集群算账时一项都不能少（第 7 章展开）。

本章小结
  1. 成本公式只有一条除法：$/M tokens = 时租×卡数÷吞吐；GB300 贵 4 倍却更便宜，因为吞吐摊薄了一切。
  2. 低时延/高吞吐是承诺，高性价比是账本；goodput 是它们的交汇点——承诺之内最大化产出÷投入。
  3. 质量是分母上的折扣项：每成功任务成本才对齐用户的真实开销；TCO 里电费只占一两成，资本与碎片时间才是大头。

2指标体系：性价比到底怎么度量

"性价比"不是玄学词，它有一套可计算的指标族。按"钱从哪出、货从哪进"分五类：价格类、产出类、能耗类、资产类、质量调整类。本节逐个给出定义、口径与陷阱——指标选错，优化方向就会错。

2.2 产出类：tokens/s/$ 与 goodput

自部署侧的对称指标是每美元产出多少 token（tokens/s/$），它把 1.1 的公式倒过来。三个常见变体：

  • 聚合吞吐（tok/s/卡 或 tok/s/集群）：MLPerf Inference 的 Server 场景在 p99 TTFT/TPOT 约束下测吞吐，再乘以时租就得到每 token 成本——"基准吞吐 × 租金"是工程侧最硬的口径[MLPERF61]。局限：单租户、无抢占，生产环境"每完成 token 成本"高于基准推算。
  • goodput（SLO 达标吞吐）：只数满足 TTFT/TPOT 承诺的请求。定义见 DistServe（OSDI'24），教学手算见站内评测篇 2.1。用吞吐不达 SLO 的部分是"白赚的数字、丢掉的客户"。
  • 并发敏感性：同一硬件、同一模型，成本随并发剧烈变化——并发感知成本模型（arXiv 2606.11690）实测 H100 上 Mixtral-8x7B FP16：1 请求/秒时 $15.25/M tokens，25 请求/秒时 $0.87/M，同一套硬件差 17.5 倍[CONCOST26]。低并发自部署"看起来免费"，其实是按最贵档付费。

2.3 能耗类：J/token 是被低估的硬通货

每 token 能耗（J/token）把"算力、带宽、利用率"压成一个物理量。NVIDIA 给出的 GPT-MoE-1.8T 代际曲线：Hopper ≈10 J → Blackwell ≈0.4 J → Blackwell Ultra ≈0.2 J（NVFP4 口径，十年 200,000×）[NVFP4]。但能耗在账本里的位置常被高估：Epoch AI 测算电费只占 GPU TCO 的 10–15%，资本开支主导[EPOCHTCO]——省电的意义更多在散热上限、机柜密度与碳口径，而非直接省钱。2026 年学术侧开始把能耗当一等指标：SIMPLE 定律用 4 个参数闭式拟合每 token 能耗（13 个稠密模型、H100 上 R²=0.969）[SIMPLE26]；Wilhelm 等直接主张把 Energy/Token 列为基准一等公民并做能耗感知路由[EPT26]。

2.4 资产类：TCO 与租金曲线

SemiAnalysis InferenceMAX 把自部署成本写成一条公式： $/M tokens = TCO($/chip-hr) × 10⁶ ÷ (3600 × tok/s/chip)，其中 TCO 含折旧、电费、机房、网络与运维[INFERMAX]。芯片小时价本身在波动：H100 合约价从 2025-10 的 $1.70 回升到 2026-03 的 $2.35（+38%），B200 在 2026-09 达 $8.01（三个月 +79%，HBM 短缺）[GPUIDX]。租金上行与每 token 成本下行并不矛盾——软件与精度优化的降本速度（如 B200 上两个月 $0.11→$0.02/M 的纯软件 5×[NVIDIABLOG]）跑得比租金快，但把"租卡比去年贵"算进 TCO 是诚实账本的前提。

2.5 质量调整类：为"答对"付费

两个口径：（1）每成功任务成本（1.3 的公式，评测篇 4.2 有完整账本）；（2）固定能力价格——Epoch AI 的"固定性能成本"曲线：找能力相同（如 GPQA 同分）的模型比价格，2023 年以来平均每季 −47%[EPOCH26]。市场结构数据：同等能力档，开源模型比闭源便宜约 90%（OpenRouter 大规模交易数据研究）[MARKET25]；tiered 定价研究发现"经济档"价格半衰期仅 1.10 年，且降价的主力是软件/架构创新（TFP 残差约 103.7%）而非 GPU 降价[TIERED26]。

2.6 跨系统比较的纪律

引用任何成本数字前问三句：（1）口径——输入/输出/命中哪一格？哪个混合比例？离线吞吐还是 SLO 约束下的 server 吞吐？（2）快照日期——价格与租金随月波动，"DeepSeek 输入 $0.28"是 2025-09-29 的 V3.2 牌价，2026-11 的 flash 谷价已是 $0.15；（3）谁测的——厂商自提交（MLPerf 的传统警示）优于媒体转述，同行评审优于官方博客，官方博客优于匿名评测。本站评测篇 5.2 的横评口径纪律同样适用于成本数字。
本章小结
  1. 价格必须三分口径（未命中/命中/输出）+ 快照日期；混合价比例要按自家负载校准，错配可失真 5 倍。
  2. 产出指标用 goodput 而非裸吞吐；成本随并发剧烈变化，低并发自部署是隐形的奢侈品。
  3. J/token、TCO、每成功任务成本各管一段：能耗管密度与碳，TCO 管采购，质量调整管用户真实开销。

3发展历程：从"按 token 卖钻石"到分级定价的四年

$/M tokens 四年降了两个多数量级。把功劳簿摊开，会发现每一轮降价都对应一层技术的成熟：2022–2023 系统层（批处理与显存）、2024 模型层（MoE 与价格战）、2025 缓存与分离层（545% 账本）、2026 定价结构层（峰谷与分级）。本章按时间复盘，数字均带口径。

3.1 2022–2023：系统层革命，先消灭"浪费"

降本的第一性原理不是让计算更快，而是让已付费的计算不空转。三块基石：（1）Orca（OSDI'22）的迭代级调度：静态批处理在变长负载下吞吐损失可达一个数量级，连续批处理把它拉回，GPT-3 175B 上较静态批处理/FIFO 吞吐最高 36.9×（SLO 约束口径）[ORCA22]；（2）vLLM/PagedAttention（SOSP'23）：KV Cache 碎片从 60–80% 浪费降到 <4%，吞吐较当时系统 2–4×[VLLMPA23]；（3）Sarathi-Serve（OSDI'24）chunked prefill：把 prefill 切块掺进 decode 批，尾延迟约束下服务容量 2.6–5.6×[SARATHI24]。这些工作的共同点：零质量损失、纯系统收益，是所有后续降本的"免费头寸"。

3.4 2025–2026：分级定价时代——价格本身成为成本工程

  • 峰谷分时：DeepSeek 2026-08-16 起 V4 系列谷时=峰时半价（谷=工作日凌晨 UTC 时段）[DSPRICING26]；阿里云百炼部分模型错峰时段最高 6 折[QWENPRICING]。本质是把"夜间空转的折旧"打折卖给你。
  • 缓存命中价：全行业命中价普遍 1 折上下（Anthropic/Gemini/豆包），DeepSeek 做到 1/50——把你该自己做的前缀缓存，用价格杠杆"外包"给你。
  • SLO 分级：OpenAI Priority ≈2×牌价、Flex/Batch = 5 折[OAIEN]；Kimi HighSpeed 双倍价高速档[KIMIPRICE]——为时延付溢价，或用耐心换半价。
  • 按输入长度分档：豆包 1.6（2025-06）首创按输入长度区间定价，0–32K 档输入 0.8 元/M、输出 8 元/M，官方称综合成本较豆包 1.5 深度思考/R1 低 63%[DOUBAO16]；qwen3-max 三档阶梯同理——prefill 成本随长度非线性增长，价目表如实反映。

3.5 度量这条曲线：每季 −47% 与 725 倍/18 个月

Epoch AI 两份研究给出了可引用的刻度：（1）固定性能价格：2023 年以来平均每季 −47%；SOTA 能力刚出现时每季 −66%，两年后放缓至 −32%；实例：GPQA Diamond 75% 的每题成本从 o3（2025-01）的 $0.30 降到 GPT-5.6 Luna（2026 夏）的 $0.0004，18 个月 725 倍；FrontierMath 同期 377 倍[EPOCH26]。（2）按任务不均衡：六个基准上价格年降幅 9×–900×（中位 50×/年；2024 年后中位 200×/年）[EPOCHPRICES]。Tiered 定价研究补充市场结构：OpenRouter 318 模型 2020–2026 累计降价约 600 倍、经济档半衰期 1.10 年、而旗舰档因 reasoning 溢价（均值 31.5×）不服从指数衰减[TIERED26]。读曲线的正确姿势：降的是"固定能力"的价格，你要的能力越接近 SOTA，降得越慢、越贵。

本章小结
  1. 每轮降价对应一层技术成熟：2022–23 系统层消灭浪费（零质量损失），2024 模型层+价格战，2025 缓存/分离层与账本公开，2026 定价结构层。
  2. 价格战进入下半场：从"谁敢亏"到"谁的账本好"——毛利分化（24.6% 实测 vs 80%+ 自称）证明系统效率即定价权。
  3. 固定性能价格每季 −47%，但越接近 SOTA 降得越慢；分级定价把系统成本的时间/结构不均匀性直接写进了价目表。

4模型级降本：每个 token 少算一点、少搬一点

模型级手段改变的是每个 token 要做多少计算（FLOPs）与搬运多少字节（显存带宽）。它们共同的风险是质量折扣——所以每个手段后面都跟着"质量账"。站内量化篇与投机解码篇已把机制讲透，本章只做"性价比视角"的重读与最新数字。

4.1 量化：精度换吞吐，在 Blackwell 上是"降本第一杠杆"

量化同时省三样东西：显存（装得下）、带宽（搬得快）、Tensor Core 吞吐（算得快）。代际叠加的量级（MLPerf Llama-2-70B、8 卡离线口径）：以 H100 FP16 为基线，H100 FP8 +29%、H200 FP8 +84%、B200 FP8 +193%、B200 NVFP4 +441%[MLPERFFP4]。SemiAnalysis InferenceX 在 GLM-5.1/B200 上的口径：FP4 较 FP8 吞吐 +113%~149%，每 token 成本 −53%~−60%（46 tok/s/用户档：$0.16/M vs $0.35/M）[SEMIX-GLM]。质量侧：DeepSeek-R1-0528 从 FP8 量化到 NVFP4，MMLU-Pro/GPQA/LiveCodeBench 损失 ≤1%（厂商口径）；NVIDIA QAD 报告给的大模型界线——671B 级模型 PTQ 近无损（MATH500 95.4→94.2），小模型需要量化感知蒸馏[NVFP4QAD]。工程结论：旗舰模型 + NVFP4 目前是 $/token 的最优点之一，但质量回归必须跑自己的评测集。

量化像把货运卡车从"每件货物单独包装"改成"标准托盘"：单件防护弱一点（精度损失），但装车快了几倍、一趟运的货多几倍。货越贵重（模型越小、任务越难），越需要专门定制托盘（QAD）而不是直接套用。

4.2 MoE 与激活稀疏：参数可以贵，激活必须便宜

MoE 把"模型能力（总参数）"与"每 token 成本（激活参数）"解耦：DeepSeek-V3 671B 总参、每 token 仅激活 37B——能力按 671B 计、算力按 37B 付。腾讯混元 Turbo S（2025-02）用 Hybrid-Mamba-Transformer 结构降 KV 占用，牌价打到输入 0.8 元/M、输出 2 元/M，官方称约为 DeepSeek 同期 API 成本的 1/2~1/4（官方发布，媒体转述）[HUNYUANTS]。部署侧的研究线：Fiddler（ICLR'25）用 CPU 算专家、GPU 算注意力[FIDDLER25]；Pre-gated MoE（ISCA'24）预门控把专家预取与计算重叠，峰值显存降到 GPU-only 的 23%[PREGATED24]；MoE-Infinity（ASPLOS'24）按请求级专家激活矩阵做缓存，个人机器每 token 延迟 3.1–16.7×[MOEINF24]。2026-11 的 SGLang Paged Experts 把"专家按需进出显存"带进主流引擎：16 GB 卡跑超显存 MoE，比 CPU offload 快 12–30×[SGLPE]——MoE 的性价比红利第一次不需要专用引擎就能吃到。

4.3 投机解码的性价比观：加速 ≠ 省钱

投机解码通常被归入"低时延"工具箱，但它同时改变每 token 成本，方向不定。三个口径：（1）小 batch 加速：经典场景，接受长度 2–4 时 decode 加速 2–3×（站内投机解码篇全文）；（2）大 batch 仍可能赚：MagicDec 证明长上下文下 batch 32–256 仍有 2.51× 加速（稀疏注意力草稿抵消验证开销）[MAGICDEC24]；（3）能耗口径会反转：《Only Accepted Tokens Count》实测接受率低时每 token 能耗反而升高——教学账本：方案 A 10 J 产出 5 个 token（2 J/token）vs 方案 B 14 J 产出 6 个（2.33 J/token），"接受更多 ≠ 更省电"[SPECENERGY]。带 SLO 目标的调度版：AdaServe 把投机预算按 SLO 定制，违约降 4.3×、goodput 1.9×[ADASERVE25]；TurboSpec 闭环控制草稿长度以 goodput 为目标[TURBOSPEC]。结论：上投机解码前，先算"每成功 token 成本"而不是"每秒 token 数"。

4.4 路由与级联：90% 的请求用便宜模型就够了

最古老的降本手段：不每次都请最贵的模型。FrugalGPT（2023）查询级联，匹配 GPT-4 效果下成本最高降 98%（API 计费口径）[FRUGALGPT]；RouteLLM（ICLR'25）用偏好数据训练强弱路由器，部分场景成本降 2 倍以上而质量不降[ROUTELLM]。市场给了结构证明：同等能力档，开源模型比闭源便宜约 90%[MARKET25]——路由的意义就是让每个请求落到"能力够用的最便宜档"。这条线与站内推理预算篇（test-time-compute）的"自适应预算"是同一枚硬币的两面：那边管"该花多少思考"，这边管"该花谁的钱"。

本章小结
  1. 量化在 Blackwell+NVFP4 上是降本第一杠杆（$/token −53~60%），大模型 PTQ 近无损、小模型要 QAD。
  2. MoE 把能力与算力解耦（671B/37B），Paged Experts 让红利进入通用引擎；激活便宜才算便宜。
  3. 投机解码与路由都要按每成功 token 成本结算：接受率低时投机更贵，90% 的请求配得上便宜模型。

5缓存级降本：不重算已经算过的

推理负载有强烈的重复性：system prompt 千人一面、Agent 多轮对话反复带历史、RAG 反复检索同一批文档。缓存级降本的全部要义：第一次算，之后都不算。它是五层中"零质量损失"的一层（复用的是精确相同的 KV），也是 2025–2026 引擎侧竞争最激烈的一层。

5.1 命中价经济学：价目表已经替你算好了

各厂命中价（2.1 表）本身就是缓存价值的官方标定：DeepSeek 命中价 ≈ 未命中的 1/50（谷时 $0.003 vs $0.15）、Kimi/Anthropic/Gemini 约 1/10、豆包 1/5 加存储计时费。推理侧的机会成本计算：一段 32K 的 system prompt，未命中要付一次完整 prefill（计算 + 时延），命中只付 I/O；对输出同样 1K 的请求，命中能把单请求成本压掉 80–95%（取决于输入输出比与价差）。给引擎团队的两个推论：（1）把可复用前缀放到 prompt 最前面（缓存按前缀匹配，前缀里插一个时间戳就全盘失效）；（2）若用 API，把"我们该不该自建缓存"换成"命中率的每一个百分点值多少钱"——vLLM×Mooncake 的生产数据显示 Agent 负载命中率从 1.7% 提到 92.2%[VLLMMK26]，这就是答案的量级。

5.2 单机前缀缓存：从 RadixAttention 到"零开销默认开"

机制主线（站内推理服务篇 3.3 有图解）：SGLang 的 RadixAttention（NeurIPS'24）用基数树按内容组织历史 KV，新请求沿树匹配最长前缀、命中部分零计算，多轮 Agent 会话典型命中 80%+，吞吐最高 6.4×[SGLANG24]；vLLM V1（2025-01 起）把前缀缓存做成默认开启、零开销——0% 命中时吞吐损失 <1%[VLLMV1]。研究侧的补充：PromptCache（MLSys'24）模块化复用使 TTFT 降 8×（GPU）[PROMPTCACHE]；IC-Cache（SOSP'25）更进一步复用"语义相近"的历史问答，8 个部署吞吐 1.4–5.9×[ICCACHE]——从"精确前缀"走向"语义缓存"，代价是要管好质量边界。

5.3 跨实例 KV 池：把缓存从"单机内存"升级成"机房资源"

单机缓存的问题：请求被调度到别的实例就全miss。解法是把 KV 从引擎里拆出来做成共享池：

  • Mooncake（FAST'25 最佳论文，Moonshot 生产系统）：以 KVCache 为中心的分离架构，真实负载下 Kimi 多承载 75% 请求、模拟场景 SLO 内吞吐最高 +525%；Transfer Engine 在 8×400G RoCE 下 190 GB/s[MOONCAKE25]。2025-07 起 Kimi K2 生产部署（128×H200，P/D 分离 + 大规模 EP）prefill 224k / decode 288k tok/s[MOONCAKE25]。
  • 引擎集成潮：vLLM 官方博客（2026-05-06）给出 KV 池化数字——Agent 负载吞吐 3.8×、P50 TTFT 降 46×、命中率 1.7%→92.2%、近线性扩展至 60×GB200[VLLMMK26]；LMDeploy v0.18.0、TensorRT-LLM（Mooncake Store connector，2026-10）、TRT-LLM 镜像基线的 llm-d 相继接入[MKREPO][LLMD10]。
  • KV 当数据搬运：CacheGen（SIGCOMM'24）把 KV 流式压缩传输，TTFT 缩短 3.7×、字节流压到 1/4.3[CACHEGEN24]；CacheBlend（EuroSys'25 最佳论文）解决"多条预计算 KV 拼接会掉质量"的问题——选择性重算 10% 左右 token，TTFT 2.2–3.3×、吞吐 2.8–5×[CACHEBLEND25]。
  • 反直觉教训：LMCache（UChicago）实测，业界常用的上下文截断会把前缀缓存命中率砍半——为省显存做的截断，反而把缓存的钱亏掉了[LMCACHE]。

5.4 KV 压缩：缓存本身变小，命中更便宜

第三条线是让缓存本身更便宜：KIVI（ICML'24）2-bit 非对称 KV 量化，峰值显存省 2.6×、batch 至 4×、真实负载吞吐 2.35–3.47×[KIVI24]；DeepSeek-V2 起的 MLA 把 KV 压缩约一个数量级（站内 KV Cache 篇与注意力篇详述）；Cake（ICML'25）让"计算 KV"与"从盘加载 KV"并行互掩，TTFT 平均再降 2.6×[CAKE25]。压缩与池化是乘法：KV 小 4× 意味着同容量池装 4× 的会话、RDMA 搬运时间缩 4×。

本章小结
  1. 缓存级是唯一零质量损失的降本层：命中价（1/50~1/10）就是它的官方定价。
  2. 2025–26 的主线是跨实例 KV 池化：Mooncake 系（vLLM/SGLang/LMDeploy/TRT-LLM）把命中率推向 90%+，Agent 负载吞吐 3.8×。
  3. 别为省显存截断上下文——命中率减半的代价比显存贵；压缩（KIVI/MLA）与池化叠加是乘法收益。

6调度级降本：把昂贵的 GPU 时间填满

调度级手段不改变模型也不改变缓存，它改变的是"已付费的 GPU 时间里有多少在产出有效 token"。核心指标从吞吐升级为 goodput，核心动作从"批"升级为"分"与"迁"。机制细节站内推理服务篇第 2/4/5 章有完整拆解，本章聚焦性价比账。

6.1 批处理与切块：成本视角的两句话重述

连续批处理（Orca）解决"席位空转"：变长负载下吞吐损失从数量级降到接近零[ORCA22]；chunked prefill（Sarathi-Serve）解决"宴会赶走薯条"：prefill 切块掺批，尾延迟约束下服务容量 2.6–5.6×[SARATHI24]。性价比账：这两项对 $/M tokens 的贡献是把公式分母（吞吐）抬到硬件 roofline 附近，而且零质量损失、纯软件——任何还没做这两项的自部署，都在按 2–5 倍的溢价付费。

6.2 P/D 分离的账：什么时候值得养两个池

Prefill 计算受限、decode 访存受限，混在一个池里互相干扰。分离的收益证据：DistServe（OSDI'24）在 SLO 达标口径下较 vLLM 可承载 2.0–4.6× 请求速率、较 DeepSpeed-MII 7.4×、更紧 SLO 下 12.6×[DISTSERVE24]；Splitwise（ISCA'24）给出成本口径：同型机集群 1.4× 吞吐且成本 −20%，或同成本同功耗预算下 2.35× 吞吐[SPLITWISE24]；TetriInfer 直接以 perf/$ 为目标：混合负载省 38% 资源[TETRIINFER]。代价三条（KV 要跨机传、两池配比要调、显存规划更碎）与配套技术（NIXL、Mooncake Transfer Engine、EPLB 负载均衡）见服务篇 5.3。2026 年的新方向是"分离不再是二选一"：STAR（2025-10）按输入/预测输出长度在 decode 端再调度[STAR25]；DuetServe（2025-11）用单卡 SM 空间复用替代跨卡分离[DUETSERVE]；PPD（ICML'26）发现多轮会话里"部分 prefill 本地做"更划算，Turn2+ 的 TTFT 降约 68%[PPD26]。决策口径：负载 TTFT 与 TPOT 双敏感、规模够大（双池固定成本摊得开）才上全分离；否则 chunked prefill + 单机 P/D 已够。

6.3 弹性、迁移与抢占：把"空的时间"卖出去

  • 请求迁移：Llumnix（OSDI'24，阿里）跨实例 live migration，同尾延迟下省 36% 成本[LLUMNIX24]。
  • 弹性并行：LoongServe（SOSP'24，北大）按请求长度动态伸缩序列并行度，长上下文最大吞吐较 chunked prefill 3.85×、较 P/D 分离 5.81×[LOONG24]。
  • 抢占实例：SpotServe（ASPLOS'24）让推理跑在可中断的 spot 上，真实中断 trace 下 P99 只劣化 2.4–9.1×，实例费省 54%[SPOTSERVE]——离线/批处理负载的理想选择。
  • 冷启动：ServerlessLLM（OSDI'24）本地存储层级 + live migration，serverless 场景端到端延迟降 10–200×[SERVERLESSLLM]——弹性扩容的"开机型"成本被压到可用区间。
  • 系统层编排：NVIDIA Dynamo 的 Planner 按 SLA 目标自动扩缩，官方引用的 APSARA 2025 实践为 SLA 违约 −80%、TCO 再 −5%[DYNAMO1]；字节系 AIBrix（已捐 vllm-project）与 Red Hat llm-d（v1.0 GA，2026-10-20）把 P/D 分离、多租户 QoS、KEDA 自动扩缩做进 K8s——"调度级降本"正在从论文变成发行版[LLMD10][AIBRIX]。

6.4 多租户与削峰：好价格是调度出来的

公平性也有成本意义：VTC 虚拟 token 计数（OSDI'24）给多租户加了"服务差异 ≤2×"的硬上界，防止大客户挤走小客户造成的隐性违约[FAIRNESS24]。削峰的两个做法：（1）错峰复用：DeepSeek 披露其集群白天全量推理、夜间腾节点给训练/研究[DS545]——同一批卡的日历被排满，摊薄的就是 1.4 节说的"碎片化折旧"；（2）价格杠杆：峰谷计价（3.4 节）本质是让需求曲线配合供给曲线。DynamoLLM（HPCA'25 最佳论文）则证明能耗也能调度：按负载调实例数/并行度/DVFS，满足延迟 SLO 下省 53% 能耗、61% 客户成本[DYNAMOLLM]——调度器顺手把 2.3 节的 J/token 也管了。

本章小结
  1. 调度级的本质是把分母（goodput）抬到 roofline、把分子（空闲时间）压到零：连续批处理+chunked prefill 是没商量的基础项。
  2. P/D 分离的收益证据充分（goodput 2–7×、成本 −20%），但 2026 的答案是自适应：按长度再调度、SM 复用、部分分离。
  3. 弹性三件套（迁移/抢占/快冷启）+ 系统层（Dynamo/llm-d/AIBrix）让"填满日历"成为产品功能；削峰既靠调度也靠价格。

7集群与商业级：采购曲线、能耗账与定价设计

前四层都假设"卡已经在那了"。最后两层管更贵的事：买什么卡、怎么付电费、价格怎么定。这一层的决策周期是季度到年度，但一旦做错，上面四层的努力都在给错误的分母打工。

7.1 硬件性价比曲线：贵 4 倍的卡反而便宜

1.1 的公式在采购层面的推论：卡的"每 token 成本"= 时租 ÷ 吞吐，而不是时租本身。三个快照数字：H100 合约价 2025-10 为 $1.70、2026-03 回升 $2.35（+38%）；B200 2026-09 达 $8.01（三个月 +79%，HBM 短缺驱动）[GPUIDX]；GB300 NVL72 在 MLPerf v6.1 上单卡离线 16,635 tok/s（gpt-oss-120b）[MLPERF61]。代际吞吐差距更大：NVIDIA 引用 SemiAnalysis InferenceMAX 口径，GB200 NVL72 跑 DeepSeek-R1 较 H200 NVL72 吞吐 15×，叠加 Dynamo 后较"无 Dynamo 的 B200"每卡 7×[NVIDIABLOG]。采购纪律：永远按"目标负载下的 tok/s/芯片 ÷ 芯片时租"排序，而不是按卡价排序；同时把 NVLink 域（NVL72 的 72 卡共享显存带宽）当作计价单位——MoE 时代的吞吐是按"域"出来的。

7.2 能耗与碳：电费不是大头，密度和碳是

账本事实：电费仅占 GPU TCO 的 10–15%[EPOCHTCO]。但能耗仍以三种方式进入成本：（1）散热与功率上限决定机柜密度——同样机房塞进更多算力等于摊薄房租（TAPAS，ASPLOS'25 研究功率超额认购的收益[TAPAS]）；（2）碳口径开始进采购评估（大客户的 Scope 3）；（3）每 token 能耗是跨代际最公平的效率尺：Hopper ≈10 J → Blackwell ≈0.4 J → Blackwell Ultra ≈0.2 J（NVFP4，GPT-MoE-1.8T 口径）[NVFP4]。软件侧：DGX-H100 特征化显示多数配置可降 ~20% 功率而不损延迟/吞吐[GREENER]；DynamoLLM 在 SLO 内省 53% 能耗[DYNAMOLLM]。水足迹的科普口径（"每 10–50 条回复一瓶水"）已被修正到现代模型短对话约 5 ml/次——引用时用后者[WATER26]。

7.3 定价设计：价目表是最便宜的成本工程

3.4 节列了分级定价的四种形态。这里补设计视角：定价结构本质是把系统成本的不均匀性翻译成价格信号——峰谷对应集群利用率曲线、命中价对应缓存命中率、长度分档对应 prefill 计算量、SLO 分级对应资源独占程度。TSE 的工作论文从机制设计证明：开发者 API 的线性按 token 计价是"容量约束下影子成本的受限有效定价"，订阅/聚合器/按 token 各自对应不同的最优场景[MENUPRICE]。给自建平台团队的启示：内部计费（chargeback）也该长这样——按命中/未命中分开记账、给离线团队自动"谷价"，成本行为会自己跟着价格信号走。

技术要点同样值得抄：跨节点大规模 EP 扩 batch、计算-通信重叠、矩阵乘与 dispatch 用 FP8（与训练一致）、core-attention 与集合通用 BF16——每一项都是前几章的手段在这张账上的落点。后续讨论：社媒按开源推理栈反推其毛利率 84.2–96.1%（二手，KuCoin 转述）；SemiAnalysis 给出行业对照——Anthropic 2024 毛利率 −94%、MiniMax −25%、行业"混合毛利应约 60%"[SEMIX-X]。读 545% 的正确姿势：它证明的是"系统效率能造成多大的价差"，而不是"推理业务躺着赚钱"——免掉的营销、研发与训练成本，正是别家账本上的大头。

本章小结
  1. 采购按 tok/s ÷ 芯片时租排序、按 NVLink 域计价；贵 4 倍的卡可以更便宜。
  2. 电费只占 TCO 一两成，功率密度、机柜与碳才是能耗的账本形态；每 token 能耗是跨代际的公平尺。
  3. 545% 账本的价值在方法论：每个成本假设可复算、每项技术对应账上一行——自建平台都该有这张表。

8.3 观测与归因：钱花到哪个请求上了

没有归因就没有优化优先级。（1）请求级能耗归因：StepSplit（arXiv 2611.13802）把 Shapley 值方法扩到大批量：每请求能耗 = 自身部分 + 共享均摊，静态批 batch 8–256 下 L1 误差 0.4–4.3%（按 token 均分则为 13.4–61.3%）——"按 token 均摊"是常见的错误归因[STEPSPLIT]；（2）先仿真后上机：Vidur（MLSys'24）证明配置搜索可用仿真完成——LLaMA2-70B 最优配置 96 核 CPU 约 1 小时（$9.93/时）替代 42K GPU 小时（约 $218K）的实测搜索；配置错配的代价高达 2×[VIDUR24]（站内性能仿真篇有完整方法论）；（3）口径统一：并发感知成本模型提醒同一硬件不同并发下 $/M 相差 17.5×——归因报告必须带并发与 SLO 上下文[CONCOST26]。

8.4 反模式清单

  • 用旗舰模型做路由级任务：分类/抽取/改写用小模型或便宜档，市场数据说同能力开源便宜约 90%[MARKET25]。
  • SLO 过度：所有请求都要 p99 快 = 全员 Priority 价。把流量分层（交互/批处理/离线），每层各自的 SLO 与价格。
  • 只看吞吐不看 goodput：不达 SLO 的吞吐是对着镜子举杠铃；报表里两列必须并排。
  • 缓存价目没设计：自建平台不区分命中/未命中 → 内部用户没有动力把 prompt 写成可缓存的前缀结构。
  • 截断上下文省显存：LMCache 实测命中率减半，省了小钱亏了大钱[LMCACHE]。
  • 跨系统直接比数字：不带口径与快照的 "$X/M" 一律不可比（2.6 纪律）。

8.5 动手：三十行算清你的 $/M tokens

把 1.1 与 1.3 的公式放进标准库 Python（无第三方依赖，口径注释即文档）：

#!/usr/bin/env python3
"""单位成本计算器：$/M tokens、命中率收益、质量调整与 goodput。口径见注释。"""
RATE = 2.35          # USD per GPU-hour，集群时租（含分摊的 TCO 加成）
GPUS = 8             # 卡数
TOKS_OUT = 16_000    # 系统输出吞吐 tok/s（SLO 达标部分才计入，即 goodput 口径）
HIT_RATE = 0.80      # 输入 token 的缓存命中率
HIT_DISCOUNT = 0.1   # 命中部分的相对成本（按"命中价≈未命中 1/10"折算）
IN_OUT_RATIO = 3     # 真实负载输入:输出比（先用自家日志算，别抄基准的）
QUALITY = 0.9        # 任务成功率（用于质量调整）

per_m_out = RATE * GPUS * 1e6 / (TOKS_OUT * 3600)        # 输出每 M tokens 成本
per_m_in  = per_m_out / IN_OUT_RATIO                     # 未命中输入的粗估同价折算
per_m_hit = per_m_in * HIT_DISCOUNT
blended   = (IN_OUT_RATIO * ((1-HIT_RATE)*per_m_in + HIT_RATE*per_m_hit) + 1*per_m_out) / (IN_OUT_RATIO + 1)
per_task  = blended / QUALITY                           # 质量调整：答错重试都算钱

print(f"输出 ${per_m_out:.3f}/M | 输入(未命中) ${per_m_in:.3f}/M | 命中 ${per_m_hit:.4f}/M")
print(f"混合价(输入:输出={IN_OUT_RATIO}:1) ${blended:.3f}/M | 每成功任务等效 ${per_task:.3f}/M")
# 例： RATE=2.35, GPUS=8, TOKS_OUT=16000 → 输出 $0.326/M；命中率 0.8 使混合价较全未命中约省 26%
代码 8-1 · 单位成本计算器：改五个参数即可用于自建集群或 API 对照。质量调整与混合比例是两个最常被漏掉的口径；本站评测篇 4.2 的"每成功任务成本"教学账本与本代码同源。
本章小结
  1. 仪表盘 8 个数，先看goodput 达标率与命中率——它们决定其他数字有没有意义。
  2. 决策树按症状下药：贵在 prefill 找缓存、贵在 decode 找精度、贵在空闲找调度、贵在峰值找定价、贵在重试找质量。
  3. 归因要 Shapley 不要均摊、搜索要仿真不要实机、对比要口径不要裸数——算错账的降本比不降本更贵。

9未来方向

  • 从每 token 到每任务：Agent 多步调用把 token 消耗放大 10–100 倍，"每 token 便宜"与"每任务便宜"开始脱钩——质量调整成本、任务级计费（tau-bench 类）会成为主口径（站内推理预算篇与 Agent 推理系统篇已铺开）。
  • 质量感知定价与路由：tiered 定价研究显示旗舰档因 reasoning 溢价不服从指数降价[TIERED26]；按"能力档"而非"模型名"计价（AA 的 Intelligence per $ 是雏形）会倒逼路由器与级联成为标配。
  • 能耗/碳口径标准化：主流基准（MLPerf）尚无能耗与碳的必报项[MLPERF61]；SIMPLE 定律、Energy/Token 倡议与 Shapley 归因正在把 J/token 变成可审计指标[SIMPLE26][EPT26][STEPSPLIT]。
  • 硬件市场波动 vs 效率赛跑：HBM 短缺把 B200 租金三个月推高 79%[GPUIDX]，而纯软件两个月可降 5×[NVIDIABLOG]——租约结构（短约 vs 长约）本身将成为成本工程题目。
  • 跨厂商成本可比模型：定制引擎篇 6.9 指出的开放问题依然成立——每家"每 token 成本"口径不可比；学术界（并发感知成本、Tiered 定价）正在补这块地基[CONCOST26][TIERED26]。
本章小结
  1. 主口径正从每 token 走向每任务：Agent 时代便宜的是 token，贵的是任务。
  2. 定价、基准与归因方法都在向质量感知与可审计演进；J/token 会成为像 MFU 一样的常识指标。
  3. 租金上行与效率赛跑并行，租约与采购结构本身进入成本工程的射程。
