0怎么用这张表：字段与证据分层

一条"研究判断"是一个可证伪的预判：它在明确的负载与指标下，比较两个具体方案，并预先写下什么结果出现就推翻它。

  • 九个字段：问题、适用负载、机制依据、最强基线、固定变量、观测指标、否定条件、当前证据状态、拟回看日期。缺少否定条件的判断不收进本表——那只是愿望。
  • 证据分层：论文报告（他人实验）、源码核对（静态阅读）、教学推算（本站算例）、模拟（本站仿真）、独立实测（本站运行）、待验证假设（尚无实验）。当前三条判断均为最后一类；机制依据本身有各自的分层与快照日期。
  • 回看纪律：到期只对照预先写下的否定条件与观测指标更新状态；条件不够用时新增判断，不改旧判断的胜负标准。排序不变时，记录使其成立的负载条件与结论边界，不外推。
  • 日期语义：登记日期是判断写下的日子；拟回看日期按证据预期更新节奏定（本表统一 3 个月）。界面、索引或排版调整不改变任何字段。
本章小结
  1. 判断必须带否定条件与回看日期，否则不登记。
  2. 证据分层写明；"待验证假设"不得写成已有实验支持。
  3. 回看时对照预写标准更新，不事后挪门柱；排序不变也要记录条件。

1判断 1：缓存感知路由能否胜过最短队列路由

有共享 KV 池（或高前缀复用负载）时，把请求派去"已有它前缀"的实例（缓存感知路由）是否比派去"队列最短"的实例（最短队列路由）更优？

  • 适用负载：多轮 Agent 会话与固定系统提示的高复用流量（Mooncake 披露线上负载理论前缀复用率上限约 55%，论文问答场景可达 90%[MOONCAKE]）；对照组为低复用、请求间前缀基本独立的负载。
  • 机制依据：命中免去整块 prefill 计算，但缓存块可能不在本机——传输时间与排队时间都会吃掉收益（KV Cache 篇 5.4 边界算例：命中省 16 ms、拥塞时传输要 40 ms 的教学反例）。
  • 最强基线：同资源下的最短队列路由（含 P/D 分离部署的默认调度）。
  • 固定变量：相同实例数与型号、相同模型与精度、相同缓存容量与淘汰策略、相同请求集；只变路由策略。
  • 观测指标：P95 TTFT（口径按评测篇表 1-1，含排队）、goodput、命中 token 数、跨实例传输字节与耗时、排队时长。负载三档：高复用、低复用、突发。
  • 否定条件：在高复用负载下缓存感知路由的 P95 TTFT 与 goodput 均不优于最短队列（差值落入测量噪声），或其收益完全被传输开销抵消 → 判断不成立，记录负载与带宽条件。
  • 当前证据状态：待验证假设。Mooncake 的生产数字是"缓存为中心调度"的论文报告口径，未在同等对照下与最短队列路由比较。
  • 拟回看日期：2027-02-19。
本章小结
  1. 比较对象是同资源下的最短队列路由，不是"无缓存"。
  2. 三档负载分开报；P95 TTFT 用含排队的客户端口径。
  3. 命中 token 是机制量，收益要看延迟与 goodput 的最终分布。

2判断 2：Agent 配置按 token 单价与按每次成功任务成本的排序何时一致

同一个 Agent 任务集上，按"每百万 token 价格"给模型/引擎配置排序，与按"每次成功任务成本"排序，什么时候给出相同答案、什么时候反转？

背景证据：企业负载研究实测 agent 顺序步进跑在 batch=1，每步 2% 的失败率在 20 步后足以抹平 2× 的 decode 优势——按 token 吞吐排名与按每成功任务成本排名会给出不同答案（论文报告口径，见成本篇 6.5）。

  • 适用负载：多步工具调用 Agent 任务（coding / computer-use / 多轮检索），验收门槛可机器判定；对照组为单轮问答。
  • 机制依据：任务级成本把失败、重试、工具等待与恢复计入分子，把"验收通过的任务"定为分母（C_unit = C_total ÷ V_valid）；token 单价两者都不含。
  • 最强基线：同一任务集上 token 单价最低的配置（含前缀缓存命中的有效单价）。
  • 固定变量：相同任务集与验收门槛、相同预算上限、相同重试与超时策略、相同工具环境；只变模型/引擎配置。
  • 观测指标：任务成功率、每次成功任务成本（含失败与重试的 token 与等待）、token 单价（名义与命中后）、工具等待占比、恢复成功率。预先定义"排序不变"的记录方式：两种排序的一致性统计量及反转发生的任务长度分布。
  • 否定条件：在全部任务集上两种排序一致（含长任务与高失败率子集）→ 判断无区分度，token 单价是足够代理；记录任务长度与失败率范围。
  • 当前证据状态：待验证假设。现有证据是论文报告的个别对照点，未做过同任务集、同门槛、同预算的系统排序比较。
  • 拟回看日期：2027-02-19。
本章小结
  1. 分母是验收通过的任务，不是 token；失败成本留在分子。
  2. 排序一致与否按预定义的统计量记录，反转要标出任务长度条件。
  3. 预算、门槛与重试策略固定，否则两个排序都不可比。

3判断 3：交互视频在同资源下，同卡与流水线分离的选型是否随响应约束改变

同资源清单、同质量门槛下，流式视频服务用"同卡放全栈"还是"DiT—VAE 流水线分离"，加上响应约束（P95 控制到屏幕时延）后，排序会不会变？

  • 适用负载：交互式流式视频（固定块粒度与控制频率，负载形态按Self Forcing 篇 E4/E6 组的稳态与突发两档）。
  • 机制依据：分离提高稳态吞吐节拍，但首块、稳态与交互关键路径是三条账——更低的流水间隔不自动降低单次控制响应（该篇 3.5）；块等待 (N−1)/f 是模型侧优化移除不了的结构项（3.6.1.1 算例）。
  • 最强基线：同资源清单下的同卡部署（含相同块粒度与缓冲深度）。
  • 固定变量：相同卡数与型号、相同模型与精度、相同分辨率/帧率/块粒度/缓冲、相同质量门（FVD 与任务相关指标作约束不作除数）；只变放置。
  • 观测指标：P95 控制到屏幕时延（版本号判定首个有效响应）、卡顿率、有效视频秒数（V_valid 口径：过时与被丢弃帧不计产出、成本照记）、吞吐。响应约束两档：无约束与 P95 ≤ 阈值。
  • 否定条件：加入响应约束前后排序都不变（分离始终占优或始终劣），且响应约束不可行时 V_valid 归零的边界一致 → 响应约束不改变选型，判断无区分度；记录质量门与负载条件。
  • 当前证据状态：待验证假设。PixVid 的 495 ms vs 34 ms 是架构对照（像素空间 vs 潜空间），不是放置对照；TurboServe/SlackServe 报告的是各自系统的绝对数字，未做同资源放置比较。
  • 拟回看日期：2027-02-19。
本章小结
  1. 比较的是放置（同卡 vs 分离），架构与块粒度全部固定。
  2. 响应约束两档分别报排序；V_valid 过滤过时帧、成本照记。
  3. 现有论文数字不能替代同资源对照，结论等本判断的实验或新论文。
