0 导读：把额外计算变成可验证的答案收益

本文主线：生成候选 → 选择与验证 → 分配预算 → 在质量、延迟和费用之间选择。本文回答四个问题：多想一会儿和多答几次分别改变了什么？为什么候选里有正确答案仍可能交付错误答案？简单题与困难题如何分配预算？怎样把策略接入真实推理服务？

推理时计算（test-time compute）指模型部署后，为解决一个输入投入的计算。它可以用于更长的生成、多个候选、搜索中间状态、验证器或另一个模型。这里研究的是完整求解策略；底层生成如何加速，见投机解码；循环深度怎样改变模型内部计算，见Loop Transformer。

1 预备知识：质量、算力、费用和等待时间

1.1 四种预算不能互相替代

设策略 π 对题目 x 的最终正确概率为 Q，消耗计算 C、费用 M、墙钟时间 L。“预算相同”必须指明限制的是哪一个量。相同输出 token 数不意味着相同 FLOPs：模型大小、上下文长度、验证器及缓存复用都会改变计算。并行生成可以缩短等待，却仍占用更多 GPU 时间。

目标示例（本文定义）：最大化 E[Q(x, π)]
约束：E[M(x, π)] ≤ 平均费用预算
      P(L(x, π) ≤ 截止时间) ≥ 服务达标率
      同时满足显存、在途任务数与总调用次数限制

考试时可以让一个人反复检查，也可以请几个人各做一遍再选答案。人数、总工时、交卷时间和最终正确率是四本账。

1.2 一个候选的概率与一组候选的概率

在“各次独立、成功概率相同且等于 p”的教学假设下，n 个候选至少一个正确的概率是 1 − (1−p)n。若 p=0.4、n=4，结果为 0.8704。但这个数描述候选集合中存在正确答案；实际部署还得把它选出来。候选会共享知识盲点，独立假设也可能不成立。

pass@k用于衡量 k 个候选中至少一个成功的能力，通常依赖评测时知道正确与否。系统真正交付一个答案时，应报告所选答案的准确率。不能把评测器挑中的最佳答案当成线上可用的选择策略。

本章小结
  1. 比较之前写清费用、计算量和墙钟约束。
  2. 候选集包含正确答案，不保证选择器能找到它。
  3. 独立采样公式是教学上界分析的起点，真实错误相关性需要测量。

2 并行采样：从多数投票到 Best-of-N

2.1 两种选择规则

Self-Consistency 对多个推理路径的最终答案做聚合，适用于答案可以规范化并比较一致性的任务。它不要求每个路径都相同。[SC] Best-of-N 则使用评分器给完整候选排序，取分数最高者；评分器可以是规则、可执行测试或学习到的奖励模型。

[SC] Xuezhi Wang 等. Self-Consistency Improves Chain of Thought Reasoning in Language Models，ICLR 2023；arXiv:2203.11171，首次提交 2022-03-21，v4 2023-03-07。原文：“samples a diverse set of reasoning paths”（采样一组具有差异的推理路径。）原文。

例如四个候选答案是“0.5”“1/2”“0.50”“2”，字符串投票会把前三个拆散。数学、代码和开放问答需要不同的答案规范化及判定规则。开放式写作没有天然的唯一正确答案，投票也不自动等价于质量评价。

2.2 生成与选择的错误要分开

表 2-1 · 本文建议的候选级诊断
观测主要问题下一步
所有候选都错基础模型或候选多样性不足换模型、检索证据、改变求解策略
存在正确候选，最终仍错选择器失误校准评分器、增加执行验证、检查长度偏好
更多候选后准确率下降挑中了投机迎合评分器的样本检查分布漂移与评分漏洞，降低 N 或更换判据
准确率增加，任务超时增多服务或并发资源约束联合评价达标成功率，限制并行扇出

固定 N 的计算近似为 N 次生成成本加选择成本，但墙钟时间取决于排队和批处理。若所有候选共享完全相同的输入前缀，缓存可以减少重复 prefill；分支生成后的 KV 仍然各自增长。不要把前缀复用解释成 N 条分支只占一条分支的显存。

本章小结
  1. 多数投票依赖答案可比较，Best-of-N 依赖评分器可靠。
  2. 分别测量候选覆盖率与最终选择正确率。
  3. 并行候选能增加计算与显存压力，延迟收益要放进实际负载验证。

3 验证器与搜索：判断下一步是否值得扩展

3.1 结果奖励与过程奖励

结果奖励模型（ORM）给完整答案评分；过程奖励模型（PRM）给中间步骤反馈。过程监督研究在 MATH 场景比较了这两类监督信号，并公开步骤标注数据。其证据针对论文模型与任务，不能直接推出任何 PRM 在所有领域都优于结果判定。[PRM]

步骤分数需要聚合成候选分数。取最小值强调最弱一步，取乘积会受到步骤数和校准误差影响，取平均则可能掩盖一个致命错误。要在留出的完整任务上校准聚合规则；“语言流畅”“看起来严谨”都不能作为已验证正确性的同义词。

3.2 搜索需要状态、扩展器和停止条件

树形搜索把一个部分解作为节点，生成若干下一步，评价后保留有希望的分支。Tree of Thoughts 将这种探索、评估与回退组织成语言模型求解流程。[TOT] 实现时至少定义：节点包含哪些状态、一次扩展生成多长、保留多宽、何时回退、如何判断完成。

3.3 验证也要占预算

设每轮扩展 b 个分支，深度 d，即使只保留固定宽度，仍需为每轮候选评分。代码执行验证还要支付构建、沙箱和测试时间。为了比较策略，应把生成器、验证器、合并器和工具都计入成本；验证器用到更强模型时，也应写出模型版本与费用。

失败边界：可执行测试仅覆盖测试集，不能证明程序对所有输入都正确；过程评分的局部最优也可能走向错误终点。保留一个无需模型主观评分的最终验收步骤，记录评分高但验收失败的样本。
本章小结
  1. 步骤反馈和最终结果判定承担不同职责。
  2. 搜索必须明确状态、扩展、剪枝和终止条件。
  3. 验证与工具调用的时间、费用都进入同一预算账本。

4 串行推理：思考长度、修正与提前停止

4.1 更多 token 可能改变什么

串行计算可以用于分解问题、检查已得到的结论、重新求解，也可能只产生重复文字。s1 研究在特定训练模型上通过 budget forcing 控制思考过程：限制长度或在模型试图结束时延长生成。其效果建立在相应模型与评测条件上。[S1]

部署时应区分“思考预算”和“最终答案输出预算”。把所有预算耗尽后直接截断，可能得到不完整 JSON、缺少结论或未结束的工具参数。本文建议预留最终输出和验收预算，并将被上限截断的响应计入失败或单独的截断类别。

4.2 什么时候值得继续

一个可研究的决策量是“再花一单位预算带来的预期质量提升”。继续生成的理由可以是执行测试失败且错误可定位、两个独立候选冲突、必要证据尚缺；单纯把“再仔细想想”重复多次，缺少可检验的停止依据。

提前停止也会犯错：模型可能过度自信，容易检查的问题未必就是容易解的问题。因此应报告停止策略在不同难度、长度、领域上的误停率，并保留固定预算作为对照。控制器观察得到的是当前状态和历史校准结果，不能看到本题的测试答案。

4.3 串行和并行怎样组合

可以先小规模并行生成，再只修正冲突候选；也可以先快速求解，未通过验证才升级模型。每个阶段都要重新估计剩余截止时间，避免前阶段花掉大部分预算后，后阶段仍按完整额度执行。具体收益属于待测量的系统设计，不是叠加两篇论文的加速比。

本章小结
  1. 思考长度是策略参数，更多文字不等于更高正确率。
  2. 为最终答案、工具执行和验收预留预算。
  3. 提前停止与升级都要在留出集校准，并统计错误决策。

5 自适应预算与大小模型路由

5.1 给不同题目不同预算

Snell 等研究发现，推理时计算策略的效果随题目难度变化，由此研究按题目自适应分配计算。[TTC] 这提供了一条方法论：先估计收益曲线，再选择预算档位。线上难度未知，论文分析中的难度划分与实际可部署的难度预测器必须分开。

[TTC] Charlie Snell 等. Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters，arXiv:2408.03314，2024-08-06。原文：“critically varies depending on the difficulty of the prompt”（效果会显著随输入问题的难度而变化。）原文。

可用信号包括输入特征、快速模型的行为、候选分歧和执行反馈。使用模型自报信心前，需要检验其校准：预测 80% 成功的一组题是否真的接近 80% 成功。阈值在校准集上选择，最终结果在未参与调参的测试集上报告；禁止用测试答案给每道题挑最佳预算。

5.2 路由和失败后升级的区别

RouteLLM 使用偏好数据学习强弱模型之间的路由，以权衡响应质量和成本。[ROUTE] 请求开始前直接路由，代价是预测错误可能难以及时纠正；先用小模型再升级，可以利用中间反馈，但必须加上小模型已经花掉的费用、再次读取上下文的开销和累计等待时间。

5.3 带预算预留的控制伪代码

# 教学伪代码；estimate 来自校准集，不接触测试答案
remaining = total_budget
while not verified and now() < deadline:
    options = policy.propose(observed_state)
    feasible = [a for a in options
                if upper_cost(a) + finalization_reserve <= remaining
                and predicted_latency(a) < deadline - now()]
    if not feasible:
        break
    action = choose_by_calibrated_gain(feasible)
    reservation = ledger.reserve(upper_cost(action))
    result = execute_with_limit(action, reservation, deadline)
    ledger.settle(reservation, result.actual_cost)  # 失败也扣费
    remaining = ledger.remaining
    observed_state = update_from_observation(result)
return finalize_with_reserved_budget(observed_state)
代码 5-1 · 本文设计的预算控制伪代码；预测延迟不提供硬保证，执行层仍需超时与取消，费用无法预先硬封顶的服务需额外处理超支。

多分支同时启动时，先预留再结算，避免每个分支都看到同一份“剩余预算”。取消请求也不代表已发生的调用免费；账本要处理取消确认前的在途费用。难度分布变化时重新校准，保留固定策略作为漂移检测基线。

本章小结
  1. 自适应策略依赖可部署信号与独立校准集。
  2. 模型路由和失败后升级的费用、时间结构不同。
  3. 并发分支先预留预算，失败和取消仍要结算。

6 与推理服务、缓存和 Agent 的连接

6.1 一个请求变成多个排队实体

Best-of-N 会把一个用户任务展开成多个生成请求。如果每条分支都获得独立的高优先级，少量复杂任务就可能挤压其他用户。本文建议为“任务”建立统一标识与在途预算，在任务级限制扇出，在请求级做组批；达到截止时间时将取消传播到生成、验证器和工具。

串行深推理通常拉长占用时间；并行探索则增加同时驻留的 KV。调度器可以按剩余时间、分支价值和可抢占性研究策略，但这些估计会出错。应比较相同用户任务到达率下的达标成功数，不能只比较解码 token/秒。

6.2 投机解码与预算策略的分工

正确实现的经典投机采样旨在保持目标采样分布同时减少生成耗时；增加候选或改变思考长度则改变完整求解策略。两者可以结合，但草稿、验证和额外分支会争用算力，必须做基线、单项、组合消融。KV 前缀复用是否有效，也取决于模型、提示模板和精确 token 前缀是否相同。

6.3 交互任务中的计算边界

Agent 测试时计算研究把并行采样、串行修正、验证与轨迹多样性扩展到交互任务。[ATTC] 在真实环境中，并行候选不能各自随意执行有副作用的操作；可以并行读取与模拟，最终提交应经过统一执行与验收。环境等待很长时，加速模型生成可能只改善很小一段关键路径，详见Agent 时间账本。

本章小结
  1. 调度与预算都应认识用户任务及其多个分支。
  2. 底层解码加速与求解策略优化需要组合验证。
  3. 交互式搜索必须计入工具时间，并控制最终动作的执行。

7 对照实验：怎样证明预算花得值得

7.1 四组基线与公平条件

在相同模型、提示模板和任务集上，比较单次生成、固定 N 的采样选择、固定串行预算、自适应策略。路由实验再加入始终用小模型和始终用大模型。分别做等平均费用、等截止时间两种比较；一个策略在其中一项占优，不代表另一项也占优。

每组保存完整候选、最终选择、生成与验证 token、工具费用、排队时间、终止原因和独立质量标签。多次运行保持相同题目集合，按题目配对比较并估计不确定性；测试集上的失败样本全部保留。搜索参数和评分器只能在训练/校准划分调节。

7.2 复算一个明确标为人工的账本

本站提供同一组四道题的三种策略记录：single 成功 2/4、花费 4 积分；best-of-4 成功 3/4、花费 20；adaptive 成功 3/4、花费 12。每次成功成本分别为 2、20/3 和 4。这些标签与费用均由作者手工设定，不是模型测量，也不是实际运行了一个自适应控制器。

7.3 看失败边界而非单点排名

画出预算横轴、最终准确率纵轴的曲线，另画截止时间内成功率和每次成功费用。按题目类别与难度分层，标出候选全错、选择失败、截断、工具失败等原因。在质量、延迟和费用上同时不被另一方案压过的配置构成可选集合；最终选择由应用约束决定。

本章小结
  1. 对照必须包含简单固定策略及路由的两端模型。
  2. 评测独立于预算选择，所有失败进入同一账本。
  3. 人工样例只核对统计，真正的收益要靠留出集与多次运行证明。

8 研究边界与下一步

值得继续研究的三个问题是：低成本难度预测能否在新领域保持校准；验证器能否识别高分错误并控制额外开销；预算控制器能否与负载、缓存和截止时间联动。它们分别需要分布外评测、对抗性错误集和服务负载实验。

本站已有架构、量化、缓存和服务文章提供底层优化手段；本篇把这些手段接到“最终任务是否成功”的目标上。实际部署先选择可解释的少量预算档位，取得完整账本后再增加复杂控制器。相邻专题：性能评测与复现实验、Agent 在线推理系统。

本章小结
  1. 难度预测、验证器可靠性和负载联动是三项独立研究问题。
  2. 先有固定基线与完整记录，再增加自适应复杂度。
  3. 收益最终体现在可验证任务质量、截止时间和总费用上。
