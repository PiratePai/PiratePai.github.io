1 · 引子：三个让人困惑的现象，指向同一个答案

先看三个乍看毫无关系、实则同根同源的现象。

现象一：思考模型"话多"。2024 年 9 月 OpenAI o1 发布后，"用更多测试时算力换更高准确率"成为大模型领域的主旋律：模型先写一大段思维链（Chain-of-Thought, CoT），再给出答案。但代价立等可见——延迟和费用随思考长度线性增长，而且要在语言空间里做 RL 后训练（如 RLVR）才能学会"怎么想"。更微妙的是：自然语言真的是思考的最佳载体吗？写 CoT 时，大量 token 花在"维持文本连贯"上（"我们首先……接下来……因此"），真正承载推理的关键 token 只占少数。

现象二：小参数量打赢大模型。2025 年 2 月，马里兰大学 Tom Goldstein 组发布了 3.5B 参数的 Huginn 语言模型：它只预训练了 800B token（约等于同期主流模型的一个零头），但在数学等推理基准上，推理时把内部一个 4 层的核心块循环几十次，性能一路上涨，作者称其效果"有时相当于把计算负载加到 50B 参数的量级"[12]。2025 年 6 月的 HRM 用 27M 参数在数独、迷宫和 ARC 上做出接近满分的表现[14]；10 月三星的 TRM 用 7M 参数在 ARC-AGI-1 拿到 44.6%[15]。参数量和推理能力之间，显然隔着一层可以撬动的东西。

现象三：闭源实验室悄悄"闭嘴"。2026 年，The Information 报道 OpenAI 新模型 Astra 使用了一种"以某种方式掩盖部分或全部 AI 推理过程"的新技术[21][22]；社区分析指向循环深度（recurrent depth）——模型在潜空间里反复迭代内部状态，而不是把思考过程写成文字。几乎同时，爱好者发现国产模型 Nanbeige4.2-3B 的技术报告写着它"用 28T token 从零预训练了一个循环 Transformer"[21]。循环结构第一次有了公开的工业级落地证据。

这三个现象的共同答案：神经网络的"参数量"和"计算量"可以解耦。传统 Transformer 每一层都有独立权重，深度 = 参数量；但如果把同一组权重循环使用，参数不变、计算深度却可以任意拉长——模型在"想得深"与"说得长"之外，获得了第三种扩展推理算力的方式。这条技术线今天被称为 Loop Transformer / 循环语言模型（Looped LM）/ 循环深度（Recurrent Depth）/ 潜空间推理（Latent Reasoning），2024 年底以来已长成一片森林——截至 2026 年 9 月，专门追踪它的 Awesome-Loop-Models 清单已收录 200 余篇论文[36]。
"By 'loop model,' we mean that, within a single forward pass of a model, a shared learned internal layer, block, module, or operator is reused." 所谓"循环模型"，指的是在模型的一次前向传播内部，重复使用一个共享的、可学习的层、块、模块或算子。 — Awesome-Loop-Models 仓库对"循环模型"的范围界定，Huang et al., GitHub, 2026-04-24 发布 [36]

2 · 预备知识：本科生也能懂的"循环深度"原理

2.1 Transformer 的"深度"到底买到了什么

一个标准 Transformer 语言模型 = 词嵌入层 + N 个结构相同但权重各自独立的层（每层 = 自注意力 + 前馈网络）+ 输出头。数据流是：x₀ = Embed(词)，然后 xₗ = Blockₗ(xₗ₋₁)，一层层堆上去。深度 N 是"顺序计算步数"：第 3 层能利用的任何信息，都必须已经被前 2 层写进表示里。

为什么顺序步数重要？考虑一个多跳问题："A 的母亲的哥哥的女儿是谁？"。每做一次"查关系"（图谱一跳），网络需要若干层来：定位要查的实体 → 检索关系 → 把结果写到新位置。三跳问题需要的深度约是三倍。深度不够怎么办？有两个办法：

办法 A：把中间结果写成文字（CoT）
每生成一个 token，整个网络就重新前向一遍——相当于把"深度"外包给"序列长度"。问题：中间结果必须压缩成离散词表上的一个 token，信息瓶颈大；推理延迟与 token 数成正比；还要专门训练。
办法 B：把深度堆得更高
直接加深网络。问题：参数量、显存、训练和推理成本同步膨胀；而且大部分日常输入根本用不着那么深，浪费。

Loop Transformer 的主张：顺序计算步数（深度）和独立参数量本来就没有必然绑定关系——让一层网络重复使用自己的权重，就能在不加参数的前提下把深度拉到任意长。计算发生在连续的潜空间（hidden states）里，不占用 token 序列，也不需要离散化。

2.2 RNN 的时间维 vs Transformer 的深度维：一个对偶

这件事其实在神经网络的历史里发生过一次。RNN 的循环是沿着时间的：hₜ = f(hₜ₋₁, xₜ)，同一个 f 在每个时间步重复使用——参数极少，但训练必须沿时间逐步展开（BPTT），无法并行，这是 RNN 在 2017 年被 Transformer 取代的核心原因。Transformer 用 N 个独立层把"顺序计算"从时间维挪到了深度维：同一句里所有 token 的计算图一次性并行建好，训练吞吐暴增——代价是每层独立参数。

标准 Transformer：xℓ = Blockℓ(xℓ−1)，ℓ = 1…N   （N 组权重，深度 N）
Loop Transformer：x(k+1) = fθ(x(k))，k = 1…L   （1 组权重，深度 L，L 可在推理时任选） 两种"顺序计算"：前者把循环放在序列时间维（参数共享但训练慢），后者放在深度维（参数独立但训练可并行）。Loop Transformer 在深度维上重新引入参数共享，兼得两者一半好处。

关键洞察（也是本科读者最容易忽略的一点）：循环放在深度维，训练仍然可以并行！因为循环的每一步对序列中所有 token 同时发生——句子第 1 个词循环 32 次和第 2048 个词循环 32 次，是在同一批矩阵乘里完成的。这与 RNN 沿时间的循环（必须先算完 t-1 时刻才能算 t 时刻）本质不同。所以 Loop Transformer 训练时像 Transformer 一样高效并行，推理时像 RNN 一样可以选择"想多少步"。

2.3 三个必须解决的设计问题

把 x ← f(x) 写出来只要一行，但直接这么循环会立刻撞上三个问题——它们恰好定义了这个领域十年的技术演进：

问题一：状态会"忘题"
循环几轮后，初始输入的信息在反复变换中逐渐丢失，模型忘了题目本身。解法是输入注入（input injection）：每一轮都把输入嵌入重新加回状态——Huginn 的 x = x + input_embeds（第 8 节代码）。
问题二：循环会"发散"
同一个非线性映射反复复合，状态范数可能指数爆炸或塌缩到平凡不动点。解法包括残差缩放（按循环数 1/N 调整[33]）、谱范数约束[23]、LayerNorm 增益控制[27]、噪声注入[12]。
问题三：梯度传不回来
循环 L=32 次就要存 32 份中间激活做反向传播，显存爆炸。解法是截断反传：前 L−k 步 no_grad，只对最后 k 步回传梯度（Huginn 的做法，第 8.3 节），或者干脆求不动点后用隐函数定理只存一份状态（DEQ 路线[3]）。
（附带问题：何时停）
难题多想、易题少想，才有性价比。这就是自适应计算问题——从 ACT[1] 的 halting 机制，到 2026 年按 token 路由循环深度[16]、按难度置信度退出[37]，是贯穿十年的暗线。

2.4 一个 40 行的最小可跑示例

实验 1 · 用不到 40 行 PyTorch 搭一个最小的循环语言模型。跑起来之后你可以把 L 从 1 改到 64——参数一个没变，计算深度变了 64 倍：

import torch, torch.nn as nn

class LoopBlock(nn.Module):                       # 一个可循环的标准 Transformer 块
    def __init__(self, d=64, h=4):
        super().__init__()
        self.attn = nn.MultiheadAttention(d, h, batch_first=True)
        self.ffn  = nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d))
        self.n1, self.n2 = nn.LayerNorm(d), nn.LayerNorm(d)
    def forward(self, x):                         # x: (B, T, d)
        a, _ = self.attn(self.n1(x), self.n1(x), self.n1(x),
                          is_causal=True, need_weights=False)
        return x + self.ffn(self.n2(x + a))       # 两个残差分支

class LoopLM(nn.Module):
    def __init__(self, vocab=1000, d=64):
        super().__init__()
        self.embed  = nn.Embedding(vocab, d)
        self.prelude = LoopBlock(d)               # 锚层：token → 初始潜状态
        self.core    = LoopBlock(d)               # 核心块：唯一被循环的部分
        self.coda    = LoopBlock(d)               # 锚层：潜状态 → 预测
        self.head    = nn.Linear(d, vocab)
    def forward(self, ids, L=4):                  # L = 循环次数，推理时随便改
        e = self.prelude(self.embed(ids))         # e 同时充当"题面备忘录"
        x = e
        for _ in range(L):                        # —— 整个范式就这一行 ——
            x = self.core(x + e)                  # 输入注入：每轮重新看题
        return self.head(self.coda(x))

lm, ids = LoopLM(), torch.randint(0, 1000, (2, 32))
logits1 = lm(ids, L=1)                            # "快思考"：1 次循环
logits8 = lm(ids, L=8)                            # "慢思考"：8 次循环，参数相同

这就是 Huginn 三明治结构的微缩版：prelude（锚）→ core×L（循环）→ coda（锚）。真正的 Huginn-3.5B 用 1+4+1 = 6 个块、平均循环 32 次（第 8 节）；本文所有"循环深度"变体——HRM 的双尺度循环、Ouro 的深度分配、PLT 的跨循环并行——都是在这 40 行的骨架上做文章。

3 · 发展时间线一览（2016–2026）

  • 2016-03 · ACT（Graves, Google DeepMind）[1] —— 首次让 RNN 自己学习"想多久"：halting 概率 + ponder 惩罚，自适应计算的源头。
  • 2018-07 · Universal Transformer（Dehghani 等, Google Brain）[2] —— 第一个权重共享的循环 Transformer：沿深度循环同一层 + 每位置动态停止；理论上证在一定假设下图灵完备。ICLR 2019。
  • 2019-09 · DEQ 深度平衡模型（Bai 等, CMU/FAIR）[3] —— 把"循环多少次"推到极限：直接求不动点 z* = f(z*)，隐函数定理让反向传播只需常数显存。NeurIPS 2019。
  • 2021-06 · Can You Learn an Algorithm?（Schwarzschild 等, UMD）[6] —— 共享残差块在简单谜题上训练，测试时多迭代几步即可解出更难的实例——"测试时算力外推"的最早清晰证据。NeurIPS 2021。
  • 2021-07 · PonderNet（Banino 等, DeepMind）[5] —— 把"何时停止"变成可学习的概率分布，ACT 思想现代化的里程碑。NeurIPS 2021 口头报告。
  • 2022-11 · 路径无关平衡模型（Anil 等）[4] —— 发现平衡模型要"路径无关"才能从更多推理迭代中获益，为后来的训练目标设计埋下伏笔。NeurIPS 2022。
  • 2023-01 · 循环 Transformer = 可编程计算机（Giannou 等, UW-Madison）[7] —— 手工构造 13 层循环 Transformer 执行指令集：程序计数器、条件分支、函数调用、甚至上下文 SGD。ICML 2023。
  • 2023-11 · 循环 Transformer 更擅长学习"学习算法"（Yang 等）[8] —— 在上下文回归任务上，循环结构用 <10% 参数打平标准 Transformer；提出教师强制课程训练法。ICLR 2024。
  • 2024-05 · MoEUT（Csordás 等）[9] —— 用 MoE 弥补权重共享的容量损失，循环 Transformer 首次在语言建模上与非循环模型参数匹配地掰手腕。NeurIPS 2024。
  • 2024-10 · Relaxed Recursive Transformers（Bae 等, Google）[10] —— 把预训练好的 LLM 改造成层共享递归模型（+ 每深度 LoRA），证明存量模型可以"事后循环化"。ICLR 2025。
  • 2024-12 · COCONUT（Hao 等, Meta）[11] —— "连续思维"：把最后隐藏状态直接回填为下一输入嵌入，不解码成词；潜空间推理范式的引爆点。COLM 2025。
  • 2025-02 · Huginn / 循环深度（Geiping 等, UMD）[12] —— 3.5B、800B token 从零预训练的循环深度语言模型；推理时任意加深，KV 跨循环复用 + 零样本自适应算力。NeurIPS 2025。同月：Reasoning with Latent Thoughts（Saunshi 等, Google）证明 k 层×L 循环 ≈ kL 层、"循环即潜思维"[13]。ICLR 2025。
  • 2025-06 · HRM 层级推理模型（Wang 等）[14] —— 仿脑双时间尺度循环（慢规划 + 快执行），27M 参数在 ARC/数独/迷宫上出圈。
  • 2025-07 · Mixture-of-Recursions（Bae 等）[16] —— token 级循环深度路由 + 深度受限 KV 缓存，把"自适应算力"做进循环模型。NeurIPS 2025。
  • 2025-10 · Ouro（Zhu 等, 字节联动学界）[17] —— 首批"把推理内置进预训练"的循环语言模型：7.7T token、1.4B/2.6B，对标最高 12B 模型；同月：PLT 并行循环 Transformer[18] 跨循环并行 + KV 共享，循环几乎零额外延迟；TRM[15] 7M 参数 ARC-AGI-1 44.6%；并行采样器[19] 免训练加速 Huginn 5×。
  • 2025-11 · 循环化改造（McLeish 等）[20] —— 给现成前馈 LM 加装循环深度，比同预算继续后训练更划算。
  • 2026 上半年 · 定律与稳定性之战 —— Parcae 缩放定律[23]、等深度缩放定律[24]、残差缩放理论[33]、机制分析（循环不动点）[25]、CoT 与压缩循环的内存分离定理[34]；系统侧 MELT（KV 固定内存）[30]、LT2 线性时间[28]；业界：Astra 传闻[21][22]、Nanbeige4.2-3B 公开采用循环预训练[21]。
  • 2026 下半年 · 全面扩散 —— 循环结构进入视觉生成（ELT[38]）、VAE（LoopVAE[39]）、推荐（RecRec）、世界模型、扩散语言模型（Thinking with Looped Flows[35]）；理论工具进入动力系统深处（分形收敛盆[35]、Jacobian 视角）；SMELT 把 MoE×循环缩放定律合流[32]。专用论文清单突破 200 篇[36]。
一句话概括四个阶段：① 2016–2022 想清楚"能不能循环"（ACT/UT/DEQ/PonderNet）；② 2023–2024 想清楚"循环有什么用"（可编程性、参数效率、学习算法）；③ 2024 末–2025 想清楚"循环能推理"（潜空间思考、从零预训练、小模型打大模型）；④ 2025 末–2026 想清楚"循环能落地"（工业预训练、并行化、缩放定律、全模态扩散）。

4 · 阶段一（2016–2022）：思想萌芽 —— 从 ACT 到平衡点

4.1 ACT（2016）：让网络学会"想多久"

循环结构的第一个现代问题不是"怎么循环"，而是"何时停"。Graves 在 2016 年的 ACT（Adaptive Computation Time）[1] 里给 RNN 加了一个 halting 单元：每个时间步输出一个"继续思考"的概率，累计超过阈值就停，训练时用"思考时长惩罚"（ponder cost）防止网络无限磨蹭。这个朴素机制种下了整个领域的两个母题：计算应当按需分配、停止本身可以被学习。此后几乎所有循环深度模型的自适应算力设计——UT 的逐位置停止、PonderNet 的概率分布、2026 年的深度路由与学习停止[16][37]——都能溯回到这里。

4.2 Universal Transformer（2018）：第一次把"循环"装进 Transformer

Transformer 靠并行训练赢了 RNN，但 Dehghani 等人注意到一个反向事实：Transformer "在许多循环模型轻松胜任的简单任务上无法泛化"，比如复制一个比训练时更长的字符串[2]。原因正是 2.1 节讲的：固定深度 = 固定顺序计算预算。他们的 Universal Transformer（UT）把 RNN 的参数共享重新装回 Transformer：

  • 沿深度循环同一组权重（self-attention + transition 函数），步数可变；
  • 每个位置独立决定何时停止（ACT 的逐 token 版本）——简单 token 早停，难 token 多想；
  • 加坐标编码与每步位置信息，让网络知道"这是第几轮思考"。

结果：算法类任务（复制、排序、图问题）泛化显著超过标准 Transformer，机器翻译上小胜。更重要的是理论地位——在一定假设下 UT 可被证明是图灵完备的，而固定深度的 Transformer 不是。

"We introduce the Universal Transformer (UT), a parallel-in-time self-attentive recurrent sequence model which can be cast as a generalization of the Transformer… under certain assumptions, UTs can be shown to be Turing-complete." 我们提出 Universal Transformer（UT），一种"时间上并行"的自注意力循环序列模型，可以看作 Transformer 的泛化……在一定假设下，可以证明 UT 是图灵完备的。 — Dehghani, Gouws, Vinyals, Uszkoreit, Kaiser,《Universal Transformers》, arXiv:1807.03819, 2018-07-10 首发（v3 2019-03-05）, ICLR 2019 [2]

为什么它当时没有火？三个字：太贵了。逐位置动态停止导致批次内计算图参差不齐，2018 年的算力和训练基建撑不起这种模型；而 GPT/BERT 路线的"堆层数"简单粗暴有效。UT 成了一个"预言书"——它对"深度与参数解耦"的全部论证，要等七年后被循环深度模型逐字兑现。

4.3 DEQ（2019）：把循环推到"无穷深"

如果循环次数 L 可以是 32，为什么不是 ∞？Bai 等人的深度平衡模型（DEQ）[3] 换了个视角：与其展开 L 层，不如直接求不动点 z* = f(z*, x)——这相当于一个"无限深"的权重共享网络。妙处在于反传：在不动点处用隐函数定理，梯度可以一步算出，不需要沿无限层展开，显存占用与深度无关。DEQ 把循环网络和动力系统（不动点迭代、收敛性）正式连通，后来的"平衡推理器""临界 DEQ"乃至 2026 年大量关于循环收敛性的理论工作（第 11.3 节）都在它的框架里说话。2022 年 Anil 等人进一步发现：平衡模型要真正从"推理时多迭代几步"中获益，其解必须路径无关——即无论从哪条路径迭代，收敛到同一个答案——这直接启发了后来的训练目标设计[4]。

4.4 PonderNet（2021）与"easy-to-hard"（2021）：两个方向的小露锋芒

DeepMind 的 PonderNet[5] 把 ACT 的 halting 改造成干净的概率混合："继续想"与"直接答"两个分布的可学习加权，用类似变分推断的目标端到端训练，解决了 ACT 长期训练不稳的老毛病。同年 Schwarzschild 等[6] 做了一个对后来影响深远的实验：训练一个共享权重的循环残差网络去解简单版的前缀和 / 迷宫 / 国际象棋残局，然后在测试时让它多迭代几步——它就能解出训练时从没见过的更难实例。这是"测试时通过增加循环次数扩展算力"的最早清晰证据之一，Huginn 论文标题里的 "Test-Time Compute" 说的就是这件事。

阶段一的遗产：概念全部就位——参数共享（UT）、不动点（DEQ）、可学习停止（ACT/PonderNet）、测试时外推（easy-to-hard）。缺的是一个让这些想法长出规模的理由。这个理由在 2023 年由两条线同时给出：一条来自理论（循环 = 可编程），一条来自参数效率（MoE 补容量）。

5 · 阶段二（2023–2024）：理论与可编程性 —— 循环 Transformer 能"算"什么

5.1 循环 Transformer = 可编程计算机（2023）

Giannou 等（UW-Madison / Stanford 一众循环结构研究的核心人物）问了一个工程师式的问题：一个循环 Transformer 到底能执行多复杂的程序？他们手工构造（不是训练）了一个 13 层的循环 Transformer，证明了它可以当一台通用计算机跑：把输入当作打孔卡（指令 + 内存），循环一次执行一条指令，网络内部维护程序计数器，实现了条件分支、函数调用，甚至上下文内的 SGD 和反向传播[7]。这篇工作的直接价值不是实用，而是能力标定：循环次数 = 程序步数，循环结构把 Transformer 从"有限深函数"升级成"通用机"。

"We provide a framework for using transformer networks as universal computers… This small instruction-set computer is implemented by a looped, 13-layer transformer." 我们提供了一个把 Transformer 网络用作通用计算机的框架……这台小型指令集计算机由一个循环的 13 层 Transformer 实现。 — Giannou, Rajput, Sohn, Lee, Lee, Papailiopoulos,《Looped Transformers as Programmable Computers》, arXiv:2301.13196, 2023-01-30, ICML 2023 [7]

5.2 循环 Transformer 更擅长学习"学习算法"（2023-11）

Yang 等（与上一批作者高度重叠）把上面的构造问题反过来：不用手工设计，训练出来的循环 Transformer 自己能学会迭代算法吗？他们在 Garg 等提出的"上下文回归"任务上（给一堆 (x, y) 样本，让模型隐式地做梯度下降式拟合再预测新点）对比标准 Transformer 与循环 Transformer：循环模型在多类潜在线性模型的数据拟合任务上，用不到 10% 的参数达到与标准 Transformer 相当的表现[8]。方法上的关键贡献是教师强制课程（teacher-forcing curriculum）：训练时给每个循环步都直接施加"正确中间状态"的监督，像教小孩做长除法一样，先把每一步教对，再让循环自己跑。这个技巧后来成为所有循环语言模型训练配方的标配（Huginn、Ouro 均有变体）。

"…the looped transformer achieves performance comparable to the standard transformer across various data-fitting problems while using less than 10% of the parameter count." ……循环 Transformer 在各类数据拟合问题上取得了与标准 Transformer 相当的性能，而参数量不到后者的 10%。 — Yang, Lee, Nowak, Papailiopoulos,《Looped Transformers are Better at Learning Learning Algorithms》, arXiv:2311.12424, 2023-11-21（v3 2024-03-16）, ICLR 2024 [8]

同期理论工作迅速跟上：Gatmiry 等（Google）证明线性循环 Transformer 能精确实现多步（预条件）梯度下降[50]；Chen 等进一步证明其样本复杂度无需随循环数指数增长[49]；Xu & Sato 严格分析了循环 Transformer 的近似速率与表达力短板，并提出给每个循环步注入时间步编码（TMLT）缓解"所有步骤看起来一样"的问题[48]；图算法模拟、长度泛化等方向也各有构造性结果（如 Fan 等《Looped Transformers for Length Generalization》[40]的前身工作）。一个清晰的共识在形成：很多"推理"本质上就是迭代算法，而循环结构是迭代算法的天然宿主。

5.3 MoEUT（2024）：补上"容量"短板

循环结构的阿喀琉斯之踵是容量：所有循环步共享权重，等于强制每一步做"同一种运算"，模型总容量受限于那一小块参数。Csordás 等（IDSIA/Schmidhuber 组 × Stanford）的 MoEUT 给出了漂亮的解法：循环块内部用细粒度混合专家（MoE）——权重共享的是"块结构"，但每次循环内部可以按 token 路由到不同的专家组合，容量回来了。结果：MoEUT 在参数匹配的语言建模上打平标准 Transformer，训练算力（MACs）更少[9]。"循环 × MoE"自此成为一条固定配方（2026 年的 LoopMoE[31]、SMELT[32]、CHERRY 等持续精化）。

5.4 Relaxed Recursive Transformers（2024-10）：存量模型也能循环化

Google 的 Bae 等展示了另一条路线：拿已经预训练好的 LLM，把它的一半层数砍掉、剩下的层循环使用，再给每个"虚拟深度"配一个极小的 LoRA 增量来保留各深度所需的差异化行为——参数立刻省下一半，性能接近保留；他们还模拟了"按深度连续批处理"的调度，理论上限吞吐可提升 2–3×[10]。这条路线的意义在于：循环化不必从零开始，它是模型压缩 / 部署效率问题的一个新答案（2025 年 11 月 McLeish 等的"循环化改造"把它推到更强：改造后的模型在数学上甚至优于同预算继续训练的原模型[20]）。

阶段二的遗产：循环结构的能力边界被标定（可编程、能学迭代算法、容量可用 MoE 补），训练方法成型（教师强制课程、逐步监督），并且证明了两件"实用的事"：省参数、能改造存量模型。但所有实验都还停留在中小规模或合成任务——循环结构能不能撑起一个真正的大语言模型？这个问题交给 2025 年。

6 · 阶段三（2024-12 – 2025）：潜空间推理爆发 —— COCONUT / Huginn / HRM / TRM

6.1 时代背景：o1 之后，"思考"的成本问题浮出水面

2024 年 9 月 OpenAI o1 把"测试时算力扩展"变成行业共识，但 CoT 路线的三个结构性成本也随之显形：

成本一：延迟与费用
思考 10000 token 才回答的模型，对交互式应用和 agent 长回路都是灾难；且每个思考 token 都要走一遍完整前向。
成本二：数据与训练依赖
会"想"需要 RLVR / 蒸馏思维链数据；推理能力与预训练脱节，变成昂贵的后处理。
成本三：语言模态的束缚
空间推理、连续控制、密码学运算……很多思考过程没有对应的自然语言词；离散 token 每步只有几十比特带宽，而 hidden state 是几千维连续向量。
（隐藏成本：CoT 不忠实）
写出来的推理和内部计算可以不一致——既然如此，为什么要强制模型"用写的"来"想"？

2024 年 12 月起，三篇/批工作几乎同时给出了同一个方向的不同实现：把推理搬进潜空间。

6.2 COCONUT（2024-12，Meta）：连续思维

Hao 等（Meta，田渊栋组）的 COCONUT（Chain of Continuous Thought）改动小得惊人：在输入序列里插入若干 <latent> 占位 token，模型跑到这个位置时，不解码、不采样，而是把前一个位置的最后隐藏状态直接回填为这个位置的输入嵌入，继续前向（代码见第 9 节）。也就是说：思考在隐藏状态的连续空间里进行，每步"潜思维"的宽度是整个隐藏维度（GPT-2 下是数 千维浮点），而不是一个词表上的离散选择。

两个设计值得注意：

  • 课程训练：先用完整 CoT 训练；然后逐步把 CoT 的前 k 步"替换"成 k 个 latent 位置重训，k 从 1 慢慢加大。模型从"用语言想"平滑过渡到"用潜空间想"，而不是硬切换。
  • BFS 直觉：语言 CoT 每生成一个词就是一次硬承诺（DFS），走错一步无法回头；而一个连续向量可以同时编码多个候选下一步的叠加，作者用 ProntoQA 等逻辑推理任务上的实验支持这一点：COCONUT 在需要大量搜索的规划任务上超过 CoT，且思考 token 数少于 CoT[11]。
"…rather than decoding it into words, the model feeds it back as the next input embedding directly in the continuous space… enabling a breadth-first search (BFS) instead of prematurely committing to a deterministic path." ……模型不把它解码成词，而是直接在连续空间中把它作为下一个输入嵌入回填……这使得（模型能进行）一种广度优先搜索，而不是过早地锁定一条确定性路径。 — Hao, Sukhbaatar, Su, Li, Hu, Weston, Tian,《Training Large Language Models to Reason in a Continuous Latent Space》, arXiv:2412.06769, 2024-12-09（v4 2026-08-23）, COLM 2025 [11]

6.3 Huginn（2025-02，UMD）：第一个"原生循环"的大语言模型

Geiping 等（马里兰大学 Goldstein 组，在美国超算 Frontier 的 4096 块 AMD GPU 上训练）发布的 Huginn-3.5B 是这个领域的成人礼：第一次有循环深度模型从零预训练到数十亿参数规模，并且像正常 LLM 一样可用。架构即图 1 的三明治（1 锚 + 4 核 + 1 锚，参数上它是 6 个块的"小"模型），核心发现：

  • 推理时任意加深：训练时平均循环 32 次，推理时可以循环 8 次、64 次，正确率随循环数平滑上升，无需任何微调（他们展示过 zero-shot 推到训练从未见过的深度区间）。
  • 零样本自适应算力：循环状态之间的变化率可以当作"收敛信号"——简单句子状态很快稳定（少循环），难句状态持续变化（多循环）。模型自己"知道"难不难。
  • KV 缓存跨循环复用：新 token 的第 k 轮循环可以直接复用旧 token 在先前轮次留下的 KV（第 8.5 节），这让"加深"的边际成本远低于朴素想象。
  • 3.5B 的模型、800B token，多项推理基准上"相当于 50B 参数的计算负载"的效果——虽然说法夸张成分存疑（见 10.2 节的批评），但趋势明确。
"…a new language model architecture that scales test-time computation by implicitly reasoning in latent space… by iterating a recurrent block, thereby unrolling to arbitrary depth at test-time." ……一种新的语言模型架构，通过在潜空间中隐式推理来扩展测试时计算……通过迭代一个循环块，在测试时展开到任意深度。 — Geiping, McLeish, Jain, Kirchenbauer, Singh, Bartoldson, Kailkhura, Bhatele, Goldstein,《Scaling up Test-Time Compute with Latent Reasoning: A Recurrent Depth Approach》, arXiv:2502.05171, 2025-02-07（v2 2025-02-17）, NeurIPS 2025 [12]

配套开源非常完整：模型权重（HuggingFace tomg-group-umd/huginn-0125）、训练代码（seal-rg/recurrent-pretraining）、800B token 训练集全量（tomg-group-umd/huginn-dataset）[45]——本文第 8 节的代码解析即基于此仓库。

6.4 Reasoning with Latent Thoughts（2025-02，Google）：给"循环即思考"补上理论

几乎同日，Saunshi 等（Google Research）发表了对该范式的理论定调之作。核心结论有三：

  1. 有效深度缩放：k 层循环 L 次的模型 ≈ kL 层非循环模型（在加法、多跳归纳、数学等任务上系统验证），且明确超过 k 层模型——"循环换深度"在缩放意义上成立；
  2. 潜思维定理：循环模型隐式生成"潜思维"（latent thoughts），L 次循环可以模拟 T 步 CoT；循环深度缩放与 CoT 的推理时缩放同构；
  3. 推理 vs 记忆的二分：需要顺序组合的任务吃深度，需要查表的任务吃容量——循环天然偏向前者，因此循环本身可作为正则化器抑制死记硬背。
"We make the stronger claim that many reasoning problems require a large depth but not necessarily many parameters." 我们提出一个更强的论断：许多推理问题需要的是很大的深度，而不一定是很多的参数。 — Saunshi, Dikkala, Li, Kumar, Reddi,《Reasoning with Latent Thoughts: On the Power of Looped Transformers》, arXiv:2502.17416, 2025-02-24, ICLR 2025 [13]

6.5 HRM 与 TRM（2025-06 / 2025-10）：极小参数的"分级思考"

2025 年 6 月，Wang 等的层级推理模型 HRM 刷屏：受大脑"多时间尺度"组织启发，用两个互相耦合的小循环模块——高层模块负责慢速抽象规划、低层模块负责快速细节执行——交替迭代，外部输入只在高层每 N 步注入一次。27M 参数、不用 CoT 数据、不用预训练，在 1000 个样本上训练，即可在困难数独、大迷宫上"接近完美"，并在 ARC 上超过更大模型[14]。

"…a high-level module responsible for slow, abstract planning and a low-level module for detailed computations… With only 27 million parameters, HRM… achieves nearly perfect performance on complex Sudoku puzzles and optimal path finding in large mazes." ……一个负责缓慢、抽象规划的高层模块，和一个负责细节计算的低层模块……仅用 2700 万参数，HRM……在复杂数独谜题和大型迷宫最优寻路上取得接近完美的表现。 — Wang, Li, Sun, Chen, Liu, Wu, Lu, Song, Abbasi Yadkori,《Hierarchical Reasoning Model》, arXiv:2506.21734, 2025-06-26（v3 2025-08-04）[14]

HRM 当时的媒体解读颇为夸张（"击败 o3"之类），学界后续复现揭示了更多细节（例如实际总计算量并不小、对超参敏感）；但它的两个模块化思想——时间尺度分层与把输入注入降频——被后续大量工作吸收。10 月，三星 SAIL 蒙特利尔的 Jolicoeur-Martineau 用"毒舌 + 开源"的风格发布 TRM（Tiny Recursive Model）：一个 7M 参数的两层共享网络先反复更新潜状态（update 阶段），再反复精炼答案（refine 阶段），在 ARC-AGI-1 上做到 44.6%、ARC-AGI-2 7.8%，训练代码全开源[15]。"小网络 + 大循环"作为一条独立路线自此站稳。

6.6 Mixture-of-Recursions 与并行采样（2025-07 / 2025-10）：效率补课

循环结构的两大工程软肋在这一年双双得到回应：

  • 软肋一：所有 token 循环次数相同（简单 token 被迫陪跑）。Bae 等的 MoR 给每个 token 路由一个学习到的循环深度，注意力和 KV 缓存只在该深度内维护，简单题 1–2 次循环就出结果[16]。NeurIPS 2025。它也是 2026 年 Raschka 博士分析 Astra 时重点引用的工程参考[21]。
  • 软肋二：循环必须串行（第 t+1 轮依赖第 t 轮结果，解码时延迟随 L 线性涨）。Geiping 组的并行采样器用"扩散强制"式调度：生成新 token 的同时并行精炼已有 token 的各轮潜状态，对现成 Huginn-3.5B 免重训直接最高 5× 加速[19]；一个月后 PLT（第 7.2 节）从架构层面给出更彻底的方案。
阶段三小结：不到一年，循环深度路线完成了从"玩具验证"到"三线开花"的跃迁——Meta 的连续思维（COCONUT）证明潜空间可思考，UMD 的 Huginn 证明可以从零预训练，HRM/TRM 证明极小模型 + 分层循环可以非常能打。2023 年 Google 理论家们写下的"k 层 × L 循环 ≈ kL 层"，现在有了工业尺寸的对照实验。剩下的悬念只有一个：它能不能上生产？

7 · 阶段四（2025-10 – 2026）：产业化与规模化 —— Ouro / PLT / 缩放定律 / Astra 传闻

7.1 Ouro（2025-10）：把推理写进预训练

2025 年 10 月 29 日，Zhu 等（字节跳动 Seed 联动 Bengio、Eshraghian 等一批学界作者）发布 Ouro——第一批"把推理内置进预训练阶段"的循环语言模型（LoopLM）家族。此前所有循环模型（包括 Huginn）都是"先按普通 LM 训练、推理时再加深"；Ouro 直接在 7.7T token 的预训练中做三件事：

  1. 潜空间迭代计算：预训练目标本身就鼓励多轮循环；
  2. 熵正则的深度分配：模型学会"这个 token / 这段输入值得循环几次"，训练时把循环深度当作可学习的分配问题；
  3. 规模验证：1.4B 与 2.6B 两个尺寸，全开源。

结果：1.4B 与 2.6B 在广泛基准上"匹敌最高 12B 的 SOTA LLM"；作者的分析进一步指出优势"并非来自更大的知识容量，而是更强的知识操纵能力"，且循环模型产生的推理轨迹与最终答案的对齐度高于显式 CoT[17]。

"Ouro 1.4B and 2.6B models enjoy superior performance that match the results of up to 12B SOTA LLMs… this advantage stems not from increased knowledge capacity, but from superior knowledge manipulation capabilities." Ouro 的 1.4B 与 2.6B 模型取得了卓越性能，匹敌最高 12B 的 SOTA 大模型……这一优势并非源于知识容量的增长，而是来自更强大的知识操纵能力。 — Zhu, Wang, Hua, Zhang, …, Bengio, Eshraghian,《Scaling Latent Reasoning via Looped Language Models》, arXiv:2510.25741, 2025-10-29（v5 2026-07-01）[17]

配套的深度阅读清单（Reza Bayat reading list）与专门网站 ouro-llm.github.io 同步出现，社区把"loop depth"正式称作继参数量、数据量之后的第三条缩放轴。

7.2 PLT（2025-10）：让循环不再串行

PLT（Parallel Loop Transformer）瞄准循环结构的最后一个死穴——串行延迟。两个动作：① 跨循环并行（Cross-Loop Parallelism）：不同 token 被分配到不同的循环轮次，一次前向同时算完——比如前 1/4 token 跑第 3 轮、后 3/4 token 跑第 1 轮，反正各轮权重相同；② KV 复用 + 门控滑窗注意力（G-SWA）：第一轮算出的 KV 缓存给所有后续轮共享，配合滑窗局部注意力把精度找回来。结果：拿到循环模型的精度、只付标准 Transformer 的延迟与显存[18]。

"Cross-Loop Parallelism… computing different loops for different tokens at the same time, all within a single pass." 跨循环并行……在同一次前向中，同时为不同 token 计算不同的循环（轮次）。 — Wu, Chen, Luo, Yan, Yu, Xia, Zhang, Zhan, Zhong, Zhou, Qiao, Bin,《Parallel Loop Transformer for Efficient Test-Time Computation Scaling》, arXiv:2510.24824, 2025-10-28 [18]

加上同期 McLeish 等的"循环化改造"（给现成前馈 LM 加循环深度，数学性能反超同预算继续预训练[20]），循环路线的部署故事完整了：新模型可以原生循环（Ouro），旧模型可以改造加装（Retrofit），推理可以并行加速（PLT / 并行采样器）。

7.3 2026 上半年：缩放定律与稳定性之战

工业界入场后，学术界的注意力转向两个更硬的问题：怎么缩放与怎么稳定。

  • 缩放定律：Prairie 等的 Parcae（ICLR 2026 LIT Workshop）用注入层谱范数约束驯服训练不稳定性，并系统测定了"固定参数预算下，训练算力与测试循环深度的 isoFLOPs 型缩放定律"[23]；Schwethelm 等《等深度缩放定律》直接量化"一次循环值多少参数"（循环与独享深度、训练算力之间的兑换率）[24]；Wang 等证明共享块的相关更新需要按循环数加强 1/N 的残差缩放，且该超参可从小模型迁移到大循环数[33]。2026 年 4 月起，这些定律开始在 8B/0.8B-active MoE 等工业尺寸上复验（IFM Research 的系列消融[36]）。
  • 稳定性与动力学：朴素的"同一块反复乘"会出现范数爆炸 / 塌缩不动点 / 训练发散。2026 年上半年的对策百花齐放：Fully Looped Transformer 的全循环稳定化训练[27]、Fixed-Point Reasoners 把推理器显式设计成吸引子动力系统[35]、LayerNorm 即"隐式增益控制"的理论解释[27]、学习型随机停止防止外推发散等。Think Shallow, Solve Deep（Viakhirev 等）把循环算子分成"收敛型 / 边缘型 / 发散型"三类，给出"深度安全"判据，并证明终端不动点目标能带来稳定的测试时深度外推[37]。

7.4 2026：传闻、实证与"闭嘴思考"之争

2026 年最出圈的行业事件，是闭源实验室是否已经秘密采用循环深度：

  • Astra 传闻：The Information 报道 OpenAI 的新模型 Astra 用一种新技术"以某种方式掩盖部分或全部的推理过程（即所谓思维链）"[21]。Raschka 的技术分析认为这与循环深度高度吻合——思考发生在潜激活里，本就不产出可读文本；他同时给出冷静的技术注脚：递归深度文献里的收益（尤其 Nanbeige 的数据）需要放大解读，"75% 的 token 效率意味着同样质量需要多花约 33% 的训练 token"[21]。
  • Claude "Mythos" 猜测：Hayduk 的 X 长文从基准模式与服务算力约束出发，论证 Anthropic 的某些收益模式与"确定性权重共享循环"兼容，但作者明确标注这是推测而非证实[44]；Ouro 作者 Zhu 的后续分析也从"深度缩放轴"角度讨论了这类传闻的技术合理性[36]。
  • 公开实证：无论传闻真假，Nanbeige4.2-3B（开源权重、28T token 从零预训练的循环 Transformer）给出了第一个可以审计的工业证据：两次循环（two passes）是质量—效率的最佳折中，保留了约 75% 的 token 效率[21]——即用参数换来了数据效率的实打实损失，但换来了推理侧的自由度。
安全视角：循环推理把思考搬进了不可读的潜空间，监控思维链的既有安全方案失效——这正是 LessWrong 社区对 Astra 传闻的主要担忧（若属实）[22]。与之呼应，可解释性研究开始反向发力：从潜思维解码（Lu 等发现解码证据有限[26]）到读出反馈转向（steering readout feedback）、潜思维轨迹奖励等（第 11.3 节）。"想得深"与"看得见"的张力，会是这个范式长期的伴生问题。

8.2 三明治结构与循环本体（model_dynamic.py:962-1247）

代码 1 · 模型的骨架：三个部件各司其职，核心块被反复调用。为本科生注释版：

class RecurrentGPT(torch.nn.Module):
    def __init__(self, config, objective, ...):
        # ① prelude：进入锚层 —— 把 token 嵌入变成"值得思考的初始状态"
        prelude = ModuleList(config.Block(config, layer_id=i)
                             for i in range(config.n_layers_in_prelude))        # 默认 1 层
        # ② core_block：思考核 —— 唯一被循环的部分
        core_block = ModuleList(config.Block(config, layer_id=i + config.n_layers_in_prelude)
                                for i in range(config.n_layers_in_recurrent_block))  # 默认 4 层
        # ③ coda：读出锚层 —— 把深思后的状态翻译成下一个词的分布
        o = config.n_layers_in_prelude + config.n_layers_in_recurrent_block * config.mean_recurrence
        coda = ModuleList(config.Block(config, layer_id=i + o)
                          for i in range(config.n_layers_in_coda))             # 默认 1 层
        self.transformer = ModuleDict(dict(
            wte=Embedding(vocab, d), prelude=prelude, adapter=adapter,
            core_block=core_block, coda=coda, ln_f=Norm(d)))

注意 layer_id 的分配方式：prelude 用 0..n-1，core 接着编号，coda 的编号直接按"展开了 32 次"的虚拟深度计算——这暗示了整个实现的中心思想：把循环模型当作一个虚拟的 36 层网络来初始化和缩放，只是其中 32 组层共享同一份权重。

代码 2 · 循环本体与截断反传（iterate_forward，model_dynamic.py:1164-1197 简化）：

def iterate_forward(self, input_embeds, freqs_cis, mask, num_steps_pair=None):
    x = self.initialize_state(input_embeds)
    # 每个训练样本随机采样循环总次数 n 与"带梯度"的步数 k
    num_steps_no_grad, num_steps_with_grad = self.randomized_iteration_sampler()

    with torch.no_grad():                          # ← 前面 n 步：不建计算图
        for step in range(num_steps_no_grad):
            xk = x
            x = self.core_block_forward(xk, input_embeds, freqs_cis, mask, step)

    for step in range(num_steps_with_grad):        # ← 只对最后 k 步回传梯度
        xk = x
        x = self.core_block_forward(xk, input_embeds, freqs_cis, mask,
                                    num_steps_no_grad + step)
    return self.transformer.ln_f(x), num_steps_no_grad, num_steps_with_grad, xk.detach()

这就是 2.3 节"问题三"的工程答案：截断反传（truncated BPTT）。循环 32 次如果全程记梯度，激活内存是普通模型的 32 倍；Huginn 的做法是前 32−k 步纯前向（no_grad），只在最后 k 步（论文默认 k 很小）回传。副作用是梯度估计有偏——模型"看不到"自己前 28 步对最终结果的影响，因此必须配合下面的输入注入与逐步噪声来保证前段循环有意义。怎么让截断之后的训练信号依然对齐，是所有后续循环 LM 论文（Ouro、Parcae、SMELT）改进的主要战场之一。

代码 3 · 输入注入与噪声（core_block_forward，model_dynamic.py:1199-1247 简化）：

def core_block_forward(self, x, input_embeds, freqs_cis, mask, step):
    # ① 输入注入：每一轮都把"题面"重新加回思考状态 —— 防止忘题
    if self.config.injection_type == "add":
        x = x + input_embeds                        # ← 全部秘密就在这一行
    elif self.config.injection_type == "gate":
        x = x * input_embeds                        #   门控注入变体
    elif self.config.injection_type in ["linear", "ffn"]:
        x = self.transformer.adapter(cat([x, input_embeds], dim=-1))

    # ② 中间噪声注入：把部分维度替换为高斯噪声（多种衰减日程可选）
    if self.config.intermediate_noise_injection > 0:
        n = self.config.intermediate_noise_injection
        x = x * (1 - n / (step + 1)) + torch.randn_like(x) * n / (step + 1)

    # ③ 真正的"思考"：4 个共享权重的层
    for block in self.transformer.core_block:
        x = block(x, freqs_cis, mask)
    return x

两个细节值得咀嚼：

  • 为什么必须输入注入？数学上，x ← f(x) 的迭代只有一个输入（初始 x），信息每轮只会被压缩不会增加——循环几十轮后模型只剩"自己想法的回声"。加法注入 x + e 等于每轮重新校准到题面，让循环变成"在输入约束下的反复细化"而不是自由漂移。2026 年 Benhao Huang 的系列消融进一步发现，注入写回的精确形式（Euler 增益 vs 精确零阶保持）对稳定循环 LM 的验证损失有可测影响[36]。
  • 为什么要噪声？训练时把部分状态替换成噪声，模拟"循环早期信息不完整"的情形，强迫模型学会在脏状态下仍然稳定收敛——这是推理时能"任意加深 + 早停自适应"的隐含前提（状态要可预测地稳定下来，变化率才能当收敛信号用）。

这套双层索引支撑起三个把"加深"变便宜的特性：

跨轮复用
新 token 第 k 轮注意力需要的旧 token KV，若本轮缺失，可用上一轮同位置的 KV 近似（"latest-m4" 等策略）——论文发现质量损失很小，吞吐大增。
按 token 自适应深度
既然缓存放宽到"各位置轮次可不同"，自然允许简单 token 循环 2 次、难 token 循环 64 次共存于同一批次——这是 Huginn 零样本自适应算力的物质基础，也被 MoR 发展成显式学习路由[16]。

三个本科读者应该注意到的设计：

  • "思考"的物理载体就是隐藏状态：正常解码流程是 hidden → argmax/采样 → token → embedding → 下一位置，中间要经过离散词表的窄门；COCONUT 直接把 hidden 接回输入端，绕开词表——信息带宽从 log|V| 比特跳到整个向量。
  • KV 前缀复用让潜思维几乎免费：一个 latent 位置只新增一步前向的算力（而且这段还不产出可读 token），对比 CoT 每个 token 全模型一遍。
  • 循环的"次数"由 latent token 个数决定：这本质上是 2.2 节"深度外包给序列长度"与"深度内生循环"的杂交——思考发生在序列维度，但内容是连续的。后来的工作（如 DiscoLoop、RecurTrace）把两者进一步融合：既在序列里放潜 token，又对潜状态做循环精炼[36]；Fan 等则系统研究了如何在潜推理与显式推理之间架桥[42]。

10 · 为什么这么设计：一份收益与代价的完整账本

10.1 五大收益（为什么值得做）

收益机理代表证据
参数效率 深度（顺序计算步数）与参数解耦：1 组权重 × L 次循环 ⇒ 有效深度 ≈ L 层。同等"思考能力"下权重、显存、部署成本都小一号。 Yang 等：<10% 参数打平标准 Transformer[8]；MoEUT 参数匹配打平且 MACs 更少[9]；HRM 27M / TRM 7M 的极端案例[14][15]。
测试时算力的第三条轴 参数量、数据量之外，循环深度 L 成为推理时旋钮：同一权重，难题多循环、易题少循环；与"生成更多 token"的 CoT 缩放同构但不用付 token 成本。 Huginn 零样本加深持续涨点[12]；Saunshi 等证明 k 层×L 循环 ≈ kL 层[13]；Ouro 把它做成预训练内的学习量[17]。
免 CoT 数据 / 免后训练依赖 推理能力来自结构（循环）而非 RLVR 数据；预训练语料本身即训练信号——"把推理写进预训练"。 Huginn 不用任何 CoT 数据[12]；Ouro 7.7T token 原生循环预训练[17]；HRM 1000 样本[14]。
超越语言模态的思考带宽 隐藏状态是数千维连续向量，可叠加多假设（BFS 式搜索）、可表达无词可依的过程（密码学、空间、连续控制）。 COCONUT 的 BFS 证据与更高准确率—效率前沿[11]；Huginn："不易用语言表示的推理类型"[12]；潜思维与答案对齐度高于显式 CoT[17]。
自适应算力 + 缓存友好 循环状态变化率可当收敛信号（早停）；KV 可跨轮复用、按 token 分深度；与 MoE/早退等既有效率技术正交可叠加。 Huginn 的 KV lookup 策略与零样本自适应[12]；MoR 的 token 级深度路由[16]；PLT 的 KV 共享零开销循环[18]。

10.2 代价与争议（为什么还没有一统天下）

代价一：不可读、难监督
思考在潜空间，人类与监控管线都看不见。CoT 监督、过程奖励、思维链审计全部失效；解码潜思维的初步尝试证据有限[26]。安全社区已把"潜推理 + 不可审计"列为结构性行为风险[22]。
代价二：循环退化与外推失败
朴素循环模型常在训练循环数之外退化。LessWrong 引述的复现工作（Fu 等, 2026）报告 318M 的朴素循环 Transformer 在 3–6 次循环后性能开始退化、9 次时崩溃[22]；深度安全判据与稳定化训练成为 2026 年的显学[23][27][37]。
代价三：串行延迟（原生形态）
循环在深度维天然串行。并行采样器[19]与 PLT[18]已给出 5×/近似零开销的方案，但都引入近似（KV 复用、跨轮并行）或调度复杂度；连续深度批调度仍在成熟中[36]。
代价四：token 效率损失
权重共享不是免费的：Nanbeige 的公开数据显示两次循环保留约 75% token 效率——同等质量需要约 1/3 更多训练 token[21]。等深度缩放定律正在量化这笔"参数换数据"的汇率[24]。
代价五：容量天花板
所有循环步共享权重 ⇒ 单步多样性受限，"查表型"知识任务吃亏（Saunshi 的推理/记忆二分[13]）。MoE 化（MoEUT / LoopMoE / SMELT）是当前主解[9][31][32]。
争议：评测口径
"3.5B 顶 50B"式的对比常混用"参数等价"与"算力等价"；压缩循环模型与全序列状态模型的记忆预算并不在一个 regime（Zhang 的分离定理）[34]。读这个领域的 benchmark 数字，务必先看"比的是参数还是 FLOPs"。
"…compressed looped Transformers remain bounded by their persistent recurrent-state budget even with more loop steps, while full sequence-state loops occupy a memory-richer regime closer to chain-of-thought scratchpads." ……压缩态的循环 Transformer 即使增加循环步数，仍受其持久循环状态预算的约束；而全序列状态的循环则处于更接近思维链草稿纸的、记忆更丰富的区间。 — Haozhou Zhang,《Chain-of-Thought and Compressed Looped Transformers: A Memory-Budget Separation》, arXiv:2605.30757, 2026-05-29 [34]

12 · 未来发展方向

综合论文脉络与 2026 年的动态，六个方向最值得关注（★ = 未来 1–2 年最可能出成果）。

方向一 ★：循环缩放定律的最终形态——"第三轴"的确立

参数、数据之后，循环深度能否构成一条平滑、可预测、可跨尺寸迁移的缩放轴？Parcae 的 isoFLOPs 曲面、等深度定律、SMELT 的 MoE×循环计算匹配定律已经拼出草图[23][24][32]，但关键空白仍在：最优循环数与模型尺寸/数据量的联合定标、循环外推的失效边界预测（何时该加参数而不是加循环）、多轮循环的信息瓶颈理论（压缩态 vs 全序列态的内存分离已给出第一定理[34]）。谁先给出"Chinchilla for Loops"，谁就定义下一代模型的训练预算表。

方向二 ★：训练算法——绕开截断反传

截断反传是有偏梯度 + 前段循环"无监督漂移"的妥协。候选出路：① 隐式微分 / 平衡解（DEQ 现代化：把循环训练重写成不动点求解，一次反传[3][35]）；② 逐步自举（把第 k 步输出当第 k+1 步的伪标签，教师强制的自监督版）；③ RL 到迭代（LoopRPT 与潜轨迹奖励已开头[29]——把"每轮循环"当作动作，奖励信号直接对齐推理质量）；④ 可并行的时间维展开（把 32 次循环摊到 32 个序列位置并行算——与 COCONUT 式潜 token 的杂交，DiscoLoop 等已试水[36]）。

方向三 ★：系统与硬件协同——让循环免费

2026 年的趋势已经明确：循环的全部理论收益，最终要以"零额外延迟、零额外显存"交付。路线图：跨循环并行（PLT）+ 并行采样（扩散强制）→ 连续深度批调度 → KV 跨轮压缩（MELT / Looped Latent Attention）→ 专用内核与编译器支持（循环友好的 CUDA graph / paged cache 变体）→ 与投机解码的合流（LoopMTP：循环深度生产多 token 草稿[36]）。更远处是硬件侧：循环模型的算术强度（小权重、高复用）天然适配存算一体与片上大 SRAM——这是一个"架构定义芯片"的候选场景。

方向四：可解释与对齐——看见潜思维

如果思考不可读，过程监督、安全审计、法规合规都会变成硬约束。研究前沿：潜思维的可解码性（目前证据有限[26]）、读出转向（用读出头反馈操控循环动力系统）、潜轨迹奖励（奖励可解释的中间状态而非只看结果）、探针实时监控（对循环状态做在线安全分类）。Astra 争议的本质是：范式收益与可审计性存在结构性交换，这个交换率本身值得作为一个科学问题来研究[21][22]。

方向五：与生成式范式深度融合

循环结构与扩散语言模型、世界模型的合流是 2026 年最新鲜的方向：Thinking with Looped Flows 把循环去噪器耦合进概率流积分[35]；Looped Diffusion LM 把"去噪步"与"循环步"统一；Looped World Models 把循环深度引入交互式环境模型。统一视角呼之欲出：迭代精炼（refine）本身就是一种通用计算原语——去噪、思考、规划、控制都在"反复把状态变得更好"，循环 Transformer 给了这个原语一个可学习的载体。

方向六：神经科学的回环

HRM 的双时间尺度直接对标前额叶-基底节的快慢回路[14]；DEQ 与预测编码假说同构；ACT 的"思考时长"与心理物理学反应时数据可对照。反向的启发刚刚开始：大脑用 ~20W 实现"深度思考"，靠的正是循环回路而非更厚的皮层——循环网络的动力学分析工具（吸引子、分形盆、临界性[35]）可能成为计算神经科学与 AI 的共同语言。

给入门者的路线图：① 先跑通第 2.4 节的 40 行 LoopLM；② 读 Huginn 论文 + 对照第 8 节代码；③ 读 COCONUT 论文 + 第 9 节代码；④ 按Awesome-Loop-Models[36] 的 "Theoretical and Mechanical Analysis" 分支跟进理论；⑤ 想做系统就从 PLT / MELT 的开源实现入手。这个领域 2023 年才真正起步，本科背景完全来得及在 frontier 上找到自己的位置。
