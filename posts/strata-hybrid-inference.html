0导读与大事记：混合推理是什么、为什么现在

这份报告回答四个问题：Strata 是什么、它凭什么把 125B 参数的模型塞进 12 GB 显卡、实测到底多快、以及它和 llama.cpp / KTransformers 这些既有方案怎么选。全文沿一条主线展开——混合推理 = 字节账本（每个 token 读谁、读多少） × 三级存储（VRAM / RAM / SSD 各放什么） × 三方并发（GPU / CPU / DMA 复制引擎同时干活） × 猜了再验（MTP 投机解码摊薄权重读取）。前两项决定"放得下"，后两项决定"跑得快"。

为什么是现在？三个变化叠加：（1）模型结构变了——Qwen3.8-Flash-Next 这代"为推理设计"的 MoE，每 token 只碰 2% 的专家权重、注意力部分自带稀疏与线性混合，卸载的收益第一次大到值得写一个专用引擎[QWEN38NEXT26]；（2）学术积木齐了——从专家缓存（Eliseev & Mazur，2023-12）、CPU 算专家（Fiddler，2024-02）、预门控（ISCA 2024）到 AMX 内核与专家延迟（KTransformers，SOSP 2025），论文们把每块积木都验证过[ELISEEV23][FIDDLER25][PREGATED24][KTRANS25]；（3）通用引擎开始吸收——llama.cpp v0.8.0（2026-10-28）把 MoE 专家 GPU 缓存做成了正式参数 --moe-cache-mib[LLAMACPP80]，"特化 vs 通用"的窗口期正在关闭，这恰好是审视 Strata 的最好时点。

On the Design of Qwen3.8-Next Architecture: Evaluation, Efficiency, and Training Stability. arXiv, 2026-08-31（模型 2026-08-26 发布）。要点：125B 总参数 / 每 token 激活 6B；另有 51B 参数 n-gram 嵌入表与 4B 参数 MTP 模块；48 层 = 36 层 Gated DeltaNet + 12 层 Qwen 稀疏注意力（QSA，1M 上下文时内核级比稠密注意力 prefill 快 7.6×、decode 快 4.9×）；每层 512 专家取 10 + 1 共享专家；原生上下文 262,144。链接：arXiv:2608.30320

1预备知识：把一台 PC 当成三级仓库

写给第一次接触推理系统的读者：本节只需要"矩阵乘"和"内存比磁盘快"两个常识。先建立四个概念——MoE、三级存储、量化、投机解码——后面所有章节都在组合它们。

1.1 MoE：每个 token 只见 2% 的专家

普通 Transformer 的每一层是一个完整的"前馈网络"（FFN），任何 token 都要读它的全部权重。MoE（Mixture of Experts，混合专家）把这一层换成一个路由器（router）加几百个并列的小 FFN（专家）：token 到来时路由器打分，只挑分数最高的几个专家来算它。Qwen3.8-Flash-Next 每层有 512 个专家、每 token 激活 10 个再加 1 个共享专家——也就是说，每个 token 只需要读约 2% 的专家权重[QWEN38NEXT26]。

把模型想成一家大医院：MoE 的路由器是分诊台，病人（token）来了先分诊，只挂 10 个科室的号，而不是让全院 512 个科室都为他上班。医院养得起 512 个科室（参数多、能力强），但每个病人实际只惊动 2% 的医生——这就是"125B 总参、6B 激活"的含义。

这个"2%"是整个混合推理流派的前提：如果一个 token 要读全部权重，卸载就没有意义；正因为只读 2%，我们才有资格谈"把热的那部分放进显存"。

1.2 三级存储：速度差 100 倍的三层货架

一台普通 PC 有三块存模型的地方，速度和容量天差地别（以 Strata 论文的测试机 RTX 5070 + 64 GB DDR5 为例，带宽为实测）[STRATAPAPER26]：

层级典型容量实测带宽类比
VRAM（显卡显存）8–24 GB~672 GB/s灶台：随手可及，但台面很小
系统内存 RAM32–128 GB~41–52 GB/s（DDR5-5200）冰箱：大得多，取一趟慢一个量级
NVMe SSD1–4 TB~3.6–7 GB/s仓库：几乎无限大，但要提前订货

关键推论：66 GB 的模型文件放进 12 GB 显卡是不可能的，但 RAM（几十 GB）与 SSD（几 TB）都在等着被利用。问题变成"每一层权重放哪、谁来读"。另外还有一条隐藏通道——PCIe 总线（~26 GB/s）：GPU 可以自己通过它直接读 RAM，不必经过 CPU——Strata 把它当"第三个工人"用，后文详述。

1.3 量化：66 GB 的模型从哪来

BF16 下每个权重 2 字节，125B 骨干参数约 250 GB；Q2_0 包把骨干压到约 2.25 比特/权重（≈34 GB 专家 + 3.5 GB 稠密部分），加上单独格式的 28.8 GB n-gram 查表，全文件 66 GB。Strata 用的量化包由 ISTA-DASLab 以 GSQ-RCO 方案发布：最常用的是 Q2_0（网格 {-1,0,1,2}×缩放，整数指令友好）、IQ2_XS / IQ3_XXS（llama.cpp 的 i-quants：每 8 个权重共享一个"格点码本"索引，精度更好但解码要查表）[STRATAPAPER26]。直觉：Q2_0 是"每个数四舍五入到 -1/0/1/2 再乘个比例"，i-quants 是"8 个数一组，用最像它的一组标准答案代替"——前者 CPU 算得飞快，后者更准但算得慢，这个差异会直接体现在第 4 节的速度表里。

1.4 投机解码：一次搬运，多写几个字

自回归解码每步只产 1 个 token，却要把常驻权重全部读一遍——极端浪费。投机解码的解法：让一个便宜的手段（小模型或模型自带的 MTP 头）先"猜"接下来 γ 个 token，大模型把它们当成一个 batch 一次并行验证，接受猜对的、修正第一个猜错的。Leviathan 等证明了这样做输出分布与逐 token 解码完全一致（无损），且每轮期望产出 E = (1−α^(γ+1))/(1−α) 个 token（α 为单 token 接受率）[LEVIATHAN23]。Qwen3.8-Flash-Next 官方就带一个 4B 参数的 MTP（多 token 预测）模块，四步投机平均接受长度约 4.06[QWEN38NEXT26][MTP24]——Strata 直接把它当"免费的草稿模型"用。

[LEVIATHAN23] Leviathan, Kalman, Matias. Fast Inference from Transformers via Speculative Decoding. ICML 2023（arXiv 2022-11-22）。原文："a decoding strategy … that generates … several tokens in each step … with the same output distribution as decoding with the target model itself"（译文：每步产出多个 token，且输出分布与用目标模型本身解码完全相同）；T5-XXL 配小草稿在 TPU-v4 上 2–3×。链接：arXiv:2211.17192
本章小结（记住三句话）
  1. MoE 每 token 只读 2% 专家权重——"读不完"从致命伤变成可调度的局部性问题。
  2. VRAM/RAM/SSD 带宽差两个数量级，PCIe 是第四条通道——混合推理本质是给字节选路。
  3. 投机解码把"读一遍权重"摊到多个 token 上——权重读取是 decode 的主要成本，而它几乎不随 batch 变大而变贵。

2目标模型：Qwen3.8-Flash-Next 为什么"家用机友好"

Strata 的第一篇文章叫 Running a 125-Billion-Parameter Model on a Normal PC（2026-09）。要理解引擎，先看它伺候的模型长什么样。Qwen3.8-Flash-Next 的设计者明确按"每 token 搬运字节数"给每个结构定价[STRATAPAPER26][QWEN38NEXT26]：

  • 48 层 = 36 层 Gated DeltaNet + 12 层稀疏注意力。GDN 是线性注意力家族：它的"记忆"是一个固定大小的递归状态，不随上下文增长——长上下文下既省显存又省读写；12 层 QSA 只保留 2 个 KV 头、只注意至多约 2048 个被索引器选中的位置，上下文再长注意力成本也有界[QWEN38NEXT26][GDN24]。
  • 每层 512 个专家取 10 + 1 共享：24,576 个路由专家，2% 激活率。
  • 51B 参数的 n-gram 嵌入表：由最后 3 个 token 的 id 直接寻址——地址提前已知，所以可以放 SSD、提前一步预取，每 token 只读约 23 KB。
  • 4B 参数 MTP 模块：官方投机解码头，权重不在 GGUF 里（Strata 从 BF16 原始检查点单独拉取其张量）。
[GDN24] Yang, Kautz, Hatamizadeh. Gated Delta Networks: Improving Mamba2 with Delta Rule. ICLR 2025（arXiv 2024-12）。要点：把 Mamba2 的门控衰减与 DeltaNet 的 delta 规则统一为 S_t = α_t(I − β_t k_t k_tᵀ)S_{t−1} + β_t v_t k_tᵀ，状态固定大小、可并行训练——即 Qwen3.8-Flash-Next 中 GDN 层的直接来源（一作工作完成于 NVIDIA 实习期间）。链接：arXiv:2412.06464

本章小结（记住三句话）
  1. "为推理设计"的结构（GDN 固定状态、QSA 有界注意力、2% 专家激活、确定性寻址的 n-gram 表）让每个部件都能找到最便宜的存放层级。

  3. MTP 模块是官方送的草稿器——模型设计者已经把投机解码的接口预留好了，引擎只差把它用起来。

3Strata 原理拆解：三级存储 × 三方并发 × 猜了再验

图 3-1 一层的执行（据论文 Figure 2 重绘）。一层 @4K 约 0.6 ms；整层循环打包成每个窗口尺寸一张 CUDA Graph，主机线程自旋等待"门铃"而非同步驱动调用。

四个工程细节决定了这套流水能否真的并发：

  • 门铃（doorbell）：GPU 跑完路由器后把专家 id 写进一小块锁页（pinned）主机内存；CPU 线程自旋盯这块内存，而不是调用 CUDA 同步 API——省掉每次微秒级的驱动往返，这是 batch=1 小内核流水线的命门（论文引用 NVIDIA CUDA Programming Guide 的 mapped pinned memory 与 CUDA Graphs 机制；引擎侧对应 src/core/graph.cpp 的捕获图注册表）。
  • 复制引擎分工（--pcie-frac）：缺失专家的一部分不用 CPU 算，直接由 GPU 的 copy engine 经 PCIe 从 RAM 拉过来算。比例是调出来的：i-quants 文件 CPU 算力是瓶颈、内存带宽有富余，55% 的缺失走 PCIe（IQ2_XS @4K 从 70 → 78 tok/s，IQ3_XXS 56 → 65）；Q2_0 的 CPU 自己就在吃满 RAM 带宽，只留 20%[STRATAPAPER26]。
  • CPU 结果回收：CPU 把专家输出写进 GPU 可映射的内存，GPU 在自己的流上取走求和——两边全程不同步握手。
  • 整层循环一张图：48 层每层的"稠密 + 三方专家"被捕获成按窗口大小分桶的 CUDA Graph，消除逐 kernel 启动开销。
像一家小餐馆只有一个灶台（GPU）、一个帮厨（CPU）和一个传菜员（DMA 复制引擎）：灶台炒所有菜都要用的底料（稠密权重）和冰柜里常备的菜（缓存专家）；帮厨在库房（RAM）就地处理冷门菜；传菜员把一部分冷门菜直接搬进后厨。三路同时进行，一层等的是最慢的那一路——所以 Strata 说自己的引擎是"平衡的"：GPU 等 CPU 约 13 ms、CPU 等 GPU 约 14 ms，谁也闲不下来。

3.2 自适应专家缓存：从 50% 到 72% 命中率

VRAM 里塞进 ~4,500 个专家（12 GB 卡），命中率多少？Strata 出厂带一份"按别人的提示词统计的专家热度档案"（profile）预填缓存；运行中每 4 个验证窗口换入至多 96 个本会话反复路由到的专家、换出最冷的，换入动作藏在 GPU 起草草稿的时间里异步完成。实测（held-out 提示词）：静态 profile 填充在 4,500 槽位时命中率约 0.50，自适应换入后升到 0.72[STRATAPAPER26]。经验法则：每多 1 GB VRAM 约多放 700 个专家，每个进 VRAM 的专家都是 CPU 不用算的。

这条路是学术谱系的集大成：LRU 专家缓存源自 Eliseev & Mazur[ELISEEV23]；按"请求级激活矩阵"预测的缓存是 MoE-Infinity[MOEINF24]；热专家常驻的思想与 PowerInfer 的幂律神经元一脉相承[POWERINFER24]。Strata 的增量在于档案预填 + 会话内换页 + 字节级槽位（不同层的专家大小差近 2 倍，按层定槽而不是按最大专家定槽，多塞下 3,556 而不是 2,673 个，1K 解码 +13%）。顺带一提，llama.cpp v0.8.0 的 --moe-cache-mib（SLRU 策略）说明"专家缓存进 VRAM"正在变成通用引擎的标配[LLAMACPP80]。

[MOEINF24] Xue, Fu, Lu, Sun, Mai, Marina. MoE-Infinity: Efficient MoE Inference on Personal Machines with Sparsity-Aware Expert Cache. ASPLOS 2024（arXiv 2024-01-25）。要点：单请求解码时专家激活高度稀疏、跨请求趋于均匀，LRU/纯计数都会失效；在线追踪"专家激活矩阵"，用最相似历史请求预测未来激活。单张 A5000 24 GB 上 DeepSeek-V2-Lite 每 token 延迟 155 ms（vLLM 485 / DeepSpeed 737 / Ollama 2590）。链接：arXiv:2401.14361

3.3 Prefill：2,048-token 大块与 PCIe 预取

读 prompt 与解码的资源画像相反：一次 2,048 个 token 进来，每个专家都会被用很多次，此时正确的做法是"把专家搬到 GPU 算"而不是"在 CPU 算"。Strata 按层流水：上一层的专家在 GPU 计算时，下一层缺失的专家正从 pinned 内存经 PCIe 流入，落到 GPU 后反量化成 FP16 交给 cuBLAS——缓冲区从专家缓存借、用完归还。结果是 prompt 速度几乎不随长度衰减：4K 时 539 tok/s，262K 全上下文仍有 496 tok/s（Q2_0）——因为 QSA 每层只注意有界的位置集合[STRATAPAPER26]。这解释了第 1 节的伏笔：稀疏注意力让"长文档"从算力灾难变成纯容量问题。

3.4 投机解码：模型自己的 MTP 层 + 上下文查表

权重读取不随 batch 变贵——这是投机的物理依据：一次验证 4 个 token，稠密权重只读一遍。Strata 的做法[STRATAPAPER26]：

  • GGUF 不带 MTP？自己拉。从 BF16 原始检查点取 MTP 层张量（5 GB，其专家以 2-bit 形式、输出头裁到 40,525 个常用 token）常驻 VRAM。
  • 每轮：最后接受的 token + 至多 3 个草稿一起过全部 48 层；草稿只有在 MTP 层置信度 ≥50% 时才进窗口（--spec-min-p）。平均每窗口产出 2.4–3.2 个 token。
  • 严格无损：输出与逐 token 贪婪解码逐 token 一致（用故意错误的草稿与回滚测试验证）；与 llama.cpp 相比下一 token 分布的 KL 散度 0.022，还低于 llama.cpp 自己 CPU 与 GPU 构建之间的 0.058。
  • 提示查表（prompt lookup）：当回答复述上下文（改代码、引文）时，从上下文里直接"抄"至多 5 个 token 当草稿——代码题再快 6–11%，其他文本不受影响。
[STRATAPAPER26] Strata Team. Running a 125-Billion-Parameter Model on a Normal PC. 2026-09（仓库内 docs/paper/Strata-Paper.pdf）。原文："Speculation with the model's own MTP layer is worth 1.6–1.8×. Plain decoding reached 47–57 tokens per second at 4K; with the verify window it is 82–92. … The speculative output is identical to plain greedy decoding token for token"（译文：用模型自带 MTP 层投机价值 1.6–1.8 倍；无投机 4K 下 47–57 tok/s，验证窗口后 82–92；投机输出与纯贪婪解码逐 token 完全一致）。链接：仓库 PDF

为什么只有 1.6–1.8× 而不是全 VRAM 引擎常见的 2.5–3×？验证窗口里每个额外 token 都会路由到自己的 CPU 专家——窗口越长，CPU 那一半越重。这是混合架构下投机解码的独有代价，论文如实算了这笔账[STRATAPAPER26]。

3.5 CPU 内核：Q2_0 重排 + AVX-512 VNNI 到达内存带宽

CPU 侧就一句话：让 6 个核把 DDR5 的带宽吃干。Q2_0 可以无损重排成 512-bit 组，一条 unpack + 一条 VNNI 整数点积处理 64 个权重——实测流过 ~42 GB/s，与"GPU 同时也在读"时的内存可用带宽（41 GB/s）持平，等于说 CPU 侧已到物理上限[STRATAPAPER26]。i-quants 做不到这种重排：码本解码要查表和符号处理，每核只有 ~5 GB/s，6 核 ~25 GB/s——i-quants 慢不是因为文件大 25%，而是因为 CPU 算力先到顶。这就是 T-MAC 查表内核（EuroSys 2025）被论文列为后续方向的原因[TMAC25]；ggml 的 CPU 后端在 x86 上甚至没有 Q2_0 的 SIMD 内核（IQ 文件的 Q2_0 下投影需要一个自写内核，比标量快 7×）。

[TMAC25] Wei, Cao, Cao, Ma, Wang, Zhang, Yang. T-MAC: CPU Renaissance via Table Lookup for Low-Bit LLM Deployment on Edge. EuroSys 2025（arXiv 2024-07-01）。原文要点：把低位权重×高位激活的 mpGEMM 改为按位查表 + 加法、彻底消除乘法，计算量随位宽线性缩减；集成进 llama.cpp 后端到端吞吐最高 4×、能耗降 60–70%，树莓派 5 上跑 BitNet 1.58bit 3B 仍有 11 tok/s。链接：arXiv:2407.00088

3.6 KV 与会话：8-bit KV、流式 KV、会话缓存

长上下文的代价主要在 VRAM 容量而非算力：262K 上下文时 12 个稀疏注意力层的 KV（8-bit）、索引键与更大的 prompt 缓冲约占 4 GB，自动配额把专家挤到 ~1,600 个（4K 时约 4,500）——Q2_0 解码从 ~95 掉到 ~56 tok/s[STRATAPAPER26]。对策是一组可组合的开关：--kv q4_0/k8v4（Hadamard 旋转后 4-bit KV）、--kv-streaming（64K 起把 KV 放 RAM、VRAM 只留注意力常读的 32K 窗口）、--kv-grow（KV 按需长、专家缓存让位）[STRATADETAILS]。更重要的是会话缓存与检查点：第一轮之后只读新增 token、跨请求保存递归状态与 KV——论文把"会话状态复用"列为最大单项改进，0.2.x 已经把它做进产品（详见第 6 节）。

本章小结（记住三句话）
  1. 一层之内三方并发：GPU 算稠密+缓存专家、DMA 拉 PCIe 份额、CPU 就地算剩余——门铃 + CUDA Graph 让三者真正并行。
  2. 专家缓存 = 档案预填（冷启动）+ 会话自适应（0.50→0.72）+ 字节级槽位——缓存派学术成果的工程完全体。
  3. 投机解码 1.6–1.8× 且严格无损，但混合架构下验证窗口会放大 CPU 负载——免费的加速也有物理代价。

5.1 逐对点评：Strata 与三个最相关的对手

vs llama.cpp（通用 vs 特化的正面战场）。llama.cpp 的 -ot "exps=CPU" + --moe-cache-mib 组合与 Strata 的机制骨架已高度同构：专家留内存、热专家进 VRAM。差别在完成度与假设：Strata 的并发流水（门铃 + 三方并发 + 层级 PCIe 预取 + Q2_0 重排内核）是围绕一个模型的形状手写的，且配齐了档案预填、字节级槽位、会话缓存、8-bit KV 流式这些"最后一公里"；llama.cpp 胜在一切模型、一切后端、一切精度，以及多年积累的生态。公平地说：为三个模型家族维护一个 20 万行引擎是重投入，Strata 用 MIT + 55 位外部贡献者的合入速度对冲；而 llama.cpp 每个版本都在吸收同类机制（SLRU 专家缓存、DFlash2 草稿）——这条差距曲线的斜率，比两条曲线的位置更值得关注。

vs KTransformers（学术谱系的两个端点）。两者同属"CPU 算专家"流派，但取向不同：KTransformers 服务"本地跑 671B DeepSeek"的研究与极客场景，敢用专家延迟（跳过部分专家、与下层重叠，精度 -0.5%）换 1.45×；Strata 坚持严格无损（拒绝任何近似，唯一例外见 6.2 的 residency 路由）并面向"下载即用"的普通用户。内核上 KTransformers 押 Intel AMX（21.3 TFLOPS/路），Strata 押 AVX-512 VNNI + 内存带宽——前者吃 CPU 算力、后者吃内存通道，其实各押了一种未来桌面[KTRANS25][STRATAPAPER26]。

vs Splash/ninfer/HyperQwen（单模型流派内部）。Splash 统一内存一把梭（Apple 专属、无需卸载），HyperQwen 站在 vLLM 肩膀上（重量化 + 服务器生态，但要求模型基本塞进 VRAM），ninfer 与 Strata 最像（自写引擎、选定模型×选定卡）。Strata 的差异化是跨平台（CUDA/HIP/SYCL/Metal + Windows/Linux/macOS）+ CPU-GPU 混合 + 免费模型自带文档化论文——在"没有 Mac、显存 12 GB、想跑最大模型"这个格子里，它目前没有直接对手。

[KTRANS25] Chen, Xie, Zhang, Tang, …, Wu, Zhang. KTransformers: Unleashing the Full Potential of CPU/GPU Hybrid Inference for MoE Models. SOSP 2025（2025-10，DOI 10.1145/3731569.3764843；无 arXiv 版）。原文要点：Fiddler 式方案在 A100+双路 Xeon 上 prefill 70.02 / decode 4.68 tok/s、GPU 利用率 <30%；三项改进——AMX 专用内核单路 CPU 达 21.3 TFLOPS（PyTorch/oneDNN 的 3.98×）、整个动态形状 decode 塞进单个 CUDA Graph、专家延迟（Expert Deferral）将 CPU/GPU 利用率提至 ~100%/37%；总体 prefill 4.62–19.74×、decode 1.25–4.09×。链接：kvcache-ai/ktransformers

5.2 选型速查

你的场景推荐理由
Mac 统一内存 36 GB+，跑 Qwen3.8Splash（或 LM Studio 里选它）统一内存无需卸载，Apple 专属优化
12–16 GB N 卡 + 64 GB 内存，就想跑 Qwen3.8-Flash-NextStrata这个格子里的唯一专门解；下载即用
什么模型都想跑（含老模型、多模态杂项）llama.cpp / Ollama / LM Studio通用性 > 单点速度
本地跑 671B DeepSeek、愿意调参KTransformers / ik_llama.cpp大内存 + CPU 算力路线的成熟实现
24 GB 卡跑 27B 级 + 要服务器并发HyperQwen / vLLM模型基本进显存时服务器生态更强
本章小结（记住三句话）
  1. 混合推理的机制（专家缓存、CPU 专家、PCIe 分流）正在从论文下沉为通用引擎的正式参数——特化引擎的护城河是"为形状手写的并发流水"，不是单点机制。
  2. Strata 的生态位：非 Mac、小显存、大内存、锁定 Qwen/DeepSeek 三家族——这个格子暂无对手；代价是每支持一个新模型都要重写引擎假设。
  3. 大厂（NVIDIA TensorRT-LLM、字节 FlashInfer、腾讯 Hunyuan 部署栈）的主战场在数据中心；消费级混合推理至今是社区与高校的领地——清华、上交、爱丁堡、华盛顿大学的论文构成了它的全部谱系。

6工程深处：论文没写、但代码里有的东西

读仓库文档（docs/ 目录 80+ 篇）能挖出比论文更"真"的工程。挑四件：

6.1 会话状态复用：论文的"未来工作"已经落地

论文 §7 把"跨请求保存会话状态"列为最大的单项改进（原文："Saving the recurrent state at the end of each turn … would turn a 30-second re-read of a long chat into a fraction of a second. For agents this is the largest single improvement available."——把每轮结束时的递归状态存下来，长对话的 30 秒重读会变成不到一秒；对 Agent 这是最大的单项改进）。0.2.x 的引擎已经带上了有界会话缓存 + 周期检查点 + 消息边界检查点（STRATA_CACHE_MESSAGE_BOUNDARY=1：编辑上一条用户消息时从轮次边界恢复，避免重读 8K+ 的历史）[STRATAMBC]。服务器还会报告每个请求的"复用后真实 prompt 速度"（新 token 数 ÷ 时间）[STRATADETAILS]。

6.2 residency 路由：第一次引入"有损"开关的谨慎

0.2.7 给 ≤13 GB 的 N 卡默认开启"路由器偏向已在卡上的专家"：RTX 3060 上故事题 +15%、代码题 +37%。但它会换一组稍有不同的专家、答案措辞会变——项目用 80 项任务检查无错误，并如实公布了 Agent 任务通过率的波动（开 4.5/10、关 5.6/10，且关闭组自身 4–6 波动）；更强的档位（2.0）出了抄写与代码缺陷，于是默认回撤到 1.5[STRATARN27]。这是"严格无损"立场第一次受工程压力，处理方式（默认保守 + 数据全公开）值得学习。

6.3 Windows 的锁页内存：平台差异是真实存在的工程

把 34–43 GB 一次性 page-lock 在 Windows 上会失败：引擎按层分段锁 + 余量用 working-set 锁，且 PCIe 读不允许跨段；大页需要 SeLockMemoryPrivilege 且重新登录才生效；任务计划程序默认优先级会把 40 GB 专家加载从 35 秒拖到 821–841 秒（实测表在 DETAILS.md）[STRATADETAILS]。这些细节没有任何论文会写，却是"普通 PC"承诺的一部分。

6.4 弹性显存与"被反超"的实验

--vram-elastic 把专家缓存切成 512 MB 段，运行中可通过 API 让给别的程序、之后收回（收不回的部分由 CPU 顶着，回答变慢但不断服务）[STRATADETAILS]。另一个值得记录的负结果：split-serve（一张卡 prefill、另一张卡 decode）在两张同类卡上全程慢于普通层切分（8K prompt +16%、32K +48%）——文档保留了这个结论而不是删掉它。

本章小结（记住三句话）
  1. 会话缓存/检查点已从论文未来工作变成产品特性——Agent 多轮场景的最大收益已经兑现。
  2. 项目对"有损加速"的处理是教科书级的：默认保守、逐档实测、公开不利数字。
  3. 平台工程（Windows 锁页、大页、调度器优先级）占了真实工作量的大头——"能跑"与"好用"之间隔着几十篇文档。

7动手：五分钟跑起来

以终端路线为例（Windows PowerShell；Linux/macOS 见 README）。装好后先看计划再动手，--plan 不改任何东西：

# 1. 安装终端（免管理员）
irm https://github.com/Niko1221/Strata/releases/latest/download/install.ps1 | iex

# 2. 看看会发生什么（不动系统）
strata launch --plan --family qwen --model q2_0

# 3. 正式设置并起服务（下载引擎 + 模型数十 GB，随后常驻 127.0.0.1）
strata launch --family qwen --model q2_0 --yes --no-tui

# 4. 拿 OpenAI 兼容 API 直接用（任意 API key 即可）
curl http://127.0.0.1:8080/v1/chat/completions -H "Content-Type: application/json" -d '{"model":"strata","messages":[{"role":"user","content":"写一首关于 GPU 的俳句"}],"max_tokens":512}'
代码 7-1 最小上手路径（AGENTS.md / TERMINAL.md 摘录）。常用旗标：--context 32k|64k|128k、--vision off|on|gpu|cpu、--parallel N、--gpu 0,1、--speed faster|full（DeepSeek）；strata launch --status/--stop/--show-key 管理服务。

它同时说 Anthropic 协议（/v1/messages）与 OpenAI Responses API（/v1/responses），工具调用含流式参数、视觉输入、MCP 客户端/服务器——Claude Code、Cline 这类工具可以直接把 base URL 指过来（strata connect 能自动配置常见应用并发一条测试请求验证）。想读源码的，入口三处：src/core/（会话/缓存/验证/专家源，含 expert_cache.cpp、graph.cpp、mtp.cpp）、src/prefill/ 与 src/kernels/（占 164 个内核文件的大头）、serve/server.py（API 层）；每个模块带同名 *_test.cpp。

8未来方向

  • 下一层专家预测：用当前层隐藏态预测下一层专家、提前发起 PCIe 拷贝——Pre-gated MoE（ISCA 2024）与 Speculating Experts（2026-03）已验证方向[PREGATED24][SPECEXPERT26]，Strata 论文把"扩大复制引擎份额"押在这里。llama.cpp 侧的 ngram 缓存持久化（v0.8.0）是同一方向的通用化[LLAMACPP80]。
  • 查表 CPU 内核：T-MAC 式 LUT 内核或加载时把热专家转成 CPU 友好格式，把 i-quants 的速度拉向 Q2_0——对"要精度也要速度"的用户是最后一块短板[TMAC25]。
  • 融合 8-bit 分组 prefill 内核：prompt 路径瓶颈在逐专家 kernel 启动与 FP16 反量化（只用了 26 GB/s PCIe 中的 7 GB/s），Marlin 式混合精度内核是现成参照[MARLIN25]。
  • 采样：目前只支持贪婪解码，温度采样需要在验证窗口里加拒绝采样——投机解码的标准配法[LEVIATHAN23]。
  • 硬件走向：统一内存桌面（Strix Halo、M4 系）在消解"PCIe 分流"这道题本身；若下一代消费卡标配 32 GB+，单模型引擎的生存空间会向"更大的 MoE + SSD 三级"迁移——Strata 的 DeepSeek 引擎（Project Maya 系）已经是这条路的前哨。
  • 通用引擎的追赶：llama.cpp 已把专家缓存做成一等参数、Jan 做进了 UI——预测：12 个月内"专家缓存 + CPU-moe"会成为所有本地引擎的默认行为，届时单模型引擎必须靠"会话智能 + 模型特化流水"维持代差。
