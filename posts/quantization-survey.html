1为什么需要量化：一张账单讲清楚

大模型的一切部署成本，几乎都可以换算成两个字：显存（容纳模型）与带宽（搬运数据）。量化（Quantization）就是把原本用 16 位浮点（FP16/BF16）存储和计算的数字，换成更少的位数（8 位、4 位甚至 2 位）来表示，从而同时省下显存和带宽。

1.1 一笔直观的账

以一个 70B（700 亿参数）的语言模型为例：

  • FP16 存储：70 × 10⁹ 参数 × 2 字节 = 140 GB——单张 80GB 的 A100 都放不下；
  • 4-bit 量化后：≈ 70 × 0.5 字节 = 35 GB——一张 A100 就能装下，还能留出 KV Cache 的空间。

再看生成速度。解码（decode）阶段每生成一个 token，都要把全部权重从显存读一遍，因此速度的上限约等于"显存带宽 ÷ 权重大小"。A100 的 HBM 带宽约 2 TB/s：

FP16：140 GB ÷ 2039 GB/s ≈ 68.7 ms/token（≈ 15 tok/s）　→　INT4：35 GB ÷ 2039 GB/s ≈ 17.2 ms/token（≈ 58 tok/s）

仅仅是"把数字变矮"，batch size = 1 的解码速度理论上限就提高了约 4 倍——这就是量化最朴素的收益。此外，低精度整数/浮点矩阵乘（INT8、FP8、FP4）在 GPU Tensor Core 上吞吐量更高、能耗更低，对预填充（prefill）这类计算密集阶段还有额外的加速。

💡 什么时候量化最"值"？—— memory-bound vs compute-bound
  • 解码阶段（memory-bound，访存受限）：算力大量空闲，瓶颈是把权重/KV Cache 搬进显存的速度。此时哪怕只是降低存储位数（weight-only 量化），就能近似线性提速。
  • 预填充阶段（compute-bound，算力受限）：一次并行算几百上千个 token，瓶颈是矩阵乘次数。此时需要权重和激活都量化（W8A8 / W4A4），才能真正吃到低精度 Tensor Core 的算力红利。

这条"两阶段两瓶颈"的判断，贯穿了后文所有方法的设计动机。

1.2 三类被量化的对象

对象是什么省的是谁的钱典型比特数
权重 W（weight）模型参数本身，推理时只读不写显存（模型放不放得下）、解码带宽8 / 4 / 3 / 2 bit

2五分钟补齐基础：定点数与量化公式

2.1 量化在数学上就是"除—取整—乘回"

把一个浮点数 x 用 b-bit 整数近似，只需要一个缩放因子 scale 和一个零点 zero：

xq = clamp( round(x / s) + z ,  0 ,  2b−1 )，   反量化：x̂ = s · ( xq − z )

其中 s 由这一组数的动态范围决定：

s = ( xmax − xmin ) / ( 2b − 1 )，   z = −round( xmin / s )
  • 对称量化（symmetric）：假定 xmin = −xmax，零点固定 z = 2b−1，整数区间是 [−2b−1, 2b−1−1]。少存一个零点、乘法更简单，适合近似零对称分布的权重。
  • 非对称量化（asymmetric）：像上面公式那样分别记录 min/max。适合分布偏向一侧的激活值。

下面是 GPTQ 官方仓库里的实现，可以看到上面的公式原样落进了代码（repos/gptq/quant.py，节选，中文注释为本文所加）：

repos/gptq/quant.py — 基础量化与反量化函数
def quantize(x, scale, zero, maxq):
    q = torch.clamp(torch.round(x / scale) + zero, 0, maxq)  # 除 → 取整 → 加零点 → 截断
    return scale * (q - zero)                                 # 乘回浮点（反量化）

还有一个常用的截断搜索（MSE search）技巧：直接取 min/max 会被个别离群值（outlier）撑大 s，导致大多数"正常"数被挤到很少几个整数格子里。于是从 [0.8, 1.0] 之间网格搜索一个收缩比例 p，用 p·xmax、p·xmin 重新计算 scale，选使量化误差（p-范数，常用 2.4）最小的那一组——同样在 GPTQ 的 find_params 里：

2.2 粒度（granularity）：scale 配得越细，误差越小，开销越大

粒度含义额外开销典型用途
per-tensor整个张量共用一个 s最小最早期方法、FP8 训练最初用法
per-channel（权重量化常用）权重每个输出通道一个 s每行 1 个GPTQ / AWQ 的默认做法
per-token（激活量化常用）每个 token 的向量一个 s每 token 1 个W8A8 激活、KIVI 的 V
per-group / per-block（分组量化）每 32/64/128 个连续元素共享 s（±z）每组 1–2 个GPTQ groupsize=128、KIVI、k-quants、MX/NVFP4

直觉：如果一组数里混进一个巨大的离群值，整组的 s 都会被撑大。把组切小，离群值就只"污染"自己那一小组——这是后面 KIVI、GGUF k-quants、Microscaling 格式共同的思路。分组的代价是元数据（scale/zero 本身也要占位数），所以出现了"把 scale 再量化一次"的双重量化（double quantization）技巧。

2.3 PTQ vs QAT：两条技术路线

  • 训练后量化（PTQ, Post-Training Quantization）：拿训好的 FP16 模型，用几百条校准数据（calibration set）统计一下分布，几分钟到几小时就把模型压好。不需要重训，是 LLM 时代绝对的主流。GPTQ、AWQ、SmoothQuant、KIVI、ViDiT-Q 全是 PTQ。
  • 量化感知训练（QAT, Quantization-Aware Training）：在训练/微调中插入"伪量化"（forward 模拟量化误差，backward 用直通估计器 STE），让模型学会适应低精度。精度天花板更高，但需要算力，曾一度被冷落、2024 年后又强势回归（见 §4.6）。

2.4 评测：量化到底"伤"了多少？

  • 语言模型：困惑度 ppl（WikiText-2 / C4）、零样本准确率（ARC、HellaSwag 等）。
  • 量化方法研究：更关心相对退化（Δppl 或 Δacc），比如"3-bit 下 Δppl < 0.1"。
  • 扩散模型：FID / CLIP-score 等图像质量指标（没有唯一正确输出，评测更间接）。

3发展历程总览（时间线）

量化的历史比 LLM 更早——CNN 时代（2015 年前后）的 Deep Compression 就在做剪枝＋量化。真正让这条技术线"爆炸"的，是 2022 年两个发现：大模型激活里存在系统性离群值，以及大模型对权重低比特出乎意料地鲁棒。下面按时间梳理主线（每条都标注发表时间）：

  • 2015–2021 · 前史：CNN 时代
    Deep Compression、整数推理（INT8）进入工业部署；QAT（伪量化 + STE）成型。2021 年 Gholami 等的综述总结了这一阶段。[53]
  • 2022.08 · 转折点一：LLM.int8()
    Dettmers 等发现超 6.7B 的模型激活中会出现系统性离群值，朴素 INT8 会崩；提出混合精度分解（离群维度走 FP16）[1]。同期 bitsandbytes 库让 8-bit 加载成为一键操作。
  • 2022.10 · GPTQ
    用二阶信息（Hessian）逐列量化权重并即时补偿误差，175B 模型 4 GPU 小时压到 3/4-bit[2]。此后 "GPTQ" 成为 weight-only 4-bit 的事实标准之一。
  • 2022.11 · SmoothQuant
    发现"权重好量化、激活难量化"，用数学等价变换把激活难度搬到权重上，打通全 INT8（W8A8）[3]。
  • 2022.12 · k-bit 缩放定律
    Dettmers & Zettlemoyer 实证：4-bit 是 LLM 推理的甜点，低于 4-bit 需要（当时）更大的模型才能补回精度[10]。
  • 2023.06 · AWQ / SpQR
    AWQ：靠激活分布找出 1% 关键权重、用等价缩放保护，无需反向传播[4]；SpQR：把离群权重稀疏地留在 FP16、其余 3–4 bit[5]。
  • 2023.07 · llama.cpp k-quants
    ikawrakow 为 GGML/GGUF 设计 256 权重一组的"超块 + 双重量化"，Q4_K 以 ~4.5 bit 达到接近 Q8_0 的质量，成为本地部署默认格式[6]。
  • 2023.08–11 · OmniQuant / HQQ
    可学习截断（OmniQuant[9]）；无需校准数据的快速量化 HQQ[8]。
  • 2023.09 · OCP Microscaling 标准
    开放计算项目发布 MX 格式规范：每组 32 个元素共享 8-bit 指数 scale（E8M0），为硬件级块缩放铺路[13]。
  • 2024 · KV Cache 量化元年 + W4A4 + FP8 训练
    KIVI（2-bit KV，K 按通道/V 按 token）[32]、KVQuant（10M 上下文）[33]；旋转法 QuaRot/SpinQuant 打开 W4A4[16][17]；QServe 提出 W4A8KV4 系统协同[15]；AQLM/VPTQ/QTIP 冲击 2-bit[19][20][21]；DeepSeek-V3 首次在 671B 超大规模上验证 FP8 训练[12]。
  • 2024.06–08 · 扩散 Transformer 量化起步
    ViDiT-Q 针对 FLUX/视频 DiT 提出"静态-动态"量化，W8A8 无损[45]；city96 的 ComfyUI-GGUF 让 FLUX 跑进 GGUF 世界[49]；SageAttention 用 INT8/FP8 attention 核加速[48]。
  • 2024.10–12 · VLM 量化专项研究出现
    Q-VLM（跨层依赖）[50]、MBQ（模态平衡）[51]——直接照搬 LLM 量化到 VLM 会明显掉点成为共识。
  • 2025 · QAT 复兴 + FP4 硬件 + 极低比特
    Gemma 3 QAT 官方 4-bit 权重[31]；NVIDIA Blackwell 原生 NVFP4[14]；SVDQuant 用低秩分支吸收离群值实现 DiT 的 W4A4[47]；TesseraQ/PTQ1.61/LittleBit 把权重推向 2-bit 以下[22][23][24]；BitNet b1.58 原生 1-bit 模型开源（b1.58-2B-4T）[27]。
  • 2025–2026 · 2-bit KV 与系统化落地
    KV 量化从"可行"走向"稳健"：LogQuant（对数分布）[34]、RotateKV（旋转）[35]、KVTuner（分层混精）[36]、MixKVQ[37]、Titanus[38]；2026.05 Together AI 开源 OSCAR，2-bit KV 在 128K 上下文保持稳定[39]；vLLM/SGLang/TensorRT-LLM 全面内置 FP8/NVFP4 推理[40][41]。

4LLM 的量化：从 8-bit 到 1.58-bit

先给出本章地图：LLM 量化方法可以按"量化谁"分成四条线——①只压权重（W4/W8，加速解码）→ ②权重激活一起压（W8A8/W4A4，加速预填充）→ ③浮点格式路线（FP8→FP4，训练推理通用）→ ④原生低位训练（BitNet）。KV Cache 单独放在 §5。

4.1 8-bit 时代与"离群值"的发现：LLM.int8() 2022.08 · NeurIPS 2022

故事从一次"翻车"开始。2022 年之前大家都觉得 INT8 很成熟，但 Dettmers 等人发现：模型超过约 6.7B 后，激活值中会出现固定的、幅度极大的离群维度（emergent outlier features）——它们集中在少数几个隐藏维度上、幅度可达正常值的 100 倍，而且从浅层一直持续到深层。这会把 per-tensor 的 scale 撑得巨大，让 99.9% 的"正常"值全部塌缩到 0 附近，精度崩溃。

"…cut the memory needed for inference by half while retaining full precision performance… [the scheme] isolates the outlier feature dimensions into a 16-bit matrix multiplication, while performing all other multiplications in 8-bit… over 99.9% of values stay in 8-bit." 译：该方法将推理所需显存减半且保持全精度性能……（两段式方案）把离群特征维度隔离到 16-bit 矩阵乘中，其余乘法全部用 8-bit 完成……超过 99.9% 的值仍以 8-bit 表示。 — Dettmers et al., LLM.int8(), NeurIPS 2022（arXiv:2208.07339，2022-08 提交）[1]

做法（直觉版）：每个矩阵乘拆成两部分——正常部分（~99.9%）做 8-bit；把含离群维度的少数列/行抠出来，做一个小小的 FP16 矩阵乘，最后加回去。这就是"混合精度分解"。遗产：此后所有量化方法都要回答"如何对付离群值"这个问题；而 LLM.int8() 本身因为离群矩阵乘的拆分在工程上较难加速，逐渐被后继者取代。

4.2 Weight-only 4-bit：GPTQ 与 AWQ 双雄

2022 年 12 月的实证研究给行业吃了定心丸：在同等"有效信息量"预算下，4-bit 是推理量化的性价比拐点，低于 4-bit 才需要明显更大的模型来补[10]。于是 2022–2023 年的主战场是：如何又快又稳地把权重压到 4-bit。

要点（编译）：基于跨模型/任务的缩放实验，作者论证 4-bit 是 LLM 推理量化的最佳精度，可以在几乎不损失性能的情况下将模型缩小数倍。 — Dettmers & Zettlemoyer, The Case for 4-bit Precision, 2022-12（arXiv:2212.09720）[10]

4.2.1 GPTQ：一边量化、一边补偿误差 2022.10 · ICLR 2023

要解决的问题：round-to-nearest（四舍五入）逐个权重独立量化，误差会累积。GPTQ 的核心想法来自 1992 年的最优脑损伤（OBS）理论：如果量化完某一列权重后产生误差，可以顺手微调还没量化的那些列来抵消它，使整层输出误差最小。它用输入激活的二阶统计（Hessian 矩阵 H = 2XXT）来衡量"哪一列权重更重要、该如何补偿"。

📌 直觉理解
想象你在搬家具进电梯（把权重塞进 4-bit 格子）。每搬错一件（量化误差），GPTQ 不懊恼，而是立刻调整后面还没搬的家具位置（利用 H−1 把误差"推"给未量化的列），保证最终电梯里的整体布局（层输出）几乎不变。按列依次处理，处理顺序本身还提供误差传播路径。
"…a new one-shot weight quantization method based on approximate second-order information, that is both highly-accurate and highly-efficient… quantize a 175-billion-parameter GPT model to 3–4 bits per weight in about four GPU hours…" 译：一种基于近似二阶信息的新颖一次性权重量化方法，兼具高精度与高效率……可在约 4 个 GPU 小时内将 1750 亿参数的 GPT 模型量化至每权重 3–4 bit…… — Frantar et al., GPTQ, ICLR 2023（arXiv:2210.17323，2022-10 提交）[2]

代码走读（repos/gptq/gptq.py，主循环 fasterquant）。先收集每层的 Hessian，加阻尼项后做 Cholesky 分解求 H−1；随后逐列量化、用 H−1 的行把误差反馈给右侧未量化列：

damp = percdamp * torch.mean(torch.diag(H))      # 阻尼：0.01*平均对角元，防 H 奇异
H[diag, diag] += damp
H = torch.linalg.cholesky(H)                     # 三步 Cholesky 求出 H^{-1} 的 Cholesky 因子
H = torch.cholesky_inverse(H)
H = torch.linalg.cholesky(H, upper=True)
Hinv = H

for i1 in range(0, self.columns, blocksize):     # 分块（128 列）处理，省显存
    for i in range(count):

三个工程细节值得注意：①groupsize（常用 128）：每 128 列共享一组 scale/zero，即分组量化；②actorder：按 Hessian 对角元从大到小的顺序量化（重要列先量化，误差更可控）；③静态分组/块处理：纯为省显存的实现技巧。GPTQ 量化完后权重被打包成 3/4-bit 整数矩阵，推理时用定制的反量化-矩阵乘 kernel（老仓库里的 vecquant4matmul，如今已由 llama.cpp、ExLlama、Marlin 等更快的 kernel 取代）。

4.2.2 AWQ：不训练、不重构，靠"缩放"保护关键权重 2023.06 · MLSys 2024 最佳论文

GPTQ 要跑校准数据做逐层重构。MIT 韩松团队观察到两个现象：①权重本身看不出谁重要，但激活幅度大的输入通道对应的权重很重要——量化这些"关键通道"（约 1%）会大幅掉点；②让这 1% 权重保持 FP16（混合精度）kernel 效率低。AWQ 的解法很优雅：给关键通道乘一个略大于 1 的缩放 s，等价地在激活侧除回去——乘过之后这些权重在量化网格里"占的格子变多了"，等效精度提高，而整个矩阵仍是统一的 INT4：

Y = (X · diag(s)−1) · Q(W · diag(s)) ≈ X · W
"We propose AWQ, a hardware-friendly approach for LLM low-bit weight-only quantization… Protecting only 1% salient weights can greatly reduce quantization error… scales are searched from offline activation statistics…" 译：我们提出 AWQ，一种对硬件友好的 LLM 低比特 weight-only 量化方法……仅保护 1% 的显著权重即可大幅降低量化误差……缩放因子由离线激活统计搜索得到…… — Lin et al., AWQ, MLSys 2024 最佳论文（arXiv:2306.00978，2023-06 提交）[4]

代码走读（repos/AutoAWQ/awq/quantize/quantizer.py）。缩放因子不是解析算出来的，而是在 20 个网格点上暴力搜索（α 从 0 到 1），每格试量化一次、用校准输出的误差选最优：

n_grid = 20

搜索完 scale 后，还要把它永久迁移进模型：LayerNorm 的权重除以 s、后续 Linear 的权重乘以 s（推理时激活自动缩小 s 倍），对 RMSNorm/GELU/连续 Linear 等各种衔接分别处理（repos/AutoAWQ/awq/quantize/scale.py 的 apply_scale / scale_ln_fcs）：

@torch.no_grad()
def scale_ln_fcs(ln, fcs, scales):
    ln.weight.div_(scales)          # LN 权重 ÷ s
    if ln.bias is not None: ln.bias.div_(scales)
    for fc in fcs:
        fc.weight.mul_(scales.view(1, -1))   # 下游 Linear 权重 × s  ⇒  (X/s)·(sW) = XW

AWQ 不需要反向传播与逐层重构，因此跨领域/跨模态泛化好（论文首次把 PTQ 用到多模态模型上），配套的 TinyChat 推理框架在桌面/手机 GPU 上取得对 FP16 的 3× 以上加速[4]。今天 Qwen、Mistral、VuLM 等官方发布的 INT4 权重很多都是 AWQ/GPTQ 格式。

4.2.3 GGUF k-quants：为 CPU/端侧而生的工程艺术 2023.07

llama.cpp 生态（GGML→GGUF）走的是另一条路：不追求 GPU Tensor Core，而是让CPU/核显也能解码大模型。ikawrakow 的 k-quants 设计了层级化的"超块"结构：

  • 每 256 个权重组成一个超块，切成 8 个 32 权重的子块；
  • 每个子块有自己的 scale/min（6-bit），再相对超块的 scale/min 二次量化（双重量化）——scale 元数据从 0.5 bit/权重降到约 0.06 bit/权重；
  • 于是 Q4_K 实际约 4.5 bit/权重，质量明显优于老式 Q4_0；Q4_K_M 再对 attention.wv、feed_forward.w2 等敏感层混用 Q6_K，约 4.8 bit。
"…each super-block of 256 weights has 1–2 floating point scales that convert quants to actual model weights…"（k-quants 作者 ikawrakow 在官方讨论中的描述） 译：每个由 256 个权重构成的超块拥有 1–2 个浮点 scale，用于把量化值还原为真实权重。 — llama.cpp Discussion #5063（2023）[7]；原始实现见 PR #1684（2023-07）[6]

后来的 i-quants（IQ4_XS 等，2024）用重要性矩阵做非均匀编码，进一步压低元数据开销。k-quants 证明了一件事：分组粒度 + 双重量化本身就是一种强大的误差控制手段，这条思路后来在 GPU 侧以 Microscaling 格式"复活"（§4.4）。

4.2.4 这一族的亲戚们（快速过）

  • SpQR（2023.06）[5]：承认离群权重救不了，干脆把 ~1% 大值稀疏地存 FP16，其余 3–4 bit；要点（编译）：将"敏感权重+结构化稀疏"与高压缩比结合，实现接近无损的 3–4 bit 压缩。
  • HQQ（2023.11）[8]：把"求 scale/zero"写成半二次优化，不需要任何校准数据，几分钟出模型。
  • 极低比特（2-bit 上下）：均匀网格到 2-bit 已不够用，2024 年起转向码本/向量量化——AQLM（加性量化）[19]、VPTQ（二阶优化的向量量化）[20]、QTIP（格码本 tessellated lattice）[21]。2025 年 TesseraQ（渐进自适应舍入）[22]、PTQ1.61[23]、LittleBit（0.1 bit/权重的潜因子分解）[24] 继续下探。

4.3 权重 + 激活一起压：从 W8A8 到 W4A4

weight-only 量化只加速解码。要加速预填充（以及让 attention/FFN 全链路吃低精度算力），必须把激活也量化。难点还是 §4.1 的老问题：激活有离群值，而且激活是逐 token 在线产生的，不能离线慢慢优化。

4.3.1 SmoothQuant：把难度从激活搬到权重 2022.11 · ICML 2023

观察："权重容易量化、激活不容易"——权重分布平稳，激活的某些通道常年爆表。数学上，Linear 层 Y = X·W 对输入通道做等价缩放不变：

Y = (X · diag(s)−1) · (diag(s) · W) ，   sj = max|X:,j|α / max|W:,j|1−α

α∈[0,1] 控制迁移强度：激活大（难量化）的通道，把激活除以一个大的 s 让它变"平静"，同时权重乘上 s 变陡——权重反正好量化，扛得住。变换在模型里落地为"改 LayerNorm 权重 + 改 Linear 权重"，推理时零额外算子：

repos/smoothquant/smoothquant/smooth.py — smooth_ln_fcs（完整核心）
@torch.no_grad()
def smooth_ln_fcs(ln, fcs, act_scales, alpha=0.5):
    weight_scales = torch.cat(
        [fc.weight.abs().max(dim=0, keepdim=True)[0] for fc in fcs], dim=0
    ).max(dim=0)[0].clamp(min=1e-5)                  # 每个输入通道的权重最大绝对值
    scales = (act_scales.pow(alpha) / weight_scales.pow(1 - alpha)).clamp(min=1e-5)
    ln.weight.div_(scales)                           # LN（或 RMSNorm）权重 ÷ s
    ln.bias.div_(scales)
    for fc in fcs:
        fc.weight.mul_(scales.view(1, -1))           # 下游 Linear 权重 × s

act_scales 来自离线校准（repos/smoothquant/smoothquant/calibration.py：前向 512 条样本，逐层记录激活 absmax）。SmoothQuant 之后，全链路 W8A8 INT8 成为现实：

"…a training-free, accuracy-preserving, and general-purpose post-training quantization (PTQ) solution… weights are easy to quantize while activations are not… by offline migrating the quantization difficulty from activations to weights with a mathematically equivalent transformation… up to 1.56× speedup and 2× memory reduction." 译：一种免训练、保精度、通用的训练后量化方案……权重易量化而激活难量化……通过数学等价变换把量化难度从激活离线迁移到权重……最高 1.56× 加速与 2× 显存节省。 — Xiao et al., SmoothQuant, ICML 2023（arXiv:2211.10438，2022-11 提交）[3]

4.3.2 旋转法（QuaRot / SpinQuant）：让离群值"消失" 2024

平滑只能处理固定通道的离群值；如果离群值换位置（不同 token 离群通道不同）就失灵了。2024 年的旋转法思路更彻底：给激活和权重左右乘一个正交矩阵（如 Hadamard 旋转 H），线性层的数学结果不变，但旋转会把能量"摊"到所有通道上——离群值被稀释，分布接近高斯，4-bit 都能量化。QuaRot（2024.04）用随机 Hadamard 旋转实现首个 W4A4 流程[16]；SpinQuant（2024.05）进一步用梯度学习旋转矩阵本身（Cayley 参数化保证正交），精度更佳：

"SpinQuant also outperforms concurrent work QuaRot, which applies random rotations… with W4A4 tensor core kernels…" 译：SpinQuant 亦优于同期采用随机旋转的 QuaRot……并配合 W4A4 Tensor Core 内核…… — Liu et al., SpinQuant（arXiv:2405.16406，2024-05 提交；OpenReview 摘要）[17]

同期系统侧的代表作 QServe（2024.05，MLSys 2025）组合 W4A8KV4 三级精度并指出：W4 权重反量化本身是访存瓶颈，必须与算子融合、compute-aware pruning 协同设计，才能把"纸面 4-bit"变成"服务端加速"[15]；Atom（2023.10，MLSys 2024）则探索 W4A4 + 稀疏[18]。另有一条"可学习"支线：OmniQuant（2023.08）把截断阈值和平滑因子当作可学参数、分块优化，无需逐层重构[9]。NeurIPS 2024 的一项研究系统对比了 SmoothQuant/AWQ/GPTQ 的相互作用，发现它们彼此并不等价、可组合但有顺序敏感性[54]。

4.4 浮点格式路线：FP8 → FP4/MX 2022–2026 · 硬件主导

整数不是唯一选择。浮点量化（FP8/FP4）保留指数位，动态范围大，对离群值天然更宽容，而且由硬件 Tensor Core 原生支持，不需要自己写反量化 kernel。

4.4.1 FP8：训练推理通吃

FP8 有两种常见格式：E4M3（4 位指数 3 位尾数，精度高、范围 ±448）与 E5M2（范围大、精度低）。NVIDIA H100 起原生支持 FP8 GEMM（配 Transformer Engine 的 delayed scaling）[11]。DeepSeek-V3（2024.12）把 FP8 训练推向了 671B 规模，其技术报告的细节是学习细粒度量化的最好教材：

  • 细粒度分块：激活按 1×128 tile（每 token 128 通道）共享 scale，权重按 128×128 block 共享 scale——比 per-tensor 细得多，离群值只影响自己的小块；
  • 在线量化：scale 不靠历史统计，前向时就地算 absmax；
  • 高精度累加：每累乘 128 个元素就"晋升"到 CUDA Core 的 FP32 寄存器做精累加（规避 Tensor Core 14-bit 累加精度问题）；
  • 所有张量统一用 E4M3（因为分块细，不缺动态范围）、优化器状态用 BF16、激活缓存 FP8、MoE 通信也走 FP8。
"…we introduce a fine-grained quantization strategy: tile-wise grouping with 1×Nc elements or block-wise grouping with Nc×Nc elements… (1) for activations, we group and scale elements on a 1x128 tile basis…; and (2) for weights, we group and scale elements on a 128x128 block basis… the relative loss error of our FP8-training model remains consistently below 0.25%." 译：我们提出细粒度量化策略：按 1×N_c 个元素做 tile 级分组，或按 N_c×N_c 个元素做 block 级分组……（1）激活按 1×128 tile 分组缩放；（2）权重按 128×128 block 分组缩放……FP8 训练模型的相对损失误差始终低于 0.25%。 — DeepSeek-AI, DeepSeek-V3 Technical Report（arXiv:2412.19437，2024-12 提交）§3.3[12]

报告还专门向芯片厂商喊话：希望未来 GPU 支持"Tensor Core 内部的分组缩放、在线量化融合、转置读取"——这些诉求随后在 Blackwell 的 MX 数据通路上部分兑现[12]。此后 Kimi K2（2025.07）等开源大模型跟进 FP8 训练，FP8 已成为 2025 年之后旗舰模型训练的默认选项之一。

4.4.2 FP4 与 Microscaling：把"分组"写进硬件

OCP（开放计算项目）2023.09 发布 MX（Microscaling）格式：每个数据元素 4-bit 浮点 E2M1，每 32 个元素共享一个 8-bit 纯指数 scale（E8M0）[13]。NVIDIA Blackwell（2025）在此基础上支持了自家的 NVFP4：块更小（16 个元素）、scale 用 E4M3 FP8（支持非 2 的幂的分数缩放），外加每张量一个 FP32 二级 scale：

"NVFP4 uses a two-level scaling strategy: a shared E4M3 FP8 scale per 16-value micro-block, plus a second-level FP32 scalar per tensor… [the block size of 16 gives] twice as many opportunities to match the local dynamic range of the data… Blackwell's fifth-generation Tensor Cores automatically handle the microscaled FP4 data including the grouping of elements, dynamic scaling, and 4-bit matrix operations." 译：NVFP4 采用两级缩放：每 16 个值的微块共享一个 E4M3 FP8 scale，另加每张量一个 FP32 二级 scale……（块大小 16 意味着）有双倍的机会去匹配数据的局部动态范围……Blackwell 第五代 Tensor Core 会自动处理微缩放 FP4 数据，包括元素分组、动态缩放与 4-bit 矩阵运算。 — NVIDIA Developer Blog, Introducing NVFP4（2025）[14]
💡 发现了吗？硬件在"重新发明"软件的招数

KIVI 的分组 KV（§5）、k-quants 的超块（§4.2.3）、DeepSeek 的 1×128 tile、NVFP4 的 16 元素微块——本质都是同一件事：小组内共享 scale，隔离离群值。区别只是从"软件侧的技巧"变成了"硬件原生数据通路"。看懂这一点，就能预测：未来更低位数的格式一定还是"块更小 + scale 更精细"。

4.5 原生低位训练：BitNet 与 1.58-bit 2023–2025

前面所有方法都是"训完再压"（PTQ）。微软的 BitNet 反其道而行：从第一行代码起就用低精度。BitNet b1.58 把每个权重限制为三值 {−1, 0, +1}（信息量 log₂3 ≈ 1.58 bit），激活 8-bit。矩阵乘退化为"加减法"，理论上能效高一个数量级：

"…a 1-bit LLM variant, namely BitNet b1.58, in which every single parameter (or weight) of the LLM is ternary {-1, 0, 1}… [it] matches the full-precision (i.e., FP16 or BF16) Transformer LLM with the same model size and training tokens… opens the door for designing specific hardware optimized for 1-bit LLMs." 译：一种 1-bit LLM 变体 BitNet b1.58，其中 LLM 的每个参数（权重）都是三值 {−1, 0, +1}……在相同模型规模与训练 token 数下可匹敌全精度（FP16/BF16）Transformer LLM……为设计面向 1-bit LLM 的专用硬件打开了大门。 — Ma et al., The Era of 1-bit LLMs（arXiv:2402.17764，2024-02 提交）[26]；前身 BitNet 见 arXiv:2310.11453（2023-10）[25]

代码走读（repos/BitNet/gpu/model.py）。BitLinear 对激活做 per-token INT8 量化；三值权重以打包形式存储，由 bitnet_int8xint2_linear 内核完成 INT8×INT2 矩阵乘：

repos/BitNet/gpu/model.py — BitLinear（节选）
class BitLinear(nn.Linear):
    @torch.compile
    def quant_input(self, input):
        s = 127 / input.abs().max(dim=-1, keepdim=True).values.clamp_(min=1e-5)  # per-token absmax
        return (input * s).round().clamp(-128, 127) / s                           # 8-bit 激活
    def forward(self, input):
        input = self.quant_input(input)
        return F.linear(input, self.weight)   # 权重为三值 {-1,0,1}（INT2 存储）

2025.04 微软开源首个原生 1-bit 模型 BitNet b1.58-2B-4T（2.4B 参数 / 4T tokens），配合 bitnet.cpp 可在普通 CPU（含 ARM）上跑出可观速度[27]；2025 年 9 月的 BitNet a4.8 进一步把激活也压到 4-bit（混合量化+稀疏化处理离群激活）[28]。要点（编译）：a4.8 在与 b1.58 相同训练成本下达到相当性能，更适合混精矩阵乘内核。不过生态（训练框架、推理引擎、微调工具）仍是瓶颈，BitNet 路线尚未被主流生产环境大规模采用。

5KV Cache 量化：长上下文的关键

5.1 KV Cache 为什么是"新瓶颈"

自回归生成时，每个 token 的注意力 Key/Value 要缓存下来供后续 token 使用，避免重复计算。它的大小：

KV 字节 = 2(K和V) × 层数 × KV头数 × 每头维度 × 上下文长度 × 批大小 × 2字节(FP16)

以 Llama-2-70B 为例（80 层、GQA 8 个 KV 头、head_dim 128）：每 token ≈ 2×80×8×128×2 = 320 KB；128K 上下文单条序列就是 ≈ 40 GB——比 4-bit 权重（35 GB）还大！长上下文场景下，KV Cache 取代权重成为显存第一杀手，直接限制了批大小和上下文长度。因此KV Cache 量化的收益，是"能服务多少并发、能开多长上下文"的系统级收益。

两条架构侧的背景：GQA（分组查询注意力，Llama-3/Qwen 等采用）已把 KV 头数砍到 1/4~1/8；DeepSeek 的 MLA 则把 KV 压缩进一个几百维的潜在向量，缓存再小近一个数量级。即便如此，百万级上下文仍需量化来"续命"。

5.2 KIVI：2-bit KV 的开山之作 2024.02 · ICML 2024

KIVI 的两个关键观察，直接决定了算法形态：

  1. Key 应按通道（channel）量化，Value 应按 token 量化——Key 参与的是 Q·KT（每个通道是一整个维度的点积贡献，离群通道会系统性破坏所有 token 的内积），Value 参与的是 attn·V（每个 token 的 V 独立加权求和）。对 K 按通道分组、对 V 按 token 分组，各自的量化误差都被控制到最小；
  2. 留一个"全精度残差窗口"：最近的少量 token（如 128 个）注意力权重最大、还没被分组覆盖，保留 FP16；其余历史 token 才做 2-bit 分组量化。
"…the key cache should be quantized per-channel [and] the value cache should be quantized per-token… a tuning-free 2bit KV cache quantization algorithm named KIVI… 2.6× less peak memory… up to 4× larger batch size and 2.35×–3.47× [throughput gains]." 译：Key 缓存应按通道量化，Value 缓存应按 token 量化……我们提出免调参的 2-bit KV 缓存量化算法 KIVI……峰值显存降低 2.6 倍……批大小最大提升 4 倍，吞吐提升 2.35–3.47 倍。 — Liu et al., KIVI, ICML 2024（arXiv:2402.02750，2024-02 提交）[32]

5.3 KVQuant：面向千万级上下文 2024.01 · NeurIPS 2024

KVQuant 面向"10M token 上下文"这种极端目标，组合了四个相互配合的设计[33]：

  • Pre-RoPE Key 量化：旋转位置编码 RoPE 会把相邻通道混在一起、破坏通道相关性，因此在 RoPE 之前对 K 量化；
  • 每通道 Key + 每 token Value（与 KIVI 观察一致）；
  • 非均匀量化（ NUQ ）：KV 分布不是均匀的，用 k-means 学出的码本代替线性网格；
  • 稠密-稀疏分解：个别超大离群值单独稀疏存储，其余稠密低比特。
"…LLMs are seeing growing use for applications which require large context windows, and with these large context windows KV cache activations surface as the dominant contributor to memory consumption… we achieve < 0.1 perplexity degradation with 3-bit quantization on both Wikitext-2 and C4… [serving] 1 million [context] on a single A100-80GB GPU and 10 million on an 8-GPU system." 译：LLM 越来越多地用于大上下文应用，KV 缓存激活随之成为显存消耗的主导因素……我们在 Wikitext-2 和 C4 上以 3-bit 量化实现了小于 0.1 的困惑度退化……在单张 A100-80GB 上服务 100 万上下文、8 卡系统上服务 1000 万。 — Hooper et al., KVQuant, NeurIPS 2024（arXiv:2401.18079，2024-01 提交）[33]

6VLM 的量化：多模态的新难题

6.1 VLM 结构与量化的特殊矛盾

主流 VLM（LLaVA、Qwen-VL 系列）＝ 视觉编码器 ViT + 投影层 projector + LLM 主干。量化它，会遇到三个 LLM 没有的问题：

  1. 两套分布：视觉 token（图像 patch 特征）与文本 token 的激活分布差异巨大。校准数据里图文比例、分辨率都会改变统计，"一套 scale 包打天下"必然失衡；
  2. 投影层与视觉编码器更敏感：它们是跨模态对齐的咽喉，低位量化这里最容易伤（常见做法是保持 FP16 或用更高比特）；
  3. 细粒度感知敏感性：文本里一个小误差只影响一个词；视觉 token 的误差会以空间方式扩散，导致幻觉物体、OCR 错字等"看得见的"退化。

所以 2024 年起的共识是：直接把 LLM 的 GPTQ/AWQ/SmoothQuant 无损搬到 VLM 上会明显掉点，需要模态感知的专门设计。

7DiT 的量化：扩散模型与众不同

7.1 为什么扩散模型的量化更难

Sora、FLUX、HunyuanVideo、Qwen-Image 这类生成模型的骨架是扩散 Transformer（DiT）：同一个网络被去噪步骤（timestep）反复调用几十次。这带来与 LLM 截然不同的量化难题：

  1. 分布随时间步漂移：t 接近 1（纯噪声）和接近 0（接近成图）时，激活分布差别巨大。用一套静态 scale＝只对某个时间步最优；
  2. 无"正确答案"：LLM 量化可用困惑度精细评测；扩散模型没有逐 token 的对错，误差要靠 FID/CLIP-score 等间接指标观察，常常"小误差放大成大画质问题"；
  3. 误差跨步累积：每一步去噪的量化误差会被后续几十步放大；
  4. 计算模式不同：没有 KV Cache 增长问题，但激活（尤其注意力图）异常值比 LLM 更极端。

7.2 UNet 时代的热身：Q-Diffusion 等 2022–2023

PTQ4DM（2022）最早指出扩散模型量化需要跨时间步联合校准；Q-Diffusion（2023.02, ICCV 2023）给出系统解法：

"…the key difficulty of diffusion model quantization [is] the changing output distributions of noise estimation networks over multiple time steps and the bimodal activation distribution of the shortcut layers… We tackle these challenges with timestep-aware calibration and split shortcut quantization… stable diffusion in 4-bit weights with high generation quality for the first time." 译：扩散模型量化的关键困难在于：噪声估计网络的输出分布随时间步变化，以及 shortcut 层的双峰激活分布……我们用时间步感知校准与 shortcut 分裂量化应对……首次实现高质量 4-bit 权重的 Stable Diffusion。 — Li et al., Q-Diffusion, ICCV 2023（arXiv:2302.04304，2023-02 提交）[43]；PTQ4DM（CVPR 2023，arXiv:2211.15736，2022-11 提交）[42]；PTQD（NeurIPS 2023，arXiv:2305.10657，2023-05 提交）进一步分解失真来源[44]

7.3 ViDiT-Q：为 DiT 设计的"静态-动态"量化 2024.06 · ICLR 2025

当骨干从 UNet 换成 Transformer（DiT），量化策略也随之升级。清华团队的 ViDiT-Q 针对 FLUX、CogVideoX、HunyuanVideo 等提出两条设计：

  • 权重量化用"静态"参数：权重离线确定 scale（按通道，结合通道显著度校准）；
  • 激活动态量化：激活随 timestep 剧烈变化，干脆每次前向在线计算 scale（per-token/per-group absmax），不做静态校准——用少量在线开销换取对分布漂移的完全免疫。这后来被称为 static-dynamic 策略。
"[ViDiT-Q] achiev[es] W8A8 and W4A8 with negligible degradation in visual quality and metrics… 2-2.5x memory saving and a 1.4-1.7x end-to-end latency speedup." 译：ViDiT-Q 在视觉质量与指标几乎无损的情况下实现 W8A8 与 W4A8……显存节省 2–2.5 倍，端到端延迟加速 1.4–1.7 倍。 — Zhao et al., ViDiT-Q, ICLR 2025（arXiv:2406.02540，2024-06 提交）[45]

7.4 SVDQuant：用低秩分支"吸收"离群值 2024.11 · ICLR 2025 Spotlight

要压到 W4A4（权重激活都 4-bit），平滑和旋转都不够。NVIDIA/ MIT 韩松团队的 SVDQuant 给出了一个漂亮的构造：把权重（和激活）的离群部分用 SVD 分解成一个小秩的旁路——旁路以 FP16 精度计算（参数量只有百分之几），主干残差因此变得"平坦"、可以放心 4-bit：

"…we use a high-precision, low-rank branch to take in the weight outliers with Singular Value Decomposition (SVD), while a low-bit quantized branch handles the residuals… [Nunchaku] fuses the kernels of the low-rank branch into those of the low-bit branch to cut off redundant memory access… We reduce the memory usage for the 12B FLUX.1 models by 3.5×, achieving 3.0× speedup over the 4-bit weight-only quantization (W4A16) baseline on the 16GB laptop 4090 GPU with INT4 precision." 译：我们用高精度低秩分支（SVD 分解）承接权重离群值，低比特量化分支处理残差……（Nunchaku 引擎）把低秩分支 kernel 融合进低比特分支 kernel 以消除冗余访存……12B FLUX.1 显存降低 3.5 倍，在 16GB 笔记本 4090 上以 INT4 精度取得相对 W4A16 基线 3.0 倍加速。 — Li et al., SVDQuant, ICLR 2025 Spotlight（arXiv:2411.05007，2024-11 提交）[47]

代码走读（repos/nunchaku/）：Nunchaku 的 Python 侧提供 SVDQuant 模型加载与 4-bit 推理入口，核心 fused kernel（SVD 旁路 GEMM 与 INT4 GEMM 融合、SmoothValue 等）在 C++/CUDA/Triton 侧实现。低秩旁路想法与 LoRA 形式相同——把"误差控制"变成"加一个小的高精度分支"，这已成为 DiT 量化的主流范式之一。

7.5 注意力核量化：SageAttention 2024.10 · ICLR 2025

DiT 里注意力占比极高。SageAttention 把 attention 内核本身做量化加速：Q·KT 用 INT8、softmax 后的 P·V 用 FP8，并做了逐行/分块平滑：

"…we propose SageAttention, a highly efficient and accurate quantization method for attention… The OPS of our approach outperforms FlashAttention2 and xformers by about 2.1 times and 2.7 times… our approach incurs almost no end-to-end metrics loss across diverse models, including those for large language processing, image generation, and video generation." 译：我们提出 SageAttention，一种高效且精确的注意力量化方法……算力（OPS）约为 FlashAttention2 与 xformers 的 2.1 倍与 2.7 倍……在语言、图像生成、视频生成等多种模型上端到端指标几乎无损。 — Zhang et al., SageAttention, ICLR 2025（arXiv:2410.02367，2024-10 提交；SageAttention2 进一步引入 INT4 QK）[48]

SageAttention 已被 ComfyUI 生态（含 Nunchaku）广泛集成——用户勾选一个选项就享受"量化注意力"的加速。

10未来发展方向

综合学界论文与业界动向，以下八条线值得持续关注（序号不代表优先级）：

① 硬件-算法协同设计成为主战场

DeepSeek-V3 技术报告公开向芯片厂提出的三点诉求——Tensor Core 内建分组缩放、FP8 cast 与访存融合、转置读取——正是下一代硬件的演进方向[12]。MX/NVFP4 的出现说明算法侧的"分组量化"正在被"焊死"进硬件；再往后是 FP4 训练、FP6、以及为 BitNet 类三值运算定制的算术单元[26]。软硬件的边界会继续模糊：今天是论文技巧，两年后就是指令集。

② 从"训后补救"到"为量化而发行"

PTQ 的 4-bit 天花板已经可以摸到，官方 QAT/预量化发行（Gemma 3 QAT、Llama QAT）把精度损失进一步压到"用户无感"[29][31]。可以预期：旗舰模型发布时同步给出 W4/W8、FP8、NVFP4 多套权重将成为标准动作，"量化"逐渐从用户操作下沉为出厂工序；QAT 与蒸馏、与 RL 后训练的结合（尤其对长思维链推理模型）是明确的增量方向。

③ 训练全链路低精度化

FP8 训练已被 DeepSeek-V3 验证到 671B[12]，下一步是 FP4/混合 FP4-FP8 训练（已有面向 Blackwell 的开源实验）、随机舍入（stochastic rounding）在低比特下的理论补全、以及优化器状态/梯度的进一步低位表示。训练低精度每前进一步，"训练-推理精度鸿沟"就缩小一步。

④ KV 压缩走向"量化 × 剪枝 × 缓存策略"的融合

纯量化把 KV 压到 2-bit 后，剩余收益要靠组合技：OSCAR 的注意力感知旋转[39]、KVTuner 的层间混精[36]、Titanus 的剪枝-量化渐进[38]，以及与注意力 sink、token 合并、分层卸载（HBM↔CPU↔SSD）的联合设计。同时，架构侧（GQA/MLA/滑动窗口）与量化位数的联合搜索会越来越重要——同样的显存预算，是留给更多 KV 头还是更高精度，是个开放问题。

⑤ 极低比特：码本、格与因子分解

1–2 bit 均匀量化在数学上已不划算，研究重心转向结构化表示：向量量化码本（AQLM/VPTQ）、格量化（QTIP）[21]、潜因子分解（LittleBit）[24]、以及 BitNet 式"原生三值+低位激活"[28]。这一线的终极问题是：给定模型能力，信息论上的最低位数的下界在哪里、以及如何让 kernel 高效解码这些非均匀表示。

⑥ 多模态与视频生成的原生量化

VLM 侧需要模态感知的校准与误差分配（MBQ 的方向[51]）；视频 DiT 侧则是时间维度的冗余利用：相邻帧激活高度相似，量化参数可跨步复用，量化与步数蒸馏（Q-VDiT[46]）、与特征缓存（如 Nunchaku 的 cache 模式）协同的"压缩组合拳"刚刚开始。

⑦ 系统级协同：kernel 与服务栈决定实际收益

QServe 的教训——W4 的反量化开销能吃掉全部理论收益[15]——使得"算法作者必须懂 kernel"成为共识。Marlin（INT4 GEMM）、Nunchaku（低秩+低比特融合）、SageAttention（量化注意力核）、bitnet.cpp（CPU 三值）等 kernel 创新，与投机解码、连续批处理、量化感知调度组合，才构成端到端的收益闭环。

⑧ 评测标准化与"量化鲁棒性"科学

困惑度已不足以刻画量化伤害：长思维链、多轮工具调用、agentic 长程任务中的误差累积，多模态任务中的空间误差扩散，都需要专门基准。Llama-3 家族在 W8A8 下的反常退化等案例[54]提示：量化敏感度与模型/数据高度耦合，"哪一层、哪种算子、哪类样本怕量化"的机理研究与自动化的混合精度决策，仍是学界富矿。

⚠️ 一个务实的提醒

实际选型时没有"最好"的方法，只有匹配场景的方法：端侧内存优先选 GGUF/QAT 权重；服务端吞吐优先选 FP8/FP4（硬件支持时）或 AWQ/GPTQ + Marlin；长上下文优先打开 KV 量化；图像/视频生成优先 SVDQuant/SageAttention 组合。先看目标硬件的原生格式，再回头挑算法，往往比反过来少走弯路。
