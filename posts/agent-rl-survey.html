1预备知识：RL for LLM 的基本概念MDP → 策略梯度 → PPO → RLHF → RLVR/GRPO → Agent RL

1.1 强化学习的基本过程

强化学习(RL)研究的问题是:一个"智能体"(agent)如何通过不断试错,学会在"环境"(environment)里采取让长期回报最大的行为。它由五个要素构成,记住这张对照表就够用了:

RL 术语经典含义(机器人/游戏)在 LLM 训练里的对应物
状态 s机器人看到的传感器读数、游戏画面当前的上下文(prompt + 已经生成的所有 token;Agent 场景还包括工具返回的观测)
动作 a往哪走、按哪个键生成下一个 token(Agent 场景:一次工具调用)
策略 π(a|s)看到状态后选动作的概率分布LLM 本身:给定上下文,输出词表上的概率分布
奖励 r得分、输赢这条回答好不好:奖励模型的打分,或"数学答案是否正确"、"单元测试是否通过"
轨迹 τ一局游戏从头到尾的动作序列一条完整回答(或 Agent 从领任务到交差的全过程),也就是后文反复出现的 rollout

目标:调整策略的参数 θ(即 LLM 的权重),让期望回报 J(θ) = E[∑ r] 最大。直接对它求导就得到策略梯度:直觉上,把"拿到高奖励的轨迹"的每一步动作概率都调高一点,低奖励的调低一点,模型就会越来越好。问题在于奖励信号是稀疏的:整条轨迹可能只在最后拿一个分,我们不知道哪个动作有功,这就是 RL 里著名的 credit assignment(功劳分配)问题。PPO、GAE、GRPO 都是在回答"怎么把最终奖励合理地摊到每个 token 上"。

1.2 LLM 生成即"动作":自回归、采样与 KV Cache

LLM 生成文本的方式是自回归(autoregressive):每一步根据前文预测下一个 token 的概率分布,按温度采样挑一个,拼回上下文,再预测下一个,循环直到结束符。从 RL 视角看,这天然就是一个马尔可夫决策过程(MDP):每生成一个 token 就是做一次动作。KV Cache 是让这个过程不慢到无法忍受的关键:已生成前文的注意力键值缓存下来,新 token 只需增量计算。但要命的是:训练框架(如 Megatron/FSDP)为了放下百亿千亿参数,把权重切片存放(TP/PP/DP 并行);推理同样可用 TP/PP 权重分片；两阶段的并行布局、数值格式、驻留与调度可能不同，因此需要按配置重分片或转换，而非推理必须在单卡持有完整连续权重。这个"形态不匹配"正是 §3 rollout 引擎要解决的头号问题。

1.3 从 RLHF 到 RLVR:三次范式转移

第一幕 · RLHF(2022):让模型说人话

InstructGPT/ChatGPT 确立了三阶段流程[3]:① SFT:用人工写的优质回答做监督微调;② 奖励模型(RM):让人类对同一问题的多个回答排序,训练一个打分器;③ PPO:用强化学习最大化 RM 打分,同时用 KL 散度惩罚约束模型别偏离 SFT 初始模型太远。PPO 由 Schulman 等人于 2017 年提出[1],核心是"裁剪的重要性比率":限制每次参数更新的幅度,防止策略一步迈太大而崩溃。RLHF 的奖励来自人(或学人的模型),主观、昂贵、且可能被模型"钻空子"(reward hacking)。

[3] Ouyang et al., "Training language models to follow instructions with human feedback", arXiv:2203.02155, 2022-03。
要点概述(非原文直引):论文提出 SFT → 奖励模型 → PPO 的三阶段对齐流程,使 1.3B 参数的 InstructGPT 在人类偏好评测中胜过 175B 的 GPT-3。这是 RLHF 的奠基性工作。

第二幕 · RLVR + GRPO(2024–2025):让模型自己学会思考

2024 年 DeepSeekMath 提出 GRPO(Group Relative Policy Optimization)[6]:把 PPO 里那个又大又难训的价值网络(critic)扔掉,改为对同一个问题采样一组回答(比如 16 条),用组内奖励的组内均值与标准差归一化后的相对奖励计算优势:比组平均好的回答整体加分,差的减分。省去 critic 可降低资源开销，但总显存比例依优化器、参考模型、激活和 rollout 配置而变；GRPO 是重要路线，RLOO、PPO 等仍有不同权衡。2025 年 1 月,DeepSeek-R1-Zero[7] 展示了无 SFT 冷启动实验；R1 本身使用冷启动与多阶段训练。R1-Zero 从 base 模型出发，不做任何 SFT 冷启动,只用可验证奖励(RLVR,Reinforcement Learning with Verifiable Rewards:数学答案对不对、代码测试过不过,规则自动判定,完全不需要奖励模型)直接做大规模 RL,模型自发涌现出长链思考、自我反思、验证回溯等行为。这就是著名的"R1 时刻",它把"推理能力"从"蒸馏教师模型"的路线,扳到了"RL 自我进化"的路线上。

[6] Shao et al. (DeepSeek), "DeepSeekMath: Pushing the Limits of Mathematical Reasoning", arXiv:2402.03300, 2024-02。
要点概述(非原文直引):GRPO 舍弃 PPO 的价值模型,对同一问题的一组采样回答计算组内相对优势作为基线,大幅降低训练资源开销,并首次在 7B 模型上接近同级闭源模型数学能力。
[7] DeepSeek-AI, "DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning", arXiv:2501.12948, 2025-01。
要点概述(非原文直引):R1-Zero 仅用大规模 RL(无 SFT 冷启动)即涌现出反思、长链推理等能力;R1 在此基础上加入少量冷启动数据与多阶段训练,性能对齐 OpenAI o1。
Ai = (ri − mean(r1..G)) / std(r1..G) GRPO 的组相对优势:对同一问题的 G 条回答,奖励标准化后即为每条回答的优势——免价值模型的代价是"每个问题必须采样一组",这直接推高了 rollout 的算力需求(§3 伏笔)

此后算法侧的改进集中在"长序列 + 稀疏奖励"的稳定性上:DAPO[8](字节 Seed,2025-03)提出 clip-higher、动态采样、token 级损失等四项修补;GSPO[9](Qwen,2025-07)把序列级重要性比率引入目标函数,解决长序列训练不稳定。这些算法层面的演进与系统演进(§3–§4)互为因果:序列越长、组越大,rollout 越贵,越需要高效引擎与异步化。

[8] Yu et al. (ByteDance Seed & Tsinghua), "DAPO: An Open-Source LLM Reinforcement Learning System at Scale", arXiv:2503.14476, 2025-03。
[9] Agarwal et al. (Qwen), "GSPO: Group Sequence Policy Optimization", arXiv:2507.18071, 2025-07。
两条均为系统级开源报告:DAPO 在 Qwen2.5-32B 上把 AIME 2024 提到 50 分并公开完整 RL 配方;GSPO 是 Qwen3 使用的序列级策略优化目标,后被 verl 等框架实现。

第三幕 · Agent RL(2025 下半年至今):让模型学会"做事"

把 RLVR 从"解一道题"搬到"完成一个任务":给模型一个目标(修复这个 bug、调研这个课题),让它多轮地思考 → 调用工具(搜索、终端、浏览器)→ 观察结果 → 继续,直到交付。奖励通常是终局可验证的:测试通过了吗?答对了吗?页面状态对吗?这带来三个新麻烦:(1) 轨迹极长(数千至上万 token、几十轮交互);(2) 环境慢且不可控(一个网页请求几秒,一次 docker 构建几分钟);(3) 功劳分配更难(几十步里只有一两步是关键决策)。

C. Wolfe, "Agentic RL: Frameworks and Best Practices", cameronrwolfe.substack, 2025。
"A rollout can be represented as a flat sequence of tokens in single-turn RL, but agentic RL is more complex: the model undergoes multiple turns of observing context, taking an action, and receiving feedback."
译:"在单轮 RL 里,一条 rollout 就是一段扁平的 token 序列;而 Agent RL 更复杂:模型要经历多轮的'观察上下文 → 采取动作 → 接收反馈'。"
图 1-1 · Agent RL 的循环:与单轮 RL 唯一的本质区别是"环境反馈"作为观测被拼接回上下文,循环几十轮
为什么 Agent RL 在 2025 年才爆发,而不是更早?三个条件到 2024 年底才凑齐:① 强基座(K2/GLM-4.5 级别的模型才有足够的工具调用先验);② 可验证任务(SWE-bench、GAIA 等基准提供了自动判分环境);③ 系统(verl/slime 等框架让千卡级 Agent RL 成为工程上可复现的事)。缺一不可。

2Agent 数据飞轮任务合成 → 环境规模化 → 轨迹采集 → 筛选/课程 → 训练 → 弱点诊断回流

太长不看:"数据飞轮"指一个能自我强化的闭环:模型用得越多 → 产生越多交互轨迹与失败样本 → 从中自动合成更好的训练数据(任务、环境、课程)→ 模型变强 → 能合成更难的任务。2025 年开源侧最完整的飞轮样本是阿里通义 DeepResearch 与复旦 AgentGym-RL,商业侧是 Kimi K2 / GLM-4.5 的 agentic 后训练流水线。它本质上是把传统"人工标注数据集"换成了"可自动生成、自动验证、自动升级难度的数据工厂"。

2.1 什么是数据飞轮:从硅谷老概念到 Agent 新含义

"数据飞轮"(data flywheel)原本是产品圈的词:产品越好用 → 用户越多 → 产生越多数据 → 数据改进产品。它进入 LLM 训练话语体系是在 RLHF 时代(用户偏好数据回流),而在 Agent RL 时代获得了完全不同的形态:因为 Agent 的训练数据不是"人写的问答",而是"模型与环境交互产生的轨迹"。轨迹可以无限免费生成,瓶颈变成了"哪里来足够多、足够难、可自动判分的任务与环境"。于是飞轮的驱动力从"用户"换成了"合成管线 + 模型自身"。

图 2-1 · Agent 数据飞轮的六个环节(闭环):任务合成 → 环境规模化 → 轨迹采集 → 筛选/课程 → 训练 → (更强模型)→ 更难任务合成……

2.2 环节一:任务合成,让"出题"自动化、可验证、难度可控

Agent RL 的奖励要"可验证",所以任务必须自带标准答案或判分规则。手工出题无法规模化,主流做法有三类:

知识图谱随机游走(WebSailor 谱系)

从真实网站构建实体图谱,随机游走采样子图生成 QA,再故意模糊化信息制造难度:答案在图上可回溯,天然可验证。

形式化建模(WebShaper)

用集合论把信息检索问题形式化,难度被建模为对实体关系的"原子操作"(合并、模糊),每加一次操作难度升一级,难度可控、可机械升级。

自我挑战 / 自评(Kimi K2、造题 Agent)

给"造题 Agent"配搜索/执行工具,迭代生成并自检题目;Kimi K2 进一步用自评 rubric 奖励把对齐扩展到不可验证的主观任务。

通义 DeepResearch 技术报告对这条管线的描述是最直接的工业证据[10]:

[10] Tongyi DeepResearch Team (Alibaba), "Tongyi DeepResearch Technical Report", arXiv:2510.24701, 2025-10。
"We design a highly scalable data synthesis pipeline that is fully automatic… Moreover, this formal modeling also allows for efficient verification of QA correctness, effectively addressing the challenge of validating synthetic information-seeking data for post-training."
译:"我们设计了一条完全自动化、高度可扩展的数据合成管线……这种形式化建模还能高效验证问答的正确性,有效解决了后训练中信息检索类合成数据难以验证的难题。"

同团队官方博客(2025-10,中文原文):
"我们提供了一套支持大规模持续扩展的智能体预训练数据合成方案 AgentFounder,并与后训练过程中源源不断生产的数据形成数据飞轮。"

报告里还有一个值得注意的课程学习细节:训练数据的难度由一个能力更强的模型(64k 上下文)动态维护,再用它去训练上下文更短的模型:

[10] 同上,关于动态课程。
"RL training on a curriculum designed for a more capable model can force it to discover more efficient solutions… For the model with a 32k context, attempting these problems is likely to yield a zero-reward signal."
译:"在为更强模型设计的课程上做 RL,会迫使(较弱)模型去发现更高效的解法……但对 32k 上下文的模型来说,尝试这些问题很可能只得到零奖励。"

3Rollout 引擎:RL 的"油门与车轮"训推形态差异 → 推理引擎三件套 → 混合引擎(colocate)→ 服务化解耦(disaggregated)→ rollout 加速技巧

太长不看:rollout 就是"让当前模型去生成一批训练样本(回答或交互轨迹)"。它占 RL 训练 60–80% 的墙钟时间,却只能借用推理引擎(vLLM/SGLang)来跑,而推理引擎的权重组织方式与训练引擎完全不同。于是诞生了两派架构:混合引擎(训推同卡,权重就地切换,省卡但有"模式切换"开销)和解耦架构(rollout 独立成服务,权重广播同步,灵活但要跨机传参)。2025–2026 的趋势是后者与"rollout-as-a-service"。

3.1 rollout 到底是什么,为什么它最贵

一个 RL 训练步 = 采样(rollout)→ 打分(reward)→ 算优势(advantage)→ 更新权重(update)。rollout 之贵有三层原因:① GRPO 要求每个问题采一组(G 条)回答;② 推理模型兴起后单条回答很长(长思维链动辄上万 token);③ Agent 场景下还有环境交互(等待网页/沙箱的秒级甚至分钟级延迟)。实践中 rollout 常占一个训练步 80% 以上时间——所以"优化 RL 训练"基本等于"优化 rollout"。

3.2 地基:现代推理引擎的三件套(为什么训练框架自带的前向不能凑合)

PagedAttention vLLM, SOSP 2023

把 KV Cache 像操作系统页表一样分页管理,显存浪费从 60–80% 降到近乎为零,并发能力数量级提升。没有它,rollout 的 batch 起不来。[18]

Continuous Batching

不等一整个 batch 全部生成完,而是谁结束谁退出、随时插入新请求。RL 采样里序列长度方差极大,这个机制是吞吐的命根子。

RadixAttention SGLang, NeurIPS 2024

用基数树缓存共享前缀的 KV(同一 prompt 的 G 条回答共享前缀;多轮 Agent 的历史轮次共享前缀),让 GRPO 采样与多轮交互大幅省算。[19]

[18] Kwon et al., "Efficient Memory Management for LLM Serving with PagedAttention"(vLLM), SOSP 2023 / arXiv:2309.06180, 2023-09。
[19] Zheng et al., "SGLang: Efficient Controlled Generation"(RadixAttention), NeurIPS 2024 / arXiv:2312.07104, 2023-12。
两条均为推理引擎奠基工作:vLLM 解决"显存碎片与并发",SGLang 解决"共享前缀复用与结构化生成控制"。RL 训练框架(verl/slime/AReaL/OpenRLHF)全部以二者为 rollout 后端。

3.3 第一派:混合引擎 / 训推同卡(colocate)

verl 的 HybridFlow 论文[20]确立了"单控制器 + 混合引擎"范式:训练侧用 FSDP/Megatron 切分权重做更新,rollout 侧在同卡的 vLLM/SGLang 实例里生成;两套系统共享同一批 GPU,靠"参数重分片 + 显存 offload(训练时把推理引擎的 KV/权重卸载,推理时把训练优化器状态卸载)"来切换。好处是省卡、权重同步快(同机内存拷贝);代价是切换有开销、两类任务互相挤压显存。看本地 verl 源码里的主训练循环,可以清楚看到"生成 → 收卡(sleep)→ 更新"的同步节拍:

4异步 Rollout 与异步 RL木桶效应 → 三档异步谱系 → staleness 控制与回放 → 六大系统横评 → Agent 时代为何异步是刚需

太长不看:同步 RL 里,每一步训练都要等最慢的那条 rollout 结束(木桶效应),而且"生成 GPUs 忙、训练 GPUs 闲"与"训练忙、生成闲"交替出现,平均 GPU 利用率常常不到一半。异步 RL 把"生成"与"训练"解耦成两条永不停歇的流水线:代价是训练用的数据可能来自几步之前的旧权重(off-policy / 数据过期 staleness)。全部技术围绕一个问题:旧到什么程度还能用?怎么控制它别太旧?

4.1 同步的病:木桶效应与流水线气泡

GRPO 一个 batch 里,多数回答几百 token 就结束,少数思维链拖到上万 token,同步模式下所有 GPU 干等着最长的尾巴(skewness/长尾气泡);rollout 与训练两个阶段之间还有阶段依赖造成的流水线气泡(pipeline bubble)。AReaL 论文对同步范式的诊断很典型:

[25] Fu et al. (清华叉院 / 蚂蚁 / HKUST), "AReaL: A Large-Scale Asynchronous Reinforcement Learning System for Language Reasoning", arXiv:2505.24298, 2025-05(NeurIPS 2025)。
"Most existing large-scale RL systems for LLMs are synchronous… This stabilizes RL training but suffers from severe system-level inefficiency. Generation must wait until the longest output in the batch is completed before model update, resulting in GPU underutilization."
译:"现有大多数 LLM 大规模 RL 系统是同步的……这稳定了训练,却带来严重的系统级低效:必须等批内最长的输出全部生成完才能更新模型,导致 GPU 利用率不足。"

4.2 第一档:半异步(1-step off-policy),只用"上一秒"的数据

最温和的异步:训练第 t 步时,用第 t−1 步权重生成的数据(生成与训练重叠一步)。理论上一点 importance ratio 修正就能补偿,实测性能与同步几乎无差。代表是 Microsoft 的 Asynchronous RLHF[26] 与 OpenRLHF 的异步数据流[27]:

[26] Noukhovitch et al. (Microsoft Research), "Asynchronous RLHF: Faster and More Efficient Off-Policy RL for Language Models", arXiv:2410.18252, 2024-10。
"Asynchronous off-policy achieves the exact same win-rate as synchronous on-policy, 57.2%, up from 31.8% by the SFT model… we confirm that asynchronous RLHF is faster while being equally performant at large scale."
译:"异步 off-policy 取得了与同步 on-policy 完全一致的胜率 57.2%(SFT 模型为 31.8%)……我们确认:大规模下异步 RLHF 更快且性能相当。"

[27] OpenRLHF Team, "An Easy-to-use, Scalable and High-performance RLHF System"(EMNLP 2025 Demo)。
"…rollout engines, actor engines, and remote engines operate independently and communicate via message passing, enabling immediate processing as soon as data becomes available."

4.3 第二档:全异步,把"旧数据"变成可管理的资源

全异步系统中,rollout worker 流式地产出轨迹,训练器凑够一批就更新,两者完全不看对方脸色。此时数据的"年龄"(由第 v 版权重生成、被第 v+k 版权重消费,称 staleness = k)成为必须显式管理的资源。核心机制有四个,且都能在本地源码里看到对应实现:

(1) Staleness 容量控制:AReaL 的"限流阀门"

AReaL 的做法是给 rollout 派发加一个背压阀门:可派发余量 = max(0, min(并发上限−running, (最大容忍旧度+当前版本号+1)×训练批大小−accepted−running))；accepted 与版本采用源码累计计数口径，不能把累计上限叫作当前在途量。直观解释:如果 rollout 跑得比训练快,就少派点活,免得数据攒到"过期"。本地源码:

# 仓库:AReaL(inclusionAI / Ant,本地 clone)— areal/infra/staleness_manager.py(核心逻辑节选)
class StalenessManager:
    """Manages rollout capacity based on staleness and concurrency constraints…"""
    def get_capacity(self):                                   # 还能再派发多少条新 rollout
        current_version = self.version_provider.get_version()  # 当前训练到第几版权重
        concurrency_capacity = self.max_concurrent_rollouts - self.rollout_stat.running
        ofp = self.max_staleness                                # 最大容忍旧度 k
        sample_cnt = self.rollout_stat.accepted + self.rollout_stat.running
        staleness_capacity = (ofp + current_version + 1) * self.consumer_batch_size - sample_cnt
        return min(concurrency_capacity, staleness_capacity) # 两条约束取小:并发不超、旧度不超

完整文件见本地 AReaL/areal/infra/staleness_manager.py:79-113;训练器侧配套有版本化权重管理(AReaL/areal/trainer/rl_trainer.py:887-897,set_version)与多版本 LoRA 保留(lora_keep_versions = max_head_offpolicyness + 2)以便对旧数据做精确的重要性修正。

(2) Staleness 增强的策略梯度:算法侧的补偿

AReaL 区分三个策略：当前训练策略 πθ、近端参考策略 πprox、实际采样的行为策略 πbehav。裁剪比率 πθ/πprox 控制相对近端策略的更新，另用 πprox/πbehav 修正旧数据的分布偏移。两种比率分工不同，不是把一个分母简单替换成另一个。系统的旧度控制与算法的离策略修正仍须共同工作。AReaL 算法。论文报告在数学/代码实验中最高 2.77× 训练加速，不可直接外推全部 Agent 负载。

4.5 为什么 Agent 时代"异步"从优化项变成了必选项

数学/代码 RLVR 里,rollout 只是"模型自己写长答案",耗时可控;而 Agent rollout 的耗时由环境决定:一次 docker build 几分钟、一个网页加载几秒、不同任务间方差极大。同步模式下,最快的轨迹 2 分钟、最慢的 40 分钟,整个集群每步都要陪跑 40 分钟——异步化(以及与之配套的环境侧并发、部分轨迹回收、冗余 rollout)是唯一出路。AgentGym-RL 与 Agent Lightning 都为此设计了专门的异步 Agent 执行器(如 Agent Lightning 的两级并行 Agent runner、AReaL 的多轮异步工作流)。一句话:文本 RL 里异步是"省钱",Agent RL 里异步是"能不能训得动"。

5.2 生成侧:扩散模型的 RL,从 DDPO 到视频 RL 爆发

理论奠基:把去噪过程变成 MDP(2023)

扩散模型生成图像 = 从纯噪声开始迭代去噪 T 步。DDPO 的洞察是:把每一步去噪看作一个动作,去噪链就是一条轨迹,终态图像的奖励就是轨迹奖励,于是 PPO 式策略梯度可以直接用。DDPO 与 DPOK 在 2023 年 5 月几乎同时独立完成这一形式化,自此扩散模型的 RL 微调有了理论通行证[42][43]:

[42] Black et al. (UC Berkeley / MIT), "Training Diffusion Models with Reinforcement Learning"(DDPO), arXiv:2305.13301, 2023-05(NeurIPS 2023)。
"We describe how posing denoising as a multi-step decision-making problem enables a class of policy gradient algorithms, which we refer to as denoising diffusion policy optimization (DDPO)."
译:"我们说明了把去噪表述为多步决策问题,如何催生一类策略梯度算法——我们称之为去噪扩散策略优化(DDPO)。"
其 MDP 形式化(原文 Sec. 4.3):"s_t ≜ (c, t, x_t), π(a_t|s_t) ≜ p_θ(x_{t−1}|x_t, c)… R(s_t,a_t) ≜ r(x_0,c) if t=0, 0 otherwise."
译:"状态 = (提示 c, 步数 t, 含噪图像 x_t);策略(动作分布) = 去噪网络预测的下一状态分布;奖励仅在最后一步按终态图像与提示的匹配度发放,其余步为 0。"

[43] Fan et al. (Google et al.), "DPPOK"(Denoising Policy Optimization with KL), arXiv:2305.16381, 2023-05(NeurIPS 2023)。
"We show that optimizing the expected reward of a diffusion model's image output is equivalent to performing policy gradient on a multi-step diffusion model."
译:"我们证明:优化扩散模型图像输出的期望奖励,等价于在多步扩散模型上做策略梯度。"(DPOK 额外引入对预训练模型的逐去噪步 KL 正则,防止奖励作弊与画质崩坏。)"

6.2 未来发展方向研判(附依据)

  1. 异步/解耦将成为 RL 系统的默认形态,同步模式退居小规模调试用途。依据:AReaL 2.77×、StreamRL 2.66×、Agent Lightning v1.0 2× 的加速证据链,以及 vLLM 把异步支持内置于引擎本身(2026-05)。当推理引擎原生支持 pause/resume,同步模式的"省事"优势不复存在。
  2. Rollout 引擎与 RL 框架的边界重组:推理引擎吃掉框架的 infra 层。依据:vLLM 原生 RL API、SGLang 深度绑定 slime、vime 的出现。未来框架的核心价值将只剩"算法与数据流编排",权重同步/调度等沉入引擎层。
  3. staleness/off-policyness 将被形式化为可优化的资源分配问题。依据:AReaL 的容量公式、ROLL Flash 的"异步比例"超参、经验回放研究(2026-04)的"stale 方差-样本效率"权衡理论化,从工程 trick 走向有理论的自动调参。
  4. Agent RL 的瓶颈继续从模型转向环境:环境合成、环境并行、环境课程成为独立研究方向。依据:EnvScaling 定律、Agent-World 自进化闭环、ProRL Agent 的 rootless sandbox、AgentGym-RL 的 27 环境统一框架,以及 2025-11 起的环境规模化系列综述。
  5. "数据飞轮"从营销词变为可审计的工程系统。依据:Tongyi DeepResearch 公开全配方(CPT↔后训练数据互通)、K2 的自评 rubric、Agent-World 的弱点诊断闭环,飞轮的每个环节(出题、判分、课程、回流)都有了开源参照实现。
  6. 可验证奖励从"数学/代码"扩展到"物理/几何/一致性/体验"。依据:World-R1 的 3D 约束、4D Latent Reward(2026-03)、多模态 rubric 奖励(RubricRL, 2025-11)、零样本 MLLM 打分器(SpectraReward, 2026-07),"什么都能自动判分"的边界在快速外扩。
  7. RL 与蒸馏/量化的融合训练("一次训练,既对齐又加速")。依据:RL-Native Distillation(2026-08)、Flow-Map GRPO 少步一致性模型 RL(2026-07)、Qwen-Image-2.0-RL 的在策略蒸馏。在线 rollout 昂贵,能省一步蒸馏就省一步。
  8. 去中心化与异构化 RL:训练不再囿于单一集群。依据:INTELLECT-2/PRIME-RL 的全球分布式 rollout + TOPLOC 验证、AReaL-Hex 异构调度、StreamRL 跨机房异构、BiDiRL 时空复用(2026)。算力来源多元化倒逼架构解耦,解耦架构反过来使能多元化。
  9. 理解与生成的统一 RL 仍是待填补的空白。依据:Janus-Pro/BAGEL 靠预训练,RL 主要各自为战(理解侧 GLM-4.1V-Thinking,生成侧 DanceGRPO);跨双通路的联合奖励设计尚无成熟工作,这是今天入场仍能做出原创贡献的方向。
  10. 对 RLVR 本身的反思将持续:增益的鲁棒性、可迁移性与持续学习。依据:多模态 RLVR 换模板即失效(2608.08802)、correct-set 周转(2606.03087)、以及 Magistral/AReaL 系列对 off-policy 负奖励塌缩的观察:"RL 学到的是能力还是过拟合验证器"将是 2026–2027 的核心议题。

  • DSec:DeepSeek 弹性算力环境(2026-09-19,arXiv:2609.22978):Agent RL 的沙箱环境(仓库、工具、任务服务)以突发方式大规模创建、需长期保持状态,环境基础设施本身成了与训练框架同等级的系统问题。DSec 把沙箱生命周期做成独立基础设施层(agent sandbox + worker container),GPU 作业被抢占后可重连续跑;DeepSeek-V4.1 起生产 rollout 全部跑在其上:日服务约 300 万个沙箱、峰值 38 万+ 并发——"环境即数据、环境规模化"论断的最强工业证据。
  • FlashREINFORCE:单 Rollout 免 Critic 异步 RL(NVIDIA,2026-09):GRPO 的"组采样"要求同一 prompt 反复 rollout 并等齐,与异步长程 Agent 天性冲突。改成每 prompt 只采 1 条 rollout:批内新鲜奖励中心化 + 序列级信任域 + token 重要性采样加权。数学任务五基准均分 38.0(GRPO 36.3,且只用一半 rollout);同预算超 GRPO +6.8 分(Qwen3-30B-A3B,lag≈8 下稳定)。
  • NeMo-DCR:万亿参数的位精确增量权重同步(NVIDIA+Aalto,2026-10-06,arXiv:2610.08430):解耦 RL 每步都要把新权重送到 rollout 集群,1T checkpoint 跨两个 AWS 区域要 87.5 分钟。利用"每步仅约 1% BF16 权重改变存储值"做位精确增量压缩 + 中继树分发:1T 模型 @3% 变更率从 87.5 分钟降到 150 秒(12–40×)。
