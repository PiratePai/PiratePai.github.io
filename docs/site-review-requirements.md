# 网站校验与审查要求

适用于本站的文章、首页、搜索、阅读器、图解和发布维护。维护日期：2026-11-18。本文是后续工作的执行要求；历史修订报告提供经验和证据，不代表当前候选已经通过检查。

## 1. 开始前确定范围

1. 记录基线提交、工作分支、变更文件和变更目的，从最新 `main` 建分支。
2. 说明是否涉及事实、正文结构、导航、共享资源、图解、索引或发布，按第 5 节选择检查。
3. 从 `data/articles.json` 与 `posts/*.html` 确认实际文章集合，不沿用历史报告的篇数。声称“全站检查”时，列出全部文章及处理状态，不能只检查用户截图或代表页。
4. 复用已核对的研究与检查记录；需要新方案时先读官方文档、维护中的参考实现和相关测试。记录来源、版本/提交、采用机制与不适用部分，不能把读源码写成运行验证。

历史记录与本文冲突时，按当前用户要求、`AGENTS.md` 中明确的后续修订及本文执行。尚未执行的要求须标为待验证，不得因文档已建立而标为“自动保障”。

## 2. 必须审查的内容

### 2.1 事实、机制与证据

- 每个影响结论的数字，须能定位到来源及原文位置，并保留模型、硬件、精度、负载、基线、质量门、指标和日期；不适用的字段明确说明。区分绝对值、相对变化、平均值与尾延迟。
- 区分论文自报、官方自测、第三方转述、源码核对、教学推算与独立复现。核对论文题名/作者不等于验证其机制与所有性能数字。
- 只比较口径相容的结果。不能把整模型代际收益归因于单个开关，也不能将吞吐、goodput、容量、单步时延、FPS 和动作到画面延迟混为一谈。
- 公式、代码、图、滑块读数、判定文案、比较表和小结表达同一机制；复算单位、维度、分母、边界及反例。动画能动不代表机制正确。
- 事实更新覆盖被改动及直接依赖的结论，并复查其摘要、图注、小结和跨文引用；保留历史快照与限制。纯排版维护不扩大事实核验范围，不刷新 `reviewed`。
- 所有来源键有可定位出处；摘录与译文对应。无法核实的内容标清局限、撤回数字或保留为检索线索，不能补造日期、commit 或实验。

### 2.2 逻辑排版与可扫读性

- 一个段落承载一个主要信息点。按问题、机制、证据、限制和结论组织；字数只是找候选的线索，不按每个句号或固定字数切段。
- 有先后依赖的步骤用 `ol`；无先后关系的并列项用 `ul`；术语解释可用 `dl`；多对象按相同属性比较时用表格。不要用手写 `①②③`、`（1）（2）（3）` 或 `<br>` 模拟列表。
- 列表项保持相同层级和句式。单项不要硬套列表；两项是否拆分取决于语义与密度；完整引文、代码注释编号、公式链与图内编号不机械列表化。
- 提示框、摘要、源码解读、学习路径、表后说明与更新附录同样需要段落层级。单个 `li` 包含多个独立工作时，拆条目或分组子列表，不能把长段从 `p` 搬到 `li` 就算完成。
- 图注交代图表内容、编号、来源和口径，延伸分析放正文。时间线保留事件与意义，完整代码、长引文可移至邻近正文或有明确标题的详情；不能把论文配图连带藏在默认关闭的附录中。
- 调整后检查引导句、主语、引用归属与边界标点；避免孤立数字、失去对象的“它/该”、残留分号或无上下文短页。强调不应覆盖整段。

### 2.3 HTML、内容与链接保真

- `p` 在 `div/table/ul/ol/h2/h3` 等块元素前闭合；列表直接子元素使用 `li`，相关图片归入对应项或移出列表。属性引号正确转义，`alt` 完整，链接正确闭合。不能依赖浏览器静默修复源码。
- 排版和样式改动前后，对照正文顺序、代码、引用、图片路径及原有 ID。生成元数据单独比较，避免新增变更记录干扰正文保真检查；替代文本、衔接句等有意修改须说明。
- 锚点“存在”且仍指向原主题。展示编号变化不应改掉历史 ID；同步目录、文内章节号、图表号与跨文章引用。自动页号可变，长期链接优先用语义锚点。
- 正文在静态 HTML 中完整保留。分别验证源文件、增强后的 DOM、分页模式、全文模式及无 JavaScript 阅读；文本相同也不能证明图片默认可见或交互监听器仍有效。
- 图片路径存在、SVG XML/命名空间正确、浏览器成功解码、所在章节可达及默认可见是不同检查，不能互相替代。

### 2.4 页面、图解与交互

- 首页与文章复用共享主题、字体和导航语言；正文、提示框、代码、表格、引用均检查计算样式。声明了字号或字体不等于实际生效，新增 `p` 也可能继承旧容器的小字号。
- 常规浏览器检查覆盖桌面 1440px、手机 375px、浅色与深色；工具栏、长标签和图解另查 320px。必要时补 768px 等中间宽度、文本放大与字体回退。这些项目不等于完整无障碍认证。
- 正文无页面级横向溢出；确需二维阅读的表格、代码、复杂图可在自己的容器内滚动，不能靠缩小全部文字、隐藏信息或禁止缩放解决。
- 文字对比度按现有检查中的普通文字 4.5:1、大字 3:1 复核；传达意义的图形前景与相邻背景至少 3:1。不得只靠颜色区分语义，论文原图不套用手绘图改色规则。
- 图解检查真实渲染后的边界、遮挡、标签相交、同一标尺、图例和读数；不是只看 `viewBox` 内的源码坐标。滑块最小/默认/最大值、所有阶段、重置、暂停和结束状态均有正确解释。
- 鼠标、键盘、焦点、Escape、抽屉关闭、浏览器前进后退、主题持久化、深链接冷启动及折叠自动展开可用。分页不拆散图与图注、公式、完整列表项或演示，不生成只有几十字的碎页。
- 动画默认静止或按既定策略播放，离屏、后台与减少动态效果偏好下停止持续调度；不以动画时长或调度频率推导整站 CPU 改善。

### 2.5 搜索、元数据与性能

- `data/articles.json` 是日期与变更范围的唯一维护入口。首页、页头、变更记录、JSON-LD 和 sitemap 一致；篇数按文章去重，同日多条变更不能重复堆叠完整标题。
- 文章、共享资源或生成逻辑改动后运行统一构建，不手改生成区。资源版本按内容摘要更新，跨平台文本摘要按 LF 规范化；重新构建必须稳定。
- 搜索检查中文、英文规范化、多词同章节命中、章节直达、查询分享与前进后退、快速输入后导航、空结果、失败降级和重试。
- gzip 不可用、损坏、JSON 合法但结构无效时回退普通索引；处理服务器透明解压与取消请求。两个索引都失败时仍有标题摘要搜索及恢复入口，用户输入不能拼成可执行 HTML。
- 体积、请求数、首次/重复访问、缓存、CPU 调度和真实耗时分开记录。比较须固定内容、环境与指标；静态 HTML 缩小不等于加载加速，客户端分页不等于初次下载变小。
- 性能优化保留内容、语义锚点、交互、降级路径及资料范围；不能以删内容、隐藏配图或移除失败处理换取漂亮指标。记录收益、代价和回退方式。

## 3. 自动检查能证明什么

下表按基线 `3490057` 的实际脚本与断言核对。CI 配置与脚本变更时同步维护此表，不将未来目标写成已覆盖。

| 入口 | 实际覆盖 | 不能据此宣称 |
|---|---|---|
| `build-site.py --check` | 动画、核心图、阅读器、元数据与索引的生成一致性 | 页面好读、外部事实正确 |
| `check-site.py` | 首页/文章本地目标、唯一 ID、站内锚点、所引用 SVG 的 XML/命名空间、JS 语法 | 所有外链可达、完整 HTML 合法性、运行行为正确 |
| `unittest` 中 `test_reader_content.py` | 关键 `p`/列表/图片属性边界；指定文章编号与历史锚点主题；图形语义色转换 | 全站 HTML 验证、所有跨文编号与逻辑排版自动审查 |
| `unittest` 中 `test_site_build.py` | 编辑日期、元数据、资源版本、更新分组、sitemap 等构建约定 | 文献已经重查、搜索引擎已收录 |
| `verify-mechanisms.py` 与 Node 核心图测试 | 明确实现的标准库账本、概率/数值机制与边界 | GPU/NPU 跑分、论文训练复现、未覆盖公式的正确性 |
| Node 搜索测试 | 静态索引、命中/排序、锚点及 gzip 的多种回退 | 全部浏览器输入、历史记录与视觉状态 |
| `check-reader.cjs URL` | 枚举全部文章的双宽度分页、正文顺序、ID、锚点、图片解码、部分代表性交互；另检查无 JS 的阅读路径及配图不被折叠 | 全文可读性、每个控件/无 JS 正文的完整人工验收 |
| `check-reading-comfort.cjs URL` | 全部文章双宽度双主题的字号、对比度、宽度、工具栏及指定图形点；另有 320px 工具栏检查 | 所有绘图/装饰色均已检查、字体全部实际加载、完整无障碍符合性 |
| `check-home.cjs URL` | 首页变更分组、搜索、历史/目录同步、失败恢复、无 JS 与部分窄屏行为 | 所有文章交互与引用语义 |
| `check-content-guides.cjs URL` | 脚本中列出的四篇内容指南及相关交互 | 自动覆盖将来新增的所有专题 |
| `check-core-visuals.cjs URL` | 全站手绘 SVG 几何及指定核心演示、多个宽度/主题/状态 | 所有论文原图细节、未列演示的每个状态 |
| `check-animations.cjs URL` | 脚本中列出的演示、后台/减少动态效果等行为及按元数据选择的研究锚点 | 整站 CPU 百分比或全部文章同有某次研究记录 |

当前 CI [`check-site.yml`](../.github/workflows/check-site.yml) 执行生成一致性、站点、机制、Python 和 Node 测试，**不运行上述浏览器脚本，不自动完成语义审查**。浏览器运行失败、未配置 Playwright 或没有 Edge 时须如实报告，不能把 CI 绿灯当作视觉通过。

## 4. 人工审查与问题关闭

1. 固定审查候选的 SHA 或明确的未提交差异与文件集合。语义审查先判断事实、逻辑和缺失，再看排版、交互和细节；不要用主观总分代替具体问题。
2. 每项记录：`编号｜文件/语义锚点｜复现或原文｜影响｜修订要求｜优先级｜验证方式｜状态`。截图附视口、主题与步骤；源码问题不能冒充浏览器观察。
3. 状态使用“待处理、已修待验、已验证、非问题、暂缓”。非问题需证据；暂缓需原因、影响和跟踪位置。没有依据的猜测先核查，不直接改事实。
4. P0：事实/公式明显错误、正文或引用丢失、核心阅读不可用；P1：严重错配、遮挡、导航或排版问题影响理解/操作；P2：局部措辞、对齐与非阻断细节。交付前关闭 P0/P1，P2 修复或明确记录，不隐瞒已知缺陷。
5. 修复用户示例后，检索相同结构与共享来源，检查其他文章和容器。只有完成实际清单覆盖，才能声称“通篇/全站处理”。
6. 同一候选与风险范围由一份语义审查清单负责；实现者逐项处理，最终验收核对证据和未覆盖风险。修后默认复核差异和失败项；候选、环境与相关输入未变时复用已通过证据，不为更新摘要反复全量审查。
7. 审查可由当前执行者完成；用户另行指定 DSH 等审查者时，其发现仍须回到源码核对。自动/人工审查职责与调用某个模型是两件事，本文不构成新增模型调用、委派、改凭据或发布的授权。

## 5. 按变更选检查

“基础检查”指第 6 节的现有 CI 命令。多个类型同时发生时取并集，不重复执行同一检查。修复导致新风险或输入变化时补相关检查。

| 变更 | 最低验证范围 |
|---|---|
| 仅维护规范、审查报告或模板 | 差异、相对链接、命令/参数与实际源码一致性；不因文档改动重跑浏览器、不刷新文章日期。仓库现有 CI 仍会按 PR 触发。 |
| 单篇勘字/引用文字 | 核对差异、事实与引用；基础检查。没有影响布局的纯勘字可免重跑浏览器，说明理由。 |
| 文章分段、列表、折叠、配图或章节结构 | 基础检查 + 阅读器 + 舒适度；人工看受影响段及前后文、主题、无 JS；对照图片、代码、引用和 ID。全站排版须有逐篇覆盖。 |
| 技术结论、公式、代码、比较图 | 基础检查 + 对应来源/机制核查与有意义的反例；涉及图解再加核心图/阅读器相关检查。若未做真实模型实验，明确写出边界。 |
| 首页、搜索、日期、索引、资源加载 | 基础检查 + 首页浏览器检查；涉及新专题补内容指南或定向用例；验证压缩、失败、历史、无 JS 与缓存更新。 |
| 共享主题、字体、阅读器或分页 | 基础检查 + 阅读器 + 舒适度 + 首页受影响入口；枚举全部文章与相关图表/代码，必要时加核心图检查。 |
| 图解、动画或共享演示逻辑 | 基础检查 + 核心图/动画对应脚本；人工看默认及边界状态、所有主题/宽度、键盘、减少动态效果与无 JS。影响阅读器时追加其检查。 |
| 已获授权的合并/发布 | 核对 PR 最新 SHA 与成功检查；跟踪同一 merge SHA 的 Pages 部署；按第 7 节核验线上。 |

现有浏览器脚本大多枚举全站或固定专题，只接收预览 URL；不要虚构文件过滤参数。需缩小本地反馈范围时可做定向浏览器检查，记录它与完整回归的区别。

## 6. 可复制的检查入口

从仓库根运行。基础检查使用 Python 标准库和 Node.js；当前 CI 使用 Python 3.12、Node.js 22。浏览器检查额外需要可被 `require('playwright')` 解析的 Playwright 与已安装的 Microsoft Edge；依赖缺失时记录缺口，不宣称运行成功。

内容或资源有变化时先构建：

```text
python scripts/build-site.py
```

基础检查（与当前 CI 保持一致）：

```text
python scripts/build-site.py --check
python scripts/check-site.py
python scripts/verify-mechanisms.py
python -m unittest discover -s scripts -p 'test_*.py'
node --test scripts/test-site-search.cjs scripts/test-core-visuals.cjs
```

独立终端启动静态预览，其他终端按第 5 节选择浏览器命令：

```text
python -m http.server 8958 --bind 127.0.0.1
```

```text
node scripts/check-home.cjs http://127.0.0.1:8958
node scripts/check-reader.cjs http://127.0.0.1:8958
node scripts/check-reading-comfort.cjs http://127.0.0.1:8958
node scripts/check-content-guides.cjs http://127.0.0.1:8958
node scripts/check-core-visuals.cjs http://127.0.0.1:8958
node scripts/check-animations.cjs http://127.0.0.1:8958
```

运行前设置 `READER_QA_DIR` 可保存阅读器/舒适度结果，`HOME_QA_DIR` 保存首页截图，`SITE_QA_OUTPUT` 指定内容指南产物目录。普通浏览器脚本的外部请求屏蔽只用于排除计数器等噪声，不能作为全文外部来源链接可用的证据。

每次记录命令、候选、环境、覆盖集合、退出码、日志/截图位置与未验证项。重试保留首次失败；先分清测试环境问题与真实产品缺陷，修复后执行受影响检查。不要改弱断言、跳过文章或反复重跑直到碰巧成功。

## 7. 合并与上线验收

1. 核对提交范围与工作树，确认未混入 `gate.js`、密文试点、临时脚本、凭据和他人未提交改动。通过工作分支与 PR 交付，不用旧 API 脚本无差别推送。
2. 核验最新 PR head 对应的检查与审查记录。旧提交的绿灯不证明新提交通过；审阅通过也不等于合并/发布授权。遵循当前会话已有授权，已授权的步骤不重复确认。
3. 合并后记录 merge SHA，检查该 SHA 的主分支检查与 `pages-build-deployment` 成功；`main` 已有提交不等于网站已更新。
4. 验证首页、修改文章、共享资源、元数据、索引和 sitemap 可达且包含本次预期改动。全站发布枚举全部文章；下载内容与合并产物比较时说明换行/构建转换。HTTP 200 不等于新版本，部署成功也不替代线上内容核对。
5. 定向检查关键线上入口与交互；发布失败或内容不符时记录原因，按已授权范围修复或用可审阅的回退提交/PR 恢复。不把本地通过写成已经上线。

最终交付至少说明：改了什么、为何调整、影响范围、实际验证、未验证/遗留项、PR/commit 与是否上线。验收证据使用本次实际文章/状态数量，不抄历史的 16/19/21 篇或 42/84 组统计。

## 9. 参考与采用边界

- [Google 技术文档列表规范](https://developers.google.com/style/lists)：采用按顺序/集合/术语选列表、项目保持平行结构的做法；不将英语标点规则机械套给中文。
- [W3C Reflow 说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：补充 320 CSS px 与放大重排检查；二维表格/图形可有局部滚动，但正文仍须可读。
- [W3C Text Spacing 说明](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)：检查用户覆盖行距 1.5 倍、段后距 2 倍、字距 0.12em、词距 0.16em 时是否丢内容；按语言/文字实际适用性处理。这些是抗覆盖测试值，不是本站强制默认排版值。该手工检查尚未接入当前 CI。
- 已安装的 `tech-doc-style-chinese` 与 Typography 用于事实保真、中文结构和分层排版；核对版本及运行边界见 [2026-11-17 记录](logical-layout-20261117.md)。官方网页于 2026-11-18 阅读；规范来源与本站当前自动覆盖是两回事。
